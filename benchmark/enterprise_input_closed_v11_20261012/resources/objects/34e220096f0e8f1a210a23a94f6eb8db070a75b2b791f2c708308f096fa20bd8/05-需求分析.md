# A-13 百雀羚工厂 AI 知识库 — 需求分析

> 课题：将分散于各部门的管理经验、设备手册、质检标准等整合为可检索、可对话的 AI 知识库。  
> 下表从**一线与管理人员**视角归纳问题与应对思路，采用 Kano 思路分为基本型与期望型/兴奋型。

---

| 需求层次 | 用户问题 | 解决点子 |
|----------|----------|----------|
| 基本型需求 | 规程、手册分散在文件柜、网盘、群里，**不知道以哪份为准、也搜不到** | 把公司制度与各岗位文档统一入库，用对话方式提问，按语义检索相关内容 |
| 基本型需求 | 不同岗位只能看本部门资料，**怕看到别部门不该看的内容** | 登录后绑定工作部门，问答范围限定为「公司通用制度 + 本部门知识」 |
| 基本型需求 | 班长、质检会问「**这话有依据吗**」，口头回答难以服众 | 正式问答附带引用来源（文档名称与相关片段），便于现场核对 |
| 基本型需求 | 担心系统**凭空编造**操作步骤或检验限值 | 规程类回答必须基于内部已入库文档；无依据时明确说明，不代替正式文件 |
| 基本型需求 | 多人使用需要**分清是谁在问**，不能人人共用匿名入口 | 提供账号登录，个人会话与记录相互隔离 |
| 期望型需求 | 生产、质检、设备、工艺**视角不同**，同一句话关心的文件不一样 | 可随时切换当前工作部门，问答与检索范围随部门变化 |
| 期望型需求 | 操作工要「先做什么后做什么」，质检要**限值和条款** | 回答按场景组织为分步说明或要点列表，贴近岗位习惯 |
| 期望型需求 | 班组长、专员手里有新版的 PDF、Word，**希望纳入统一问答** | 支持按「公司总体 / 各部门」上传文档，解析入库后可被检索 |
| 兴奋型需求 | 培训后想**自测**是否记住安全与岗位规程 | **知识问答**：按部门随机抽题测验，选题即反馈解析，并保留个人成绩 |
| 兴奋型需求 | 问食堂、寒暄也被当成查制度，**答非所问、体验生硬** | 区分生活类与规程类；示例问题一键提问；引用区可收起，小屏也好用 |

---

## 说明

- **基本型**：缺了就不算可用的「工厂知识问答」，用户会直接否定系统价值。  
- **期望型**：访谈与画像里常提到的「希望有」的能力，做得越好满意度越高。  
- **兴奋型**：用户未必逐条提出，但能明显提升「好用、像真系统」的感受；**不能替代**基本型中的范围管控、溯源与不编造规程。
