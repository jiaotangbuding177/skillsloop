# 一、课程升级定位

## 1.1 从工作坊到企业创新任务

本课程不是一场“先听设计思维、再做课堂练习、最后做汇报”的普通工作坊，而是一次有明确委托方、真实问题、现场证据和成果责任的企业创新任务。

百雀羚提出真实业务挑战，学生与EvoMind组成14支创新团队。团队进入企业现场观察流程、访谈关键角色、收集证据，再将证据转化为洞察、创意和可测试原型。课程结束时，学生交付的不是一组未经验证的想法，而是一套能够被企业继续讨论和验证的早期创新资产。

课程围绕一句话展开：

> 每一次创新，都始于一个真实的人。

因此，学生在每个阶段都必须回答“我们为什么做这一步”：

| 阶段 | 必须回答的问题 |
|---|---|
| 真实的人 | 我们究竟在帮助谁？ |
| 真正的问题 | 他在什么具体情境中遇到了什么困难？ |
| 真实证据 | 我们凭什么相信这个问题存在？ |
| 洞察 | 这些行为和矛盾背后真正说明了什么？ |
| 创意 | 哪种改变最可能创造价值？ |
| 原型 | 怎样用最低成本让别人体验这个改变？ |
| 验证 | 用户的真实反应支持还是推翻了我们的判断？ |
| 价值 | 企业为什么值得继续投入？下一步该验证什么？ |

## 1.2 课程名称与传播口径

**课程名称：** AI × Design Thinking 企业创新 Bootcamp

**副标题：** 用设计思维发现问题，用AI放大创新能力，用真实企业场景创造价值。

**核心命题：** Innovation is not about having ideas. It is about solving the right problem for the right people.

**中文解释：** 创新不是拥有更多想法，而是为真正的人解决真正的问题。

## 1.3 课程目标

课程结束后，学生应能够：

1. 将企业给出的课题或技术方向重新表述为以人为中心、可被研究的问题；
2. 使用观察、访谈和证据记录方法理解真实业务情境；
3. 区分事实、解释、假设和AI生成内容，形成可追溯的证据链；
4. 从用户行为、情绪、目标和约束中提炼洞察；
5. 使用POV与HMW定义正确的问题边界；
6. 在AI辅助下完成创意发散，同时由团队承担筛选和决策责任；
7. 制作能够回答关键问题的低保真原型；
8. 通过测试反馈修正方案并说明迭代依据；
9. 说明创新方案的用户价值、企业价值、风险和下一步验证计划；
10. 建立面向AI时代的人机协同创新意识。

## 2.3 三条不可妥协的原则

### 原则一：先证据，后结论

学生不得把课题卡、企业导师观点、互联网材料或AI输出直接当作事实。所有关键判断必须注明证据来源；没有证据的内容统一标记为“待验证假设”。

### 原则二：先原型，后包装

Day 3先完成能够被体验和测试的低保真原型，再进入海报和路演制作。不得用精美PPT替代原型，不以视觉包装掩盖未经验证的方案。

### 原则三：AI提供候选，人承担责任

AI可以整理、归纳、发散和挑战，但不能代替现场观察、建立信任、价值判断、伦理判断和最终决策。学生必须能指出每一项关键结论由谁决定、依据是什么。

# 三、EvoMind：贯穿课程的 Innovation Partner

## 3.1 四阶段角色

| 阶段 | EvoMind角色 | 主要任务 | 不得替代的人类任务 |
|---|---|---|---|
| Day 1 | Research Partner | 整理背景、生成Persona初稿、显化假设、优化访谈提纲 | 确认目标用户、判断关键假设、设计真实追问 |
| Day 2 | Evidence Analyst | 转录摘要、标签化、痛点聚类、生成旅程和洞察候选 | 建立访谈信任、观察情绪、核对事实、解释矛盾 |
| Day 3 | Creative Partner | 生成创意、挑战假设、比较方案、辅助原型文案和路演结构 | 价值取舍、方案选择、体验设计、测试和迭代 |
| Day 4 | Knowledge Curator | 总结亮点、证据链、风险与建议，形成项目索引 | 承担判断责任、回应评委、决定下一步 |

## 3.2 AI输出使用规则

每组使用EvoMind时必须遵守以下规则：

1. **先有人类输入，再有AI分析。** 不允许在没有现场材料时让AI虚构用户洞察。
2. **AI输出统一标记。** AI生成的Persona、聚类、洞察和创意均标注“AI候选”。
3. **关键结论必须回到证据。** 每条核心洞察至少关联一条观察或访谈证据。
4. **保留不同意见。** AI无法解释的矛盾、少数意见和反例不能被自动删除。
5. **保护企业和个人信息。** 未经授权的配方、工艺参数、个人身份信息、未公开经营数据不得上传。
6. **记录人类修改。** 每组保留至少三处“AI建议—团队修正—修正理由”记录。
7. **最终决策由人署名。** 每个方案方向必须写明团队决策人与决策依据。

## 3.3 AI能做什么，人必须做什么

| 环节 | AI擅长 | 人必须负责 |
|---|---|---|
| 信息收集 | 整理资料、总结文档、生成信息清单 | 判断信息是否重要、可靠和可公开 |
| 用户研究 | 转录、摘要、聚类、发现重复词语 | 建立信任、观察情绪、提出追问、获得许可 |
| 洞察提炼 | 发现模式、比较差异、生成洞察候选 | 解释意义、处理矛盾、确认问题边界 |
| 创意发散 | 快速产生大量方向、寻找跨领域类比 | 判断用户价值、企业价值、伦理与可行性 |
| 原型制作 | 生成草图、文案、界面和故事板素材 | 设计体验、选择保真度、组织真实测试 |
| 最终决策 | 提供风险分析、建议和表达结构 | 承担责任、做出选择、回应利益相关者 |

## 4.3 课题卡的使用方式

现有16张课题卡中包含若干技术方向和“学生可做方向”。这些内容在课程中只作为企业的初始想法，不作为既定答案。

抽取课题后，每组必须完成一次“解决方案退回问题”的转换：

| 卡片上写的内容 | 团队必须继续追问 |
|---|---|
| AI消费洞察、新品研发 | 谁在做消费洞察？当前哪个判断最困难？ |
| AI质检 | 哪类缺陷、在哪个环节、给谁造成什么后果？ |
| 智能排产 | 谁在何种突发情况下需要调整？目前如何做决定？ |
| AI知识库 | 谁找不到什么信息？找不到会造成什么损失？ |
| 美妆管家 | 哪类用户在什么时刻中断护肤？原因是什么？ |
| 盲盒式包装 | 用户真的需要惊喜感，还是需要其他使用价值？ |

团队不得因课题名称中含“AI”就默认AI是最佳解。若证据表明流程优化、信息设计、服务机制或非数字化方案更有效，允许提出非AI或弱AI方案。

# 六、Day 1——Discover：找到真正的问题

## 6.1 本日故事

很多创新失败，不是因为团队不努力，也不是因为技术不先进，而是因为团队解决了一个不存在、不重要或不属于目标用户的问题。

Day 1不急着产生方案。学生首先要弄清楚：课题背后真正需要帮助的人是谁；他在什么情境下遇到了什么困难；哪些判断只是团队猜测；明天进入企业现场需要寻找什么证据。

## 6.2 本日目标

1. 理解设计思维解决的是“不确定问题”，不是背诵五阶段；
2. 将企业课题从“预设AI方案”还原为“待研究挑战”；
3. 明确一个主要目标用户和一个关键使用情境；
4. 使用JTBD、Pain、Gain和同理心地图形成临时Persona；
5. 提出一个可被支持或推翻的核心假设；
6. 完成现场观察重点、访谈提纲和证据清单；
7. 通过导师审核，形成可执行的调研包。

- 不从五阶段定义开始，而从企业为什么会做错创新开始；

- 百雀羚分享聚焦“真实挑战、困难与边界”，避免变成品牌宣传；
- 强调课题卡上的技术路径只是企业当前假设，学生有责任验证它。

### Day 1绿灯审核标准

- [ ] 目标用户是具体角色，不是“所有消费者”或“企业员工”；
- [ ] 描述了一个可观察的具体情境；
- [ ] 核心假设可以被现场证据支持或推翻；
- [ ] 访谈提纲不暗示受访者接受预设AI方案；
- [ ] 观察重点与课题相关且在开放区域内可执行；
- [ ] 写明证据类型、授权要求和五人分工；
- [ ] 所有AI生成内容均已人工核验。

### Day 1最终提交：一页调研任务书

1. 课题及企业背景；
2. 主要目标用户与关键情境；
3. 临时Persona与已知依据；
4. 一个核心假设和两个次级假设；
5. 计划观察的流程与行为；
6. 三至五个核心访谈问题；
7. 需要获得的证据类型；
8. 可能出现的反例；
9. 五人现场分工；

# 七、Day 2——Research：用证据理解世界

## 7.1 本日故事

Day 2不是参观日，而是证据日。学生进入企业不是为了“看到了很多”，而是为了验证昨天的判断：真正的流程是什么、谁受到了影响、用户如何应对、哪些假设被支持、哪些假设必须被推翻。

## 7.2 本日目标

1. 在安全与保密边界内完成现场观察；
2. 获得至少两条可追溯的一手证据；
3. 完成至少一次有效访谈或事实核对；
4. 记录一个支持原假设的证据和一个反例；
5. 修正、缩小或推翻至少一个原始假设；
6. 通过AI Evidence Night形成结构化证据、用户旅程和洞察候选；
7. 明确AI分析中正确、错误和遗漏的部分。

## 7.3 安全、保密与研究伦理

- 学生仅在企业指定路线和指定区域活动；
- 访谈对象由企业提前确认，不临时围堵一线人员；
- 拍照、录像、录音必须以现场授权为准；
- 未经授权的配方、设备参数、经营数据和个人身份信息不得上传EvoMind；
- 不进入未开放区域，不接触设备、原料和半成品；
- 不因完成任务而妨碍员工正常工作；
- 引述受访者观点时不得断章取义；
- 若不能记录原话，应在结束前向受访者口头复述并确认；
- “没有找到证据”也是研究结果，不得用想象补齐。

### 现场观察重点

学生优先记录“实际发生了什么”，而不是“我们觉得应该怎样”：

- 用户为了完成任务采取了哪些步骤；
- 哪些环节需要等待、重复输入、返工或依赖经验；
- 哪些信息难以获得、难以理解或无法及时更新；
- 用户使用了哪些非正式工具、纸条、表格或口头提醒；
- 谁在流程中承担了额外协调工作；
- 用户说的流程与实际做的流程是否一致；
- 哪些异常只发生在少数场景，却可能造成重大后果。

# 八、Day 3——Create：创造未来

## 8.1 本日故事

洞察不是用户说了什么，而是团队从行为、情境和矛盾中理解用户为什么这样做。创意也不是越多越好，而是要回应真实洞察，并能通过低成本原型被验证。

Day 3先收敛问题，再发散方案；先做可测试原型，再制作展示材料。EvoMind可以成为Creative Partner，但最终方向必须由学生依据证据决定。

### 洞察质量检查

高质量洞察应同时满足：

- 来源于观察、访谈或流程矛盾；
- 解释“为什么会这样”，而不是重复用户抱怨；
- 能改变团队看待问题的方式；
- 不直接把某项技术写进洞察；
- 对后续创意具有方向性；
- 可以指出支持证据和可能反例。

### POV与HMW格式

**POV：** 我们遇到了一位【具体用户】，他需要【深层需求】，因为【基于证据的关键洞察】。

**HMW：** 我们如何能够【创造某种改变】，从而帮助【具体用户】在【关键情境】中实现【期望结果】？

禁止使用“我们如何开发一个AI系统……”作为HMW开头，因为这会在发散前锁定技术答案。

- 纸面界面或线框图；

- 用户故事板；

原型不要求完成真实算法、完整软件或高精度工业设计。原型的唯一标准是：能否帮助团队回答一个关键问题。

### Feedback Card

测试者独立填写：

- 下一步验证建议；
- 可公开级别。

# 十一、评价机制

## 11.1 评分维度

| 维度 | 权重 | 评价重点 |
|---|---:|---|
| 问题定义与用户洞察 | 25% | 用户、情境、需求与洞察是否清晰，是否避免预设技术答案 |
| 调研证据质量 | 20% | 是否使用可靠一手证据，是否区分事实、解释、假设和AI输出 |
| 方案创新与人机协同 | 15% | 是否形成有意义的新组合，是否体现AI辅助与人的判断责任 |
| 企业价值与可行性 | 20% | 是否理解业务约束，能否说明价值、风险和实施路径 |
| 原型测试与迭代 | 15% | 是否围绕关键问题测试，并根据反馈进行有依据的修改 |
| 展示表达 | 5% | 结构、时间控制、原型演示和团队协作 |

## 11.2 三条硬门槛

- 至少引用两条可追溯的一手现场证据；
- 至少说明一个被现场研究修正、缩小或推翻的原始假设；
- 至少完成一轮原型测试，并展示V1到V2的具体变化。

未达到任一硬门槛的项目，不进入综合金奖候选。

## 11.3 建议奖项

- 综合金奖1组；
- 综合银奖2组；
- 最佳用户洞察奖1组；
- 最佳现场证据奖1组；
- 最佳人机协同创新奖1组；
- 最佳原型迭代奖1组；
- 最具企业价值奖1组；
- 最佳团队协作奖1组。

奖项允许合理兼得，但每项获奖理由必须写入评委合议记录。

# 十五、风险与备用方案

| 风险 | 预防措施 | 备用方案 |
|---|---|---|
| 工厂临时限制参访 | 提前确认路线、产线状态和开放区域 | 使用录制产线视频、远程访谈和脱敏流程材料 |
| 现场不能拍摄或录音 | 提前发布禁拍清单，训练双人速记 | 双人记录，结束前向受访者复述核对 |
| 课题与现场不匹配 | 标注主要验证场域，保留二手材料与预约访谈 | 缩小问题边界或切换到同课题的可验证用户 |
| 学生被课题卡预设方案限制 | Day 1强制执行“解决方案退回问题” | 导师要求重写目标用户、情境和假设后再绿灯 |
| AI生成虚假用户或洞察 | 所有AI内容标为候选，要求关联证据编号 | 退回原始材料，人工完成聚类和洞察 |
| 企业敏感信息被上传 | 开课前培训，证据管理员负责脱敏和权限 | 停止上传、隔离材料、按企业流程处理 |
| 网络或EvoMind不可用 | 提前压力测试，准备离线模板和本地备份 | 人工亲和图、纸面旅程、离线文件夹继续执行 |
| 70人转场拥堵 | 四社区分路线、固定队首队尾和点名 | 分批参访，等待区安排资料分析任务 |
| Day 3过早制作PPT | 规定原型测试完成后才能领取海报模板 | 使用纸面原型和手工A1，不开放提前排版 |
| 原型工具受伤 | 工具培训、集中工具站、助教监管 | 停用高风险工具，改用剪刀、胶带和黏土 |
| 路演文件播放失败 | 前晚提交PPT/PDF，双机双U盘 | 使用PDF、A1海报和实物原型继续展示 |
| 路演超时 | 强制提示铃与主持收口 | 6分钟到点切换问答，不顺延 |

# 十六、执行成功标准

课程结束时应达到：

1. 14组全部完成正式路演；
2. 14组全部提交企业创新资产包；
3. 每组至少引用两条可追溯现场证据；
4. 每组至少说明一个被修正、缩小或推翻的原始假设；
5. 每组完成至少一轮原型测试并展示V1到V2的变化；
6. 每组保留至少三处“AI建议—团队修正—修正理由”记录；
7. 每位学生完成Innovation Reflection；
8. 企业获得14份可继续评估的早期创新提案及结构化项目索引；
9. 全程无安全、保密和人员失联事件；
10. 学生能够清晰说明：AI做了什么，人为什么必须作出最后判断。

# 十七、给所有参与者的最后一句话

> Every Innovation Begins With Someone.

每一次创新，都始于一个真实的人。

当技术越来越强，真正稀缺的能力不是让AI生成更多答案，而是理解谁值得被帮助、什么问题值得被解决、哪些证据值得相信，并愿意为最后的选择承担责任。

这正是AI时代的设计思维。
