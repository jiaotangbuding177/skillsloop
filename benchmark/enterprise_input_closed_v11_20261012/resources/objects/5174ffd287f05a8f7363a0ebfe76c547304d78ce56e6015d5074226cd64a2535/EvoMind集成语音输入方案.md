# EvoMind 集成 AI 语音输入功能的方案分析
> 日期：2026年6月 | 场景：将 Typeless 类产品的能力集成到 EvoMind

---
## 一、需求拆解：要实现什么？
Typeless 的核心能力可以拆成三层：
```
┌──────────────────────────────────┐
│  第三层：AI 润色（去口头禅/改写/翻译）   │  ← LLM 能力
├──────────────────────────────────┤
│  第二层：语音 → 文字（实时听写）        │  ← ASR 能力
├──────────────────────────────────┤
│  第一层：音频采集（麦克风/系统音频）      │  ← 系统层能力
└──────────────────────────────────┘
```
要在 EvoMind 里实现类似功能，就是把这**三层能力**组合起来。

## 二、科大讯飞方案详解
### 2.1 讯飞产品矩阵概览



- 37 个语种 + 37 种方言**免切换识别**
- 三人混叠场景下 86% 准确率（角色分离 + 转写）
- 强噪声环境下的识别能力
- 端侧模型已集成到讯飞输入法 14.0

**对 EvoMind 的价值：**
- 省去"ASR → LLM 润色"的两步处理
- 直接端到端输出高质量文本
- 但 API 是否已开放给开发者需要进一步确认

## 三、EvoMind 集成方案对比
### 方案 A：纯讯飞全栈方案（推荐）
```
┌─────────────────────────────────────────────┐
│  EvoMind 客户端                              │
│                                              │
│  麦克风 → 讯飞语音听写(流式)WebAPI → 原始文本   │
│                              ↓               │
│  润色文本 ← 星火大模型 API ← prompt 指令       │
└─────────────────────────────────────────────┘
```
**优点：**
- 全部走讯飞生态，接口统一、文档完善
- 中文语音识别准确率行业最高（98%+）
- 方言支持无敌（25种方言 + 多语种）
- 成熟稳定，有开源 JS/TS SDK（GitHub 有 xfyun-sdk）
- 成本可控（按小时或按次）

**缺点：**
- 纯云端，无网络不能使用
- 每步都需要 API 调用（两步延迟累计）
- 中文以外的语言准确率不如 Whisper

### 方案 B：讯飞 ASR + 自有 LLM



- 适合：长时间会议记录、直播字幕等
- 接口：`wss://rtasr.xfyun.cn/v1/ws`
- 定价：¥99/10h ~ ¥14,700/3000h
- 支持中英文+部分方言
- **对 EvoMind 来说，日常语音输入用流式听写就够了，RTASR 属于冗余方案**

### 2.4 AI 润色层：星火大模型 API
这是实现 Typeless "去口头禅/改写/翻译" 功能的关键。

**能力：**
- 接入星火 API（需申请 APPID + APIKey + APISecret）
- 可用 SparkChain SDK（支持 Android/iOS/Windows/Linux/Web）
- 可自定义 prompt 实现：去口头禅、改写语气、提炼要点、翻译

**典型 Prompt 示例：**
```
系统：你是一个文字润色助手。用户的输入是语音听写转文字的结果。
请执行以下操作：
1. 去除口头禅（嗯、啊、呃、然后、那个）
2. 修正重复、自我纠正
3. 添加适当标点和分段
4. 保持原意和原风格
5. 直接输出润色后的结果，不要额外回复

用户：[原始语音转写文本]
```
**定价：** 星火 API 按 token 计费，具体需在讯飞开放平台控制台查看最新定价。
### 2.5 最新方案：星火语音大模型（端到端）
2025-2026 年科大讯飞发布的星火语音大模型，将听写+理解+润色**合并为一步**。

**核心突破：**



```
┌─────────────────────────────────────────────┐
│  EvoMind 客户端                              │
│                                              │
│  麦克风 → 讯飞语音听写(流式)WebAPI → 原始文本   │
│                              ↓               │
│  润色文本 ← EvoMind 内置 LLM ← prompt 指令    │
└─────────────────────────────────────────────┘
```
**优点：**
- 润色阶段走自己的 LLM，不受讯飞约束
- 可以结合 EvoMind 已有的知识库做更智能的润色
- 润色环节可本地部署（小模型）

**缺点：**
- ASR 仍依赖云端
- 需要自己维护 LLM 润色的 prompt 和链路

### 方案 C：Whisper（本地）+ 自有 LLM
```
┌─────────────────────────────────────────────┐
│  EvoMind 客户端（全部本地）                    │
│                                              │
│  麦克风 → Whisper 本地模型 → 原始文本          │
│                      ↓                       │
│  润色文本 ← 本地小 LLM ← prompt 指令           │
└─────────────────────────────────────────────┘
```
**优点：**
- 完全离线，隐私最强
- 没有 API 调用成本
- 无限使用

**缺点：**
- Whisper 中文准确率不如讯飞（尤其方言）
- 本地模型推理需要 GPU / Apple Silicon / NPU
- 端侧质量受硬件限制

### 方案 D：混合方案（推荐度最高 ⭐）



| 讯飞产品 | 对应 Typeless 的哪层 | 就绪度 |
|---------|-------------------|:-----:|
| **语音听写（流式版）WebAPI** | 第二层：实时 ASR | ✅ 成熟 |
| **实时语音转写（RTASR）** | 第二层：长时流式 ASR | ✅ 成熟 |
| **星火大模型 API（Spark）** | 第三层：AI 润色/改写/翻译 | ✅ 成熟 |
| **星火语音大模型** | 第二+三层：端到端语音理解 | ✅ 最新 |
| **SparkChain SDK** | 一~三楼：全栈客户端 SDK | ✅ 成熟 |
| **讯飞输入法 14.0 端侧模型** | 一~三楼轻量化 | ⚠️ 需授权 |
### 2.2 核心方案：讯飞语音听写（流式版）WebAPI



- 在方案 B 基础上增加 Whisper 本地备选
- 在线用讯飞（中文最佳），离线用 Whisper（保底）
- 可以根据用户网络质量自动切换
- 兼顾体验和可用性

### 📌 值得注意的点
1. **科大讯飞是中文语音识别的王者**：25+方言、98%+准确率、标点智能预测，这些是 Whisper 等开源方案目前做不到的
2. **星火大模型做中文润色比 GPT 更对味**：对中文口头禅（"然后"、"就是说"、"那个"）的理解和处理，星火有天然优势
3. **讯飞输入法 14.0 已做了类似的事**：它用了星火端侧大模型做离线语音 + AI 输入增强，这说明讯飞方案已经在亿级用户规模上验证过了
4. **不要低估方言需求**：如果 EvoMind 用户有方言场景（四川话、粤语、河南话），讯飞几乎是唯一选择
