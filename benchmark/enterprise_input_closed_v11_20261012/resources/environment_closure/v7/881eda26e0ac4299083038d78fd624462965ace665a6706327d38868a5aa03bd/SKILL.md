# 项目工作周报

这是按本来源“已有 weekly-report”的需求恢复的实验初始技能。原技能字节未取得，不是本轮 Darwin 优化结果；不包含历史完成周报。

## 输入

- 用户指定时间范围、项目和成员。没有指定时先查看当前 source 的时间窗、项目和成员上下文；仍不能确定就询问，不猜真实企业事实。
- 用户提供的最近报告可用作结构参考，事实仍从本次可访问的工单、提交和合并请求核对。
- 当前实验可使用 `/workspace/services/gitee_activity.json` 及同 source Gitee facade；这是个人实验映射，不声称恢复原企业身份。

## 工作流

1. 明确时间范围与项目范围，记录采用的起止日期。读取最近报告或参考文档，确认需要保留的栏目。
2. 运行本技能目录的 `scripts/report_inputs.py --state /workspace/services/gitee_activity.json --source-id <当前来源> --since <YYYY-MM-DD> --until <YYYY-MM-DD>`，获取窗口内原始事项及 ID。也可使用当前声明的 Gitee facade 的 issues、pulls、commits、members 查询。
3. 逐项核对状态和时间字段。关闭工单、合并请求和代码提交分别列出；同一事项多种证据指向相同工作时合并描述，仍保留所有引用。提交不等同业务完成，分配不等同本人已完成。
4. 根据用户要求组织为总体进展、主要完成、进行中与阻塞、下一步。需要成员维度时按可核对 author／assignee 归集，身份未知则标未知，不能编造统计。
5. 输出 Markdown 周报或按用户所需格式保存。每个结论保留当前工单号、提交 SHA 或合并请求号；仅有实验本地 ID 时明确该 ID 属于当前实验。
6. 对照数据检查时间窗、重复统计、漏项和状态措辞，再交付报告及采用范围。

## 失败处理

- 数据文件不存在／JSON 不合法：报告实际缺项，不能用历史完成周报冒充当前查询。
- 来源身份不符：停止使用该文件，定位当前 source 文件。
- 时间窗内无活动：交付空窗说明，列出查询范围；不要补造成员工作。
- 最新报告不可读：说明结构参考不可用，按上述基本栏目生成并标注；不声称已读取。
- 某字段不足以归属成员或项目：保留未归属事项，询问需要澄清的字段。

## 边界

只汇总本次可访问证据，不发送消息、不关闭工单、不改代码。不将规划、分配或失败尝试写成已完成工作。后续 Darwin 应以当前实际技能副本为目标；本文件不是优化后的最终答案。
