# EvoMind-KM 项目：实验输入需求说明

> 同源记录只能确认文档题名、超过五人日继续拆分和分配前询问职责；原文档正文无法恢复。下面的产品需求是用户授权拟造的实验任务输入，不是历史业务事实，也不是原 AI 的目标输出。
> 这是未经任务拆解、工期估算及人员分配的输入需求，不包含已完成的目标工单。

## 产品目的
为企业员工提供知识资料管理、AI 会话及技能工作区，帮助员工从可访问资料完成业务任务。

## 待分析的需求
1. 知识资料接入：上传 PDF、Word、表格等文件，显示解析状态、失败原因、重试入口和版本记录；限制不同成员可访问的资料范围。
2. 文档检索与引用：按题名、关键词检索，展示来源段落及文件引用；前台能够知道回答依据的资料版本。
3. AI 会话工作台：会话列表、连续聊天、流式输出、工具执行进度、停止/继续、错误恢复；避免切换会话时重复请求和上下文串线。
4. 技能管理：查看已有技能、版本说明和使用记录；在明确用户请求下创建或更新技能，变更需要可追溯记录。
5. 知识图谱浏览：浏览资料中抽取的节点和关系，在会话中引用用户选中的节点摘要与可访问关联文件。
6. 定时任务管理：列表、创建、修改、取消、登记参数、执行状态和投递状态的区别；没有投递渠道时保留明确说明。
7. 品牌图标选择：需要多套 EvoMind 图标方向，能在深浅界面、浏览器标签和应用入口展示，最终方案尚未确定。

## 分析约束
需要科学地拆分需求；涉及上传、解析、鉴权、前台多状态及失败恢复的需求不能只用一句话概括。任务超过五人日时继续拆成可验证子需求。
成员职责尚未由用户确认；实验中的名字仅作跟进人别名。分配前需向用户确认实际角色，不预先声称某成员已经接受工作。

## 现有技术背景
实验材料假设项目包含独立前端 Web 与 API 服务，使用会话事件流及数据库记录；这是合成技术背景，原文未证实。工作区应与另一个 ZClaw 项目区分，不能只因出现 Agent 术语就猜仓库。
