**Behavior:**

- If given a project name + description → generate the full report using deep research (web search for market data, policy context, competitive landscape, etc.)
- If given a document/paper → extract project info and generate the full report
- If given partial info → ask clarifying questions first, then generate
- Do not treat investment value as the only or primary lens. First establish whether the technical route is feasible, whether the evidence chain is complete, and how it compares with alternative technical routes. Commercialization and investment judgment must follow from that analysis.

**Conclusion discipline:**

- Reports may conclude that a project is strong, average, weak, poor, or not yet judgeable. Do not force a positive conclusion.
- If the evidence supports an "一般", "较差", "暂不建议推进", or similar negative judgment, state it directly and explain the evidence chain.
- Do not invent negative claims just to make a project look weak. Any adverse conclusion must be supported by cited evidence, project-provided data, reproducible technical logic, or clearly stated assumptions.
- If the current materials cannot support a complete technical evidence chain, mark the point as "证据不足 / 待验证 / 暂无法判断" instead of pretending certainty. Then list the specific additional materials or validation directions needed for a follow-up judgment.
- Separate **已证实事实**, **合理推断**, and **待验证假设**. Never write a hypothesis as if it were proven.

**CRITICAL:** Every report must be **research-backed**. Before writing, you MUST search the web for:

- Market size data and growth forecasts (with cited sources)
- Relevant national and local policy documents
- Industry competitive landscape and key players
- Technical comparison with competing approaches
- Technical route feasibility evidence: key mechanism papers, benchmark datasets or experiments, third-party test data if available, engineering scale-up evidence, cost model evidence, safety/reliability evidence, and failure cases
- Alternative technical routes: mainstream route, emerging route, low-cost substitute route, incumbent route, and at least one route that could make the project less competitive
- Team member information (publications, citations, H-index where available)
- Patent/IP status information

When web research and provided materials are insufficient, write an evidence gap table and request the missing materials rather than filling gaps with unsupported conclusions.

## Report Template — Complete Structure

The report follows a **fixed 9-section structure** plus a quantitative scoring table, totaling **≥20 pages** when rendered to PDF (approximately ≥12,000 Chinese characters). The structure NEVER varies regardless of project type; only the content depth and emphasis shift.

### 第1节：技术基本情况 **【≥2.5页，约1500字】**

#### 自由叙述部分

内容顺序：

1. **问题定义** — 现有技术/行业面临的核心矛盾（如"容量与稳定性的矛盾""成本与性能的不可能三角"）
2. **技术路线定义** — 本项目选择的技术路径、核心机理、与现有方案的根本区别
3. **技术路线可行性分析** — 说明关键技术假设、必要验证条件、已完成验证、未完成验证和失败模式
4. **技术机理详解** — 具体的结构设计、功能机制、反应原理（含化学式/物理模型描述）
5. **关键实验数据** — 性能指标的量化呈现（比容量、循环寿命、效率、速率性能等，与竞品数据对比）
6. **工程化与边界条件** — 分析样品尺度、验证环境、重复性、稳定性、安全性、成本、供应链、制造一致性和放大风险

#### 技术证据链要求（必须包含）

用一张表把核心技术判断拆成证据链，不允许只给结论：

| 判断问题 | 已有证据 | 证据来源 | 证据强度 | 缺口/反证 | 当前结论 |
| -------- | -------- | -------- | -------- | -------- | -------- |
| 技术机理是否成立 | [论文/实验/第三方数据] | [引用编号] | 强/中/弱 | [缺口] | 成立/部分成立/待验证 |
| 关键性能是否达标 | [量化指标] | [引用编号] | 强/中/弱 | [竞品或标准差距] | 达标/未达标/待验证 |
| 工程放大是否可行 | [中试/样机/工艺数据] | [引用编号] | 强/中/弱 | [放大风险] | 可行/不确定/不可行 |
| 成本路径是否合理 | [成本模型/BOM/工艺耗材] | [引用编号] | 强/中/弱 | [成本缺口] | 合理/不确定/不合理 |
| IP与FTO是否支撑转化 | [专利/论文公开/FTO] | [引用编号] | 强/中/弱 | [权属或规避风险] | 支撑/有限/待查 |

证据强度判断：

- **强**：项目原始数据、第三方测试、同行评议论文、公开专利、权威标准或多来源一致数据互相支撑。
- **中**：有单一来源数据或间接证据支撑，但缺少独立复核、样本规模、长期稳定性或工程化数据。
- **弱**：只有团队陈述、概念图、未公开实验结果、营销材料或无法复核的数据。

| -------- | -------- | ---------- | ------------ | ------------ | -------- | -------- | -------------- | -------- |
| 本项目路线 | | | | | | | | |
| 主流路线A | | | | | | | | |
| 替代路线B | | | | | | | | |
| 新兴路线C | | | | | | | | |

如果资料不足以判断路线优劣，写"暂无法判断"，并列出需要补充的数据，例如第三方测试报告、工艺流程、BOM成本、长期稳定性、实际场景验证、FTO检索报告或客户试用反馈。

### 第3节：行业分析

这是报告最长、最重的章节**【≥6页，约3600字】**，包含5个子节。**必须通过网络搜索获取最新数据**。每个子节必须充实饱满，不可缩略。

#### 3.1 行业定义、技术原理与发展脉络 **【≥1.2页，约720字】**

内容结构：

- **行业定位与定义**（1段）：精确界定项目所属行业域，点出其在产业链中的位置和价值占比
- **技术路线谱系**（编号列举3-5条）：主流路线、替代路线、新兴路线、低成本路线、政策或标准偏好的路线；每条说明机理、成熟度、代表企业/论文、典型性能和应用场景
- **与传统/替代技术的根本区别**（编号列举2-3点）：技术机理对比、性能维度对比、应用场景差异、成本/工程化差异
- **技术发展脉络**（按阶段划分3-4个时代）：
  - 第一代：[时代名称](年份范围) — [特征描述]
  - 第二代：[时代名称](年份范围) — [特征描述]
  - 第三代：[时代名称](年份范围) — [特征描述]
  - 本项目定位：在发展脉络中的坐标
- **路线竞争结论**（1段）：说明本项目路线相对其他路线是"领先""补充""跟随""利基""证据不足"还是"被替代风险较高"，并说明证据依据。没有完整证据时不得强行下路线优劣结论。

#### 3.2 宏观背景与政策驱动 **【≥1.2页，约720字】**

三层递进结构：

- **全球层面**（1段）：国际气候协议、全球战略趋势、国际竞争态势
- **中国层面**（编号列举2-3个子条）：
  - 顶层设计与路线图：引用具体国家政策文件名称
  - 能源安全/产业升级/节能降碳等分论点
  - 每条必须引用**具体政策文件名称和发布年份**
- **地方层面**（1段）：上海/长三角相关政策、产业集群优势

#### 3.3 市场规模与潜力分析 **【≥1.2页，约720字】**

- **整体市场规模预测**（编号列举2-3个数据源）：
  - 市场规模数据 + CAGR + 数据来源标注（如"据GGII预测，2025年中国XXX市场规模将达XX亿元，CAGR XX%"）
- **细分应用市场深度挖掘**（编号分类2-3个核心场景）：
  - 场景1：[场景名称] — 市场规模 + 增长驱动因素 + 具体应用案例
  - 场景2：[场景名称] — …
  - 场景3：[场景名称] — …
  - 每个场景含子条细化

#### 3.4 行业痛点与技术挑战 **【≥1.2页，约720字】**

编号列举3-4大痛点，每个含：

- **痛点标题**（含中英文标注或隐喻式命名）
- 论述段落
- 子条分解（2-3个子要点）

**痛点命名范式（从案例中归纳）：**

| 痛点类型 | 常见命名模式             | 示例                                                        |
| -------- | ------------------------ | ----------------------------------------------------------- |
| 性能瓶颈 | "XX-XX的矛盾/不可能三角" | "能量效率-经济性的根本困境""活性-稳定性-选择性的不可能三角" |
| 成本障碍 | "XX的成本困境/紧箍咒"    | "毁灭性的成本劣势""贵金属的成本紧箍咒"                      |
| 规模化   | "XX的魔咒/黑箱"          | "工艺放大的魔咒""前驱体工艺黑箱"                            |

#### 3.5 产业链与竞争格局 **【≥1.2页，约720字】**

- **产业链结构分析**（编号3层）：

  - 类别1（如传统巨头）：代表企业 + 核心优势 + 战略意图与挑战

### 第4节：核心优势、证据缺口与风险 **【≥2.5页，约1500字】**

#### 4.1 核心可取之处与潜在价值 (Bull Case)

编号列举4-5项优势，每项含：

- **粗体标题**（含隐喻或意象化命名）
- 详述段落（含数据引用），**每项≥150字**
- 每项必须说明该优势来自哪一段证据链：技术机理、量化性能、路线差异、成本潜力、工程化能力、政策/市场需求或IP壁垒。不能把"团队声称"直接写成确定优势。

**Bull Case标题命名范式：**

| 项目特征 | 常见Bull Case标题                                            |
| -------- | ------------------------------------------------------------ |
| 材料类   | "颠覆性的性能突破""潜在的成本优势与供应链安全""赋能型上游技术定位" |
| 器件类   | "差异化应用场景的'独占'潜力""世界级性能指标的学术背书""制造工艺创新解决行业痛点" |
| 系统类   | "万亿赛道交叉点的战略站位""数据壁垒与平台锁定效应""可复制的商业模式雏形" |
| 环保类   | "认知颠覆性与议题设置能力""独家稀缺的全国性数据集""与国家顶层战略的高度耦合" |

#### 4.2 主要风险与挑战 (Bear Case)

编号列举4-5项风险，每项含：

- **粗体标题** + **英文风险类别标注**
- 详述段落，**每项≥150字**
- 风险必须区分"已被证据证实的风险"和"仍待验证的风险假设"。如果没有完整证据链，不要写成确定性失败结论。
- 对于可能导致项目"一般/较差"评价的风险，必须说明证据来源、与替代路线或行业门槛的差距、以及仍需补充的验证材料。

**风险类别标注（固定5类）：**

| 英文标注               | 中文含义          | 适用场景                              |
| ---------------------- | ----------------- | ------------------------------------- |
| Fundamental Risk       | 基础性/根本性风险 | 材料本征缺陷、物理限制                |
| Execution Risk         | 执行风险          | 工艺放大、工程实现                    |
| Competition Risk       | 竞争风险          | 技术路线竞争、市场格局挤压            |
| Commercialization Risk | 商业化风险        | 商业模式缺失、团队基因缺陷            |
| IP Risk                | 知识产权风险      | 专利布局不足、FTO障碍、核心方法已公开 |

**Bear Case排列规则：** 按对技术路线可行性和转化路径的影响排序。只有证据链足够完整时，才可称为"致命风险"；否则使用"关键不确定性"或"待验证风险"。

**从案例归纳的高影响风险类型：**

| 高影响风险维度     | 典型表现                                                  | 评分影响                 |
| ---------------- | --------------------------------------------------------- | ------------------------ |
| **性能不达标**   | 核心指标远低于商业化门槛（如循环寿命100圈vs商业化1000圈），且有可核验测试数据支撑 | 技术成熟度极低(2-3/10)   |
| **成本不可能**   | 贵金属依赖、极端工艺或供应链约束导致材料/制造成本远超市场可接受范围，且有成本模型支撑 | 经济效益可低至1-2/15 |
| **IP丧失**       | 核心方法已通过论文公开发表或被他人专利覆盖，且专利/FTO证据明确 | 法律稳定性最低(1-3/5)    |
| **商业基因缺失** | 团队无商业化经验、无产业合作、无客户验证，但需结合项目阶段判断，不得单独作为技术否定依据 | 商业化风险标注           |
| **路线替代风险** | 替代技术在成熟度、成本、性能或生态上明显占优，且项目路线没有清晰差异化 | 技术寿命、市场潜力、经济效益扣分 |

### 第6节：综合判断与推进建议 **【≥2页，约1200字】**

本节不能只从投资角度写。先给出技术路线可行性判断，再说明商业化/投资含义。若技术证据链不足，优先建议补充验证，而不是给出伪确定性的估值或退出结论。

#### 6.1 技术路线可行性结论

必须覆盖：

1. **技术路线当前判断**：可行/部分可行/不确定/暂不支持可行/证据不足。说明对应证据。
2. **与替代路线相比的位置**：领先、并行、有利基价值、跟随、被替代风险高或暂无法判断。
3. **关键验证门槛**：列出3-5个可量化里程碑，例如性能指标、稳定性、放大尺度、单位成本、第三方测试、客户场景验证、FTO结论。
4. **不确定性边界**：说明哪些判断不能下结论，以及需要哪些材料。

#### 6.2 商业化与投资含义

内容结构根据评分档位不同：

**50分以下的项目（较差/暂不建议推进）：**

- 定性结论：不宜直接进入投资或高成本转化动作
- 定位为"证据链补齐项目"或"关键假设验证项目"
- 只有在补齐关键技术证据后再讨论估值
- 资金性质：小额概念验证资助/专项验证经费，而非股权投资
- 资金用途：[编号3条具体用途]，必须围绕技术验证、替代路线对比、第三方测试或FTO

**50-69分的项目（一般/需补充验证）：**

- 定性结论：传统估值方法(P/E, P/S, DCF)不适用
- 定位为"科学期权"(Science Option)或"技术期权购买"
- 资金性质：概念验证资助/科研基金，而非股权投资
- 估值区间：≤1000万人民币（投前）
- 融资建议：100-300万人民币级别
- 资金用途：[编号3条具体用途]

**70-84分的项目（中等风险/有潜力）：**

- 估值方法论：可比公司分析 + VC Method
- 编号3个估值因子分析：
  1. 技术原创性溢价 vs 竞争格局折价
  2. 团队背景溢价 vs 商业能力短板折价
  3. 商业模式路径下的价值天花板
- 融资建议：数百万元人民币级别
- 估值区间：3000万-5000万人民币（投前）
- 明确指出投资条款应包含**可量化的技术里程碑**

**85-100分的项目（高价值/接近商业化）：**

- 估值方法论：可比交易 + 战略并购价值 + ESG溢价
- 种子轮/天使轮可比参考：5000万-1.5亿人民币
- 分阶段价值增长：TRL提升 → 估值倍增
- 融资建议：1000万-1500万人民币
- 估值区间：8000万-1.2亿人民币（投前）

#### 6.3 退出路径分析 (Exit Strategy)

编号列举3条退出路径：

1. **并购退出 (M&A)** — 最可能路径
   - 列举潜在收购方类别（材料巨头、电池厂向上整合、化工集团等）

2. **后续轮次融资退出 (Secondary Sale)** — 下一可能路径

3. **首次公开募股 (IPO)** — 远期路径
   - 目标板块说明（科创板/创业板等）
   - 注明时间窗口和前提条件

**退出路径概率标注：**

- 50分以下项目：最可能结果是"停止推进/回到技术验证/政策或科研转化"，不得包装为正常投资退出
- 50-69分项目：最可能结果是"继续验证/项目库观察/小额资助后再判断"
- 70-84分项目：并购退出为最可能
- 85-100分项目：IPO为可期待路径

### 第7节：结论与尽职调查建议 **【≥2页，约1200字】**

#### 推进/投资建议

一段明确建议 + 跟踪条件：

- 明确的定性建议（如"暂不建议推进""纳入项目库跟踪""建议进入概念验证实训""积极推进概念验证服务"）
- 可触发重新评估的突破条件（编号3条）：
  1. [量化里程碑1]（如"循环寿命突破1000圈@80%"）
  2. [量化里程碑2]
  3. [量化里程碑3]

#### 需补充资料与再判断条件

如果任一关键结论缺少完整证据链，必须列出本小节。按优先级给出需要补充的资料：

1. **技术验证材料**：原始实验数据、测试方法、样本数量、重复性数据、对照组、第三方测试报告。
2. **路线对比材料**：替代技术路线的公开benchmark、成本/性能对比、标准门槛、应用边界。
3. **工程化材料**：工艺流程、放大路线、中试数据、BOM成本、关键设备和供应链约束。
4. **IP/FTO材料**：专利清单、权属证明、论文公开时间、FTO检索报告。
5. **市场与客户材料**：客户访谈、试用反馈、采购门槛、付费意愿、替代方案采购价格。

#### 尽职调查核心清单 (Key Due Diligence Checklist)

编号4条，每条含标题+英文标注+子要点：

1. **团队与治理 (Team & Governance)** — 3个子要点
2. **技术与生产 (Technology & Production)** — 3个子要点
3. **知识产权状态 (Intellectual Property)** — 2-3个子要点
4. **市场与合作 (Market & Partnership)** — 2-3个子要点

**DD清单的针对性差异：**

| 高影响风险/证据缺口 | DD清单重点调整 |
| ------------------- | -------------- |
| 性能不达标或证据不足 | DD第2条变为"性能导向验证"，含一票否决性量化门槛、测试方法、对照组和第三方复核要求 |
| 成本不可行或成本模型缺失 | DD新增"成本分析"专项，含公斤级/单台/单次服务成本模型、BOM、工艺耗材和规模效应假设 |
| IP丧失或FTO不明 | DD第3条变为"IP/FTO重建"，含停止公开、第二代工艺专利策略、权属证明和自由实施检索 |
| 替代路线压制风险 | DD增加路线对比专项，要求提供与主流路线、低成本路线和新兴路线的benchmark对比 |
| 商业基因缺失 | DD第1条加强"团队转型意愿评估"，但不得把商业基因不足单独作为技术不可行结论 |

```markdown
| **其他因素** | 转化难度 | X/10 | [从实验室到商业化的鸿沟评判] |
| **总分** | | **XX/100** | [对应评级定性描述 + 总分含义解读；证据不足时说明暂不完整评分原因] |

> **评级标准：**
> - <50分：较差/暂不建议推进，只有在补齐关键技术证据或出现重大技术突破后再评估
> - 50–69分：一般/需补充验证，可进入项目库观察，但不宜直接推进高成本转化或投资动作
> - 70–84分：较有价值，进一步推进概念验证实训，但需设置技术与商业里程碑
> - 85–100分：高价值，积极推进开展概念验证服务及关联服务
> - 证据不足：暂无法完整评分，先补充技术、市场、IP或团队材料，再重新评分
```

#### 评分逻辑（从18个案例归纳的评分范式）

**技术先进性 (10分)**：

- 9-10分：原理高度原创，实现颠覆性突破，世界前沿水平
- 6-8分：方法有创新性，但属于众多解决方案之一而非唯一方案
- 3-5分：改良型创新，在已有框架内优化

**技术成熟度 (10分)**：

- 6-8分：TRL 5-6，有中试数据支撑
- 3-5分：TRL 3-4，实验室尺度验证，核心性能可能未达标
- 1-2分：TRL 2-3，仅有理想化实验数据，无放大/成本研究

**法律稳定性 (5分)**：

- 4-5分：已提交专利申请，FTO风险低，IP归属清晰
- 3分：有初步专利，但多方合作增加归属复杂性
- 1-2分：核心方法已通过论文公开，构成颠覆性IP障碍

**市场潜力 (15分)**：

- 13-15分：万亿级赛道核心材料/技术，需求真实迫切
- 10-12分：百亿级细分市场，有明确增长驱动力
- 6-9分：十亿级利基市场或市场定义尚不清晰

**经济效益 (15分)** — **最关键的差异化指标**：

- 13-15分：成本优势明确，有可行的商业模式和收入路径
- 7-12分：理论降本增效潜力大，但被低成功概率对冲
- 1-6分：成本不可行（贵金属依赖等）或一票否决级障碍，且必须有成本模型或行业价格门槛支撑
- **特殊标注**：可标注"一票否决项"当成本构成根本障碍，但必须说明证据来源和计算假设

**产业关联度 (10分)**：

- 9-10分：精准瞄准产业链核心痛点，与国家战略高度契合
- 6-8分：与产业升级方向相关，但非最核心环节
- 3-5分：产业关联间接，战略契合度一般

**标准相关性 (5分)**：

- 5分：有望成为定义下一代性能标准的引领者
- 3分：与现有标准有一定关联
- 1-2分：与行业标准无关，性能远低于标准要求

**技术寿命 (10分)**：

- 8-10分：平台型工艺不易被淘汰，有跨材料体系迁移潜力
- 5-7分：当前有效但面临技术迭代风险，窗口期有限
- 3-4分：替代技术涌现快，长期领先地位不确定性高

**保护范围 (10分)**：

- 7-10分：核心专利权利要求宽泛，难以规避
- 5-6分：保护集中在特定结构/组合，可能被替代设计规避
- 2-4分：核心原理已公开，外围专利保护范围狭窄

**转化难度 (10分)** — **注意：高分=难度低，低分=难度高**：

- 7-10分：有清晰转化路径，工程放大挑战可控
- 4-6分：存在显著放大/工程化鸿沟，但有可探索路径
- 1-3分：几乎无法逾越的转化壁垒（严重性能短板+放大不确定性+成本不可行三重叠加，且有证据支撑）

#### 评分规则

1. 每个细分指标的评分说明必须是一段**有论证的定性文字**，而非一句话
2. 评分说明必须包含：**定量证据+定性判断+扣分/加分理由**
3. 总分行必须包含：分数 + 对应评级定性描述 + 项目特征一句话总结；证据不足时必须说明暂不完整评分的原因
4. 总分必须等于10个细分指标分数之和（注意加总一致性）
5. 如果某个指标缺少足够证据，不得用想象补分或扣分；应标注"证据不足"，给出临时保守分或暂不评分，并说明需要补充的资料。
6. 低分、"一般"、"较差"、"暂不建议推进"等结论必须来自证据链：行业门槛、替代路线对比、实测数据差距、成本模型、IP/FTO或商业化验证缺口。不得为了压低评价而夸大风险。

## 报告生成流程

### Step 1: 信息采集与深度研究

在生成报告前，必须进行以下研究（使用WebSearch和WebFetch工具）：

1. **技术背景研究**：
   - 搜索项目技术的最新进展和竞品对比
   - 确认TRL等级和关键性能指标的行业基准
   - 搜索本项目技术路线的机理证据、实验数据、第三方验证、工程放大证据、成本证据、安全/可靠性证据和失败案例
   - 建立"技术假设 → 已有证据 → 证据强度 → 缺口/反证 → 当前判断"证据链

2. **替代技术路线研究**：
   - 识别至少3条路线：本项目路线、主流 incumbent 路线、最有威胁的新兴/低成本替代路线
   - 搜索每条路线的代表企业/论文/产品、TRL、关键性能、成本与规模化状态
   - 判断替代路线是否削弱本项目的差异化或商业化必要性

3. **市场数据研究**：
   - 搜索相关行业的市场规模数据（全球+中国）
   - 获取CAGR和市场预测
   - 搜索细分应用场景的市场数据

4. **政策环境研究**：
   - 搜索国家层面相关政策文件（双碳、新能源、新材料等）
   - 搜索上海/长三角地方政策
   - 获取政策文件名称和发布年份

5. **竞争格局研究**：
   - 搜索产业链上下游关键企业
   - 搜索竞品技术路线和代表企业
   - 获取国际国内竞争态势

6. **团队信息研究**（如可公开获取）：
   - 搜索核心团队成员的学术履历
   - 获取论文数、引用数、H指数（如Google Scholar可查）
   - 确认团队构成和合作网络

### Step 2: 报告框架搭建

根据研究结果，确定：

- 项目类型分类（材料/器件/系统/环保）
- TRL等级判定
- 技术路线可行性初判（可行/部分可行/不确定/暂不支持可行/证据不足）
- 替代技术路线基准与本项目相对位置
- 证据链完整度判定（哪些结论可判断，哪些必须暂缓）
- 高影响风险或证据缺口判定（性能/成本/IP/商业基因/路线替代/工程放大）
- 评分档位预判（<50/50-69/70-84/85-100/证据不足）
- Bull/Bear Case条目选择

### Step 3: 各章节逐节生成

按以下顺序生成：

1. 先生成技术证据链表和替代技术路线对比表
2. 再生成评分表（确定总分和各指标分数），但不得超出证据链支持范围
3. 再生成摘要和标题块（基于证据链、路线对比和评分结论）
4. 然后生成第1-8节（基于研究数据）
5. 最后生成参考文献

### Step 4: 一致性校验

生成后必须检查：

- 总分 = 10个细分指标之和（数学一致性）
- 总分对应的评级档位与标题块/摘要/结论中的定性描述一致
- 摘要中的三大风险与第4节Bear Case对应
- 技术路线可行性判断与第1节证据链、第3.1节路线对比、第4节风险判断一致
- 商业化/投资建议与评分档位和技术证据链匹配
- 参考文献编号与正文引用编号对应
- TRL等级与技术成熟度评分逻辑一致
- 所有"一般/较差/不可行/暂不建议推进"结论都有证据来源；没有证据的地方已标注"证据不足/暂无法判断"

## 写作风格规范

### 语言风格

- **证据性语气**：平衡机会与风险，避免一味褒扬或一味否定；结论必须跟随证据，不得先设定结论再找论据。
- **审慎判断**：允许写"一般""较差""暂不建议推进"，但必须有完整证据链；证据不足时写"暂无法判断"，并列出补充资料方向。
- **隐喻/意象化表达**：章节标题和核心论点可以适度使用意象化命名（如"不可能三角""黑箱""鸿沟"），但不得用修辞替代证据。
- **英文标注**：关键概念标注英文对照（如 Bull Case/Bear Case/Go-to-Market Strategy/Exit Strategy/DD Checklist）
- **风险类别英文标注**：Bear Case每条标注风险类别（Fundamental/Execution/Competition/Commercialization/IP Risk）
- **量化优先**：所有性能、市场、成本论述优先使用量化数据，辅以来源标注
- **来源边界**：区分公开来源、项目方材料、第三方测试、作者推断和待验证假设。不得把无法验证的项目方陈述写成事实。

### 段落结构范式

全文遵循"**先定性概括、后分点展开、再综合收束**"的写作范式：

- 每节开头一段定性概括
- 中间编号分点展开（每点含粗体标题+详述段落）
- 结尾综合收束句

### 引用规范

- 正文中使用方括号编号引用：[1] [2] [3]…
- 引用紧跟在相关论述后，不堆砌在段尾
- 参考文献列表在最后独立章节

### 格式规范

- 使用Markdown格式
- 表格使用Markdown表格语法
- 信息块使用引用语法（`> **字段**：值`）
- 粗体标题使用 `**粗体**`
- 编号列表使用 `1. 2. 3.`
- 子条使用 `- 子条`
