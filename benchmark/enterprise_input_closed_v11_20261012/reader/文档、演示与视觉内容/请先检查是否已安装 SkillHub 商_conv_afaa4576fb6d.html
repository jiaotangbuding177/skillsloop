# EvoMind 集成 AI 语音输入功能的方案分析
> 日期：2026年6月 | 场景：将 Typeless 类产品的能力集成到 EvoMind

---
## 一、需求拆解：要实现什么？
Typeless 的核心能力可以拆成三层：
```
┌──────────────────────────────────┐
│  第三层：AI 润色（去口头禅/改写/翻译）   │  ← LLM 能力
├──────────────────────────────────┤
│  第二层：语音 → 文字（实时听写）        │  ← ASR 能力
├──────────────────────────────────┤
│  第一层：音频采集（麦克风/系统音频）      │  ← 系统层能力
└──────────────────────────────────┘
```
要在 EvoMind 里实现类似功能，就是把这**三层能力**组合起来。

---
## 二、科大讯飞方案详解
### 2.1 讯飞产品矩阵概览

[资料 2] 文件: EvoMind集成语音输入方案.md 路径: EvoMind集成语音输入方案.md
- 37 个语种 + 37 种方言**免切换识别**
- 三人混叠场景下 86% 准确率（角色分离 + 转写）
- 强噪声环境下的识别能力
- 端侧模型已集成到讯飞输入法 14.0

**对 EvoMind 的价值：**
- 省去"ASR → LLM 润色"的两步处理
- 直接端到端输出高质量文本
- 但 API 是否已开放给开发者需要进一步确认

## 三、EvoMind 集成方案对比
### 方案 A：纯讯飞全栈方案（推荐）
```
┌─────────────────────────────────────────────┐
│  EvoMind 客户端                              │
│                                              │
│  麦克风 → 讯飞语音听写(流式)WebAPI → 原始文本   │
│                              ↓               │
│  润色文本 ← 星火大模型 API ← prompt 指令       │
└─────────────────────────────────────────────┘
```
**优点：**
- 全部走讯飞生态，接口统一、文档完善
- 中文语音识别准确率行业最高（98%+）
- 方言支持无敌（25种方言 + 多语种）
- 成熟稳定，有开源 JS/TS SDK（GitHub 有 xfyun-sdk）
- 成本可控（按小时或按次）

**缺点：**
- 纯云端，无网络不能使用
- 每步都需要 API 调用（两步延迟累计）
- 中文以外的语言准确率不如 Whisper

### 方案 B：讯飞 ASR + 自有 LLM

[资料 3] 文件: EvoMind集成语音输入方案.md 路径: EvoMind集成语音输入方案.md
- 适合：长时间会议记录、直播字幕等
- 接口：`wss://rtasr.xfyun.cn/v1/ws`
- 定价：¥99/10h ~ ¥14,700/3000h
- 支持中英文+部分方言
- **对 EvoMind 来说，日常语音输入用流式听写就够了，RTASR 属于冗余方案**

### 2.4 AI 润色层：星火大模型 API
这是实现 Typeless "去口头禅/改写/翻译" 功能的关键。

**能力：**
- 接入星火 API（需申请 APPID + APIKey + APISecret）
- 可用 SparkChain SDK（支持 Android/iOS/Windows/Linux/Web）
- 可自定义 prompt 实现：去口头禅、改写语气、提炼要点、翻译

**典型 Prompt 示例：**
```
系统：你是一个文字润色助手。用户的输入是语音听写转文字的结果。
请执行以下操作：
1. 去除口头禅（嗯、啊、呃、然后、那个）
2. 修正重复、自我纠正
3. 添加适当标点和分段
4. 保持原意和原风格
5. 直接输出润色后的结果，不要额外回复

用户：[原始语音转写文本]
```
**定价：** 星火 API 按 token 计费，具体需在讯飞开放平台控制台查看最新定价。
### 2.5 最新方案：星火语音大模型（端到端）
2025-2026 年科大讯飞发布的星火语音大模型，将听写+理解+润色**合并为一步**。

**核心突破：**

```
┌─────────────────────────────────────────────┐
│  EvoMind 客户端                              │
│                                              │
│  麦克风 → 讯飞语音听写(流式)WebAPI → 原始文本   │

**优点：**
- 润色阶段走自己的 LLM，不受讯飞约束
- 可以结合 EvoMind 已有的知识库做更智能的润色
- 润色环节可本地部署（小模型）

**缺点：**
- ASR 仍依赖云端

### 方案 C：Whisper（本地）+ 自有 LLM
```
┌─────────────────────────────────────────────┐

│  麦克风 → Whisper 本地模型 → 原始文本          │

- 本地模型推理需要 GPU / Apple Silicon / NPU
- 端侧质量受硬件限制

## 科大讯飞与 EvoMind 的关系

从产品层面看，科大讯飞是 **EvoMind 语音输入能力的最佳技术供应商**。具体关系如下：

### 核心定位：三层能力的对接

EvoMind 如果要具备类 Typeless 的语音输入能力，需要解决三层问题，而讯飞恰好覆盖了全部三层：

| 层级 | 能力 | 科大讯飞产品 | 对 EvoMind 的价值 |
|------|------|-------------|------------------|
| 第三层 | AI 润色（去口头禅/改写/翻译） | **星火大模型 API** | 用中文优化的 LLM 做语音转写后的润色，对中文口头禅（"然后"、"那个"）的处理比通用模型更对味 |
| 第二层 | 语音 → 文字（实时听写） | **语音听写（流式版）WebAPI** | 中文语音识别准确率 98%+，支持 25+ 种方言，这是 Whisper 等开源方案做不到的 |
| 第一层 | 音频采集 | **SparkChain SDK** | 全栈客户端 SDK，打包麦克风采集 + ASR + 润色链路 |

### 推荐方案：讯飞 ASR + 自有 LLM 的组合

文档中推荐的 **方案 B** 最匹配 EvoMind 的产品架构：

```
麦克风 → 讯飞语音听写(流式)WebAPI → 原始文本
                              ↓
润色文本 ← EvoMind 内部 LLM ← prompt 指令
```

**优势在于：**
- 语音识别走讯飞（中文最强），保证基础体验
- 润色走 EvoMind 自身的 LLM，可以和已有知识库结合，做更智能的润色
- 不绑定讯飞生态，架构灵活

### 几个值得关注的点

1. **方言是差异化护城河** — 讯飞支持 25+ 种方言免切换识别，如果 EvoMind 用户有四川话、粤语等场景，讯飞几乎是唯一选择
2. **讯飞输入法 14.0 已经验证了这条路** — 它用星火端侧大模型做离线语音 + AI 输入增强，说明这套方案在亿级用户规模上跑通了
3. **星火语音大模型是更前沿的方向** — 将听写 + 理解 + 润色合并为一步，未来可以省掉两步流水线的延迟
4. **混合方案（讯飞在线 + Whisper 离线）可作为保底** — 有网用讯飞拿最佳体验，无网切 Whisper 保证可用

### 总结

科大讯飞不是 EvoMind 的竞品，而是 **EvoMind 在语音能力层面的基础设施伙伴**。EvoMind 构建的是"企业不可替代的 AI 学习循环系统"，而讯飞提供了这个系统中**语音输入这一关键入口**的最佳中文解决方案。
