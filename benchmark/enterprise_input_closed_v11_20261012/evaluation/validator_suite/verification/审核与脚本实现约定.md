# 本轮审核与校验脚本的实现约定

用户于2026-10-12明确授权：审核每条评测任务的必要最终交付与最基本要求，通过后编写每任务校验脚本，质量留给后续评测。此授权限于本轮独立校验包、必要的控制用例和新版本验收合同，不改原作者算法或冻结benchmark，不执行企业任务、模型生成或远端消息发送。

## 审核门槛

每条完整会话逐轮确认必要交付，同对象按最后仍有效要求验收，后续未取消的独立交付继续保留。无用户依据的数量/篇幅门槛移除，具名对象错配更正；正文非空仅证明文字交付，不能外推为内容正确或充分。具体事实、计算与专业判断、视觉水平、代码业务功能、OCR全面准确性等进入后续质量链。

先完成三个不重叠来源组的设计审核，核对覆盖全部226来源、462旧检查以及已有107建议，再编译新版本。每条新增或撤回检查保留依据及理由，不直接把旧建议全部加入AND。明确目标但输入缺证的执行前置问题与检查设计是否可编码分列，不能把脚本设计审核通过称作环境全部准备好。

## 独立脚本协议

每条来源有具名Python入口、独立冻结合同和SHA。入口读取本次运行的request/最终result及独立evidence，固定使用自己的合同，不接受调用方替换。共同的格式解析与判定逻辑可以复用；每任务的交付对象、参数和检查集合独立，禁止空入口或固定返回成功。

通过为1，正常可观察的缺产物/参数错误为0；缺测量、来源错位、会话尚未结束或解析器不可用为UNSCORED/unknown，不能直接记失败或删除任务分母。质量与中间工具失败不计分。定时任务只检查实际登记记录及参数，不等待触发。

脚本读取真实文件与终态服务读回；没有文件、只有完成声明不能当文件交付。输入件/初态文件不能充当新生成文件；原本请求引用已有文件、保留路径或解包的任务应按其明确对象分别处理，不能误伤合理引用。多交付对象需要各自的最终绑定，不广播同一回复充当所有交付。

## 测试矩阵

1. 正常：文字正文、可原生解析文件、正确数量/页数/基础格式、真实记录基本字段；全部必需点AND。相同任务恢复中间错误后最终交付仍应通过。
2. 失败：缺文件、空文件、格式伪装、数量/页数错误、同一文件重复充当多个独立产物、没有必要代码文件而只有方案、应改变的文件/skill保持初态、最终记录参数不合。
3. 未评分：证据缺失、会话未结束、错误来源/工作区、缺动态参数解参、未知解析器或量测故障；脚本必须输出可追溯原因。
4. 范围：同对象末版、已取消旧要求、仍有效独立产物、近似字数只观测、固定全任务分母和未知覆盖率、禁止读取历史AI。
5. 覆盖：226入口可直接运行，合同与入口哈希一致；每种实际启用handler至少有对应控制，新增handler使用正/负/故障控制；不能把这些控制说成企业业务成功率。

既有终态校验器在新增实现前已执行50条离线测试，全部通过，收据见baseline.json。按开发路由将本次多文件校验包视作复杂任务，先记录输入接口/测试矩阵，再开展控制验证；项目没有.trellis/spec，本轮不安装或改写与校验脚本无关的框架、守卫或全局技能，不把研发流程的状态代替用户本次已给出的具体授权。
