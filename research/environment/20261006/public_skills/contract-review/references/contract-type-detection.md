## 1. 9 类合同识别规则

### 1.1 OEM 代工合同（最高频之一）

**识别优先级**：🔴 高

**强特征词**（出现任一即可加权 +3）：
- 标题含："OEM"、"代工"、"委托加工"、"委托生产"、"贴牌"
- 正文含："代工方式"、"代为加工"、"指定加工工厂"、"代为生产"
- 主体关系："甲方（委托方）"、"乙方（被委托方）"、"受托生产"

**辅助特征词**（加权 +1）：
- "包材"、"罐体"、"外箱"、"商标组合"
- "出厂检验报告"、"产品执行标准"
- "贴牌生产"、"品牌授权"、"商标许可使用"

**反例关键词**（加权 -2）：
- "服务"、"咨询"、"培训"（更像服务合同）

**置信度公式**：
```
score = 强特征词数 × 3 + 辅助特征词数 × 1 - 反例数 × 2
score ≥ 5 → 高置信 OEM 代工
3 ≤ score < 5 → 中置信，建议人工确认
score < 3 → 非 OEM 代工
```

## 2. 检测方法学

### 2.1 自动检测（脚本可处理）

```python
def detect_contract_type(text: str) -> dict:
    """
    输入：合同全文
    输出：{"type": "oem_contract", "confidence": "high", "score": 8}
    """
    scores = {}
    for contract_type, rules in TYPE_RULES.items():
        score = 0
        # 标题加权（首段 200 字内）
        title_section = text[:500]
        for kw in rules["strong_keywords"]:
            if kw in title_section:
                score += 5  # 标题中权重 ×5
            elif kw in text:
                score += 3
        for kw in rules["aux_keywords"]:
            if kw in text:
                score += 1
        for kw in rules["negative_keywords"]:
            if kw in text:
                score -= 2
        scores[contract_type] = score

    # 取最高分
    best_type = max(scores, key=scores.get)
    best_score = scores[best_type]

    # 置信度判定
    if best_score >= 8:
        confidence = "high"
    elif best_score >= 4:
        confidence = "medium"
    elif best_score > 0:
        confidence = "low"
    else:
        confidence = "unknown"

    # 第二名差距 < 3 → 标注歧义
    sorted_scores = sorted(scores.values(), reverse=True)
    if len(sorted_scores) > 1 and sorted_scores[0] - sorted_scores[1] < 3:
        confidence = "ambiguous"

    return {
        "type": best_type if confidence != "unknown" else "unknown",
        "confidence": confidence,
        "score": best_score,
        "all_scores": scores
    }
```

### 2.2 标题加权原理

**为什么标题权重 ×5？**
- 合同标题是当事人对合同性质的最直接表达
- 标题中的关键词极少误用（"OEM 代工合同"标题不太可能指服务合同）
- 但完全依赖标题又不够（如"框架协议"标题可能涵盖多种类型）

**策略**：
- 标题关键词：+5（每命中）
- 正文中再次出现：+3（每命中，但同一关键词去重）

### 2.3 多合同类型（混合）

**场景**：OEM 代工合同可能同时含采购要素（设备采购）、服务要素（设计服务）。

**处理**：
- 主类型：得分最高者
- 副类型：得分 ≥ 5 且 < 主类型得分 - 3
- 输出 `secondary_types` 字段，提示审查时加载副类型专项规则

## 4. 使用方法

主 agent 在 Step 0 阶段：

1. 调用 `scripts/detect_contract_type.py` 解析合同全文
2. 获得 `{primary_type, confidence, secondary_types}`
3. **若 `confidence == "high"`**：直接加载 `references/contract-types/{primary_type}.md`
4. **若 `confidence == "medium"` 或 `"ambiguous"`**：输出识别结果给用户确认
5. **若 `confidence == "low"` 或 `"unknown"`**：仅跑通用规则，并在 Word 输出中标注"合同类型识别置信度低"

## 5. 已知陷阱

1. **"合作协议" / "框架协议"**：标题笼统，必须依赖正文关键词
2. **混合合同**：如"设备采购 + 安装服务"，需识别为"采购合同"+"服务合同"两个类型
3. **简称 vs 全称**：用户可能在标题用"代工"，正文用"OEM"，检测需做模糊匹配
4. **简繁混用**：港台合同用繁体，需做简繁转换后扫描（建议依赖主模型常识）
5. **多语种**：涉外合同含英文术语（如"FOB"），需英文关键词库（已包含）

## 6. 边界声明

本文档**不评估**：
- 合同条款的法律合规性
- 合同条款的商业合理性
- 合同金额的合理性

本文档**只评估**：
- 合同**类型**的自动识别（关键词 + 标题 + 上下文）
- 识别**置信度**的量化输出
