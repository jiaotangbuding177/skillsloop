# 可复用流水线：音频驱动的字幕与时间轴生成

三个脚本，解决解说视频的通用问题：**改了文案，画面和声音自动重新对齐**。

这套流水线**不依赖 Remotion**——你用剪映、达芬奇、AE、Premiere 都能套这个思路，
只是最后一步的"时间轴"输出格式不同（本脚本输出的是 Remotion 需要的 `.ts`，
改一下输出函数即可导出 FCP7 XML / EDL / SRT）。

---

## 文件

| 文件 | 作用 |
|------|------|
| `gen_audio.py` | 按场景分段调 edge-tts 生成旁白 mp3，输出每段精确时长 `manifest.json` |
| `gen_subs.py` | 读 manifest + 重新生成句子级 SRT → 二次切分成短句 → 输出帧号时间轴 `subs.ts` |
| `normalize_audio.sh` | 8 段拼接 + EBU R128 响度归一化到 -16 LUFS → `narration.m4a` |

---

## 用法

```bash
# 0. 准备（只需一次）
python3 -m venv /workspace/tts-env
/workspace/tts-env/bin/pip install edge-tts

# 1. 改文案：编辑 gen_audio.py 顶部的 SEGMENTS 数组（一段对应一个场景）
#    改音色/语速：改同文件顶部的 VOICE / RATE

# 2. 跑全流程
source /workspace/tts-env/bin/activate
python3 gen_audio.py          # → audio_r50/s1..s8.mp3 + manifest.json
python3 gen_subs.py           # → src/compositions/stigmergy/subs.ts
deactivate
./normalize_audio.sh          # → public/narration.m4a（-16 LUFS）
```

`gen_subs.py` 会**自动继承** `gen_audio.py` 的 `VOICE` / `RATE` / 输出目录，
不存在两边配置不一致导致音画错位的问题。

## 设计要点

**1. 时长来源是音频，不是估的。**
每段的 mp3 用 `ffprobe` 读真实时长，累加得到连续时间轴。改任何一段文案，
后续所有场景的帧号自动顺延。

**2. 字幕二次切分。**
edge-tts 的 SRT 是句子级的，长句会超出屏幕。脚本按"字宽"再切：
中文/全角算 1，英文数字算 0.6，单行上限 15 字宽，时间按字宽比例分配。
另外会修复中英混排的空格（"MIT刚刚" → "MIT 刚刚"、"AIAgent" → "AI Agent"）。

**3. 响度线性归一化。**
`linear=true` 只施加恒定增益，不压缩动态范围，人声不发闷。

**4. 尾部补齐。**
音频末尾补静音到视频总长，防止 mux 时 `-shortest` 把片尾画面切掉。
时长从 `subs.ts` 的 `TOTAL_FRAMES` 算，**不读已渲染视频**（换语速后旧成片是旧长度，会出错）。

## ⚠️ 配套的一致性维护

跑完脚本后，还有**一个手工步骤**：

画面组件里如果硬编码了场景帧数（如 `const D = 410`）或时间缩放系数，
必须跟着新生成的 `TIMELINE` 一起改。规则：

```
D          = TIMELINE.Sn.dur
缩放分子    = D - 15            （15 = 相邻场景交叉溶解帧数）
缩放分母    = 该场景原始的动画帧数（保持不变）
```

漏了这一步**不会报错**，只会让转场节奏和动效快慢变得别扭。
目前是手动的，也是最容易被忽略的一环。

## 已知限制

- 只做了中文（字宽估算、切分规则都是按中文标点设计的）
- 依赖 `ffmpeg` / `ffprobe` 在 PATH 里
- edge-tts 需要联网，且会间歇限流（脚本已内置重试，但批量大时仍会慢）
