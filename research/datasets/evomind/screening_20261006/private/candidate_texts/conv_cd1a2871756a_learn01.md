查清楚了，原因如下：

### 🔍 根因

技能**物理上存在**（`/opt/openclaw-shared-skills/imap-smtp-email/`，版本 0.0.16），但**系统启动加载时把它过滤掉了**。

看 SKILL.md 里的加载条件：

```yaml
requires:
  env:
    - PROVIDER
    - USERNAME
    - PASSWORD
```

这个技能声明了需要 `PROVIDER`、`USERNAME`、`PASSWORD` 三个环境变量才可启用。系统启动时检测到这些邮箱配置环境变量都没设，就直接跳过了，没注册到我的可用技能列表里。所以我才说"没找到"——不是磁盘上没有，而是条件不满足被系统拦截了。

### ✅ 现在该怎么用

1. **你的 163 邮箱地址**（发件人）
2. **163 邮箱授权码**（去网页邮箱设置 → POP3/SMTP/IMAP 开启服务后获取的授权码，不是登录密码）

## AI处理／结果

来源消息组：a_53b41ef67ebb9ce322

改动只有一处，在 SKILL.md 开头的 `metadata` 部分：

**原版（共享库）：**
```yaml
metadata:
  openclaw:
    emoji: "📧"
    requires:
      bins:
        - node
        - npm
      env:                        ← 移除
        - PROVIDER                 ← 移除
        - USERNAME                 ← 移除
        - PASSWORD                 ← 移除
    primaryEnv: PROVIDER           ← 移除
```

**修改版（用户目录）：**
```yaml
metadata:
  openclaw:
    emoji: "📧"
    requires:
      bins:
        - node
        - npm
```

就是删掉了 `requires.env`（`PROVIDER`、`USERNAME`、`PASSWORD` 三个环境变量要求）和 `primaryEnv` 字段。这样技能就不会因为环境变量未配置而被静默过滤掉，而是正常加载，等用户使用时再引导配置。
