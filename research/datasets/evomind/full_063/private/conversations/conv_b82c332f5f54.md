## 📄 基本信息

**标题**：From Context to Skills: Can Language Models Learn from Context Skillfully?
**作者**：华东师范大学团队
**Arxiv**: `2604.27660v3`
**领域**：cs.AI
**核心问题**：LM 如何在复杂上下文中自主学习技能？

---

## 🧠 核心思想：Ctx2Skill

> 从复杂文档中**自动发现、提炼、选择**上下文特定的 Skill，无需人工标注，无需外部反馈。

### 架构：多 Agent Self-Play

```
Challenger  ←→  Reasoner  ←→  Judge
    ↑                      ↑
Proposer + Generator   Proposer + Generator
```

五个冰冻模型角色，不更新参数，只更新 **Skill Set（自然语言 Markdown）**：

| 角色 | 职责 |
|------|------|
| **Challenger** | 根据上下文和它的 Skill Set，生成任务 + Rubrics（评分细则） |
| **Reasoner** | 根据上下文和它的 Skill Set，回答任务 |
| **Judge** | 按 Rubric 逐条评分，二分判定通过/不通过 |
| **Proposer** | 分析失败/成功模式，诊断缺什么知识 |
| **Generator** | 把诊断写成具体的 SKILL.md |

**关键设计**：两边都有自己的 Skill Set，一起进化。Challenge 方越来越刁钻，Reasoner 方越来越强。

---

## 🚨 关键问题 & 解法：Adversarial Collapse（对抗坍缩）

自对弈到后期，Challenger 会生成**越来越极端**的任务，Reasoner 的 Skill **过度适配**这些极端案例，导致**泛化能力下降**。

**Ctx2Skill 的解法：Cross-Time Replay**

- 每轮选一个 hardest failure 和 easiest success，积累成探针集
- 自对弈结束后，用每个 iteration 的 Skill Set 重新跑探针
- 选 `ρ_hard × ρ_easy` 乘积最大的那个 iteration 的 Skill Set
- **乘法策略**：两边都要好，不能顾此失彼

---

## 📊 实验结果

**CL-Bench（4 类任务，500 个上下文）**：

| 模型 | 原始 | +Ctx2Skill | 提升 |
|------|------|-----------|------|
| GPT-4.1 | 11.1% | **16.5%** | +5.4% |
| GPT-5.1 | 21.1% | **25.8%** | +4.7% |
| GPT-5.2 | 18.2% | **21.4%** | +3.2% |

**消融实验关键发现**：
- 去掉 Challenger Skill 进化 → 最大降幅（说明对抗压力至关重要）
- 去掉 Cross-Time Replay → 第二大降幅
- **固定选最后一轮 vs Cross-Time Replay 选**：从 Iter-1 到 Iter-5 性能单调下降，Cross-Time 反而超越最好单轮

---

## 🔗 和 EvoMind 的关联

这篇论文跟你的 **EvoMind Skill 体系**有几个极强的共鸣点：

**1. Skill = 自然语言知识模块**
- Ctx2Skill 的 Skill Set 是 Markdown 格式，prepend 到 system prompt
- EvoMind 的 SKILL.md 也是自然语言描述的可复用能力模块
- 底层逻辑完全一致

**2. 自动发现 × 迭代进化**
- Ctx2Skill 通过自对弈自动发现 Skill，无需人工标注
- EvoMind 的 Evolution Engine 也是 Task→Experience→Memory→Skill→Agent 的自动进化链条
- 两者都在解决"如何让 Skill 自动生长"的问题

**3. 消融实验验证了"对抗压力"的重要性**
- Challenger Skill 进化被移除时性能下降最大 → **Skill 需要竞争性环境才能变强**
- 这为 EvoMind 的 Skill Network 设计提供了理论支撑：不能只沉淀，还要有验证和挑战机制

**4. 跨模型迁移**
- 强模型产的 Skill 可以帮弱模型（GPT-5.1 Skill → GPT-4.1，接近持平）
- 弱模型产的 Skill 对强模型也有帮助但不那么显著
- 说明 Skill 作为"能力载体"是可跨模型复用的

**5. 跟你的差距**：Ctx2Skill 的 Skill 是**上下文特定**的（针对一篇文档），EvoMind 的 Skill 是**组织能力通用**的。Ctx2Skill 是单文档级，EvoMind 是组织级。

---

## 💡 对你最有价值的点

| 给你的启示 | 可以怎么用 |
|-----------|-----------|
| Cross-Time Replay 的乘法选优策略 | EvoMind 的 Skill 进化过程中也需要防止"过度适配"，需要类似的全量验证机制 |
| Proposer+Generator 分离设计 | 诊断和生成分开，更可控，你的 Skill 生成流程也可以参考 |
| Challenger 持续制造压力 | Skill 不能只通过"沉淀"变强，需要对手——可以在 EvoMind 里设计 Skill 对战/验证模块 |
| 强模型产 Skill 可迁移到弱模型 | 可以用最强模型为所有客户产初始 Skill Set，大幅降低冷启动成本 |

要不要我把这篇论文的核心机制提炼成一个 **EvoMind Skill 进化机制的参考设计文档**？
