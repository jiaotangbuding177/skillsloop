**今日主线：AI agent 正在从“聊天工具”变成“有电脑、有权限、有流程、有评估体系的数字员工”。**

**1. Agent 要有自己的电脑，不只是 API**

MAD Podcast 这一期采访 Daytona CEO Ivan Burazin，核心观点很硬：如果把 agent 当成“数字知识工作者”，那它就需要自己的电脑，也就是 sandbox。不是简单隔离环境，而是一个可以装工具、访问网页、跑脚本、执行代码的“可组合电脑”。

Ivan 解释了为什么他不给 Claude / OpenClaw 直接登录自己的主机或银行账户：安全边界会崩。更好的方式是给 agent 独立机器、独立账号、独立手机号，甚至独立权限。比如它可以查看银行数据，但不能花钱；可以有一张额度受限的信用卡；出了问题可以 kill 掉整个机器。

他还强调，传统云厂商 AWS / Azure 的基础设施主要为“无状态应用”设计，而 agent sandbox 是“有状态工作环境”：agent 会改文件、装依赖、保留上下文、跑长期任务。这不是把现有 VM 包一层就完事，规模化之后会遇到调度、性能、数据持久化、安全、CPU 供给等问题。

另一个很值得注意的判断：agent 需求可能带来 **CPU 短缺**。过去大家只盯 GPU，但如果每个 agent 都需要一台或多台 sandbox，CPU / RAM / 本地磁盘 IOPS 会成为新的瓶颈。

更关键的一条是他转述 Ryan Carson 的经验：过去做 MVP，大家会说“别花太多时间搭系统，先把最小版本发出去”。但 AI agent 时代反过来了——你必须花时间写文档、搭流程、把它们做进 cron job 和 skill file。这样才可能让 agent 稳定地产出，甚至像 10 个人一样工作。

这其实和刚才 Daytona 的 podcast 是同一件事：agent 不是“问一句答一句”，而是要被嵌入系统。

**3. Garry Tan：skill file + evals 会让 agent 越跑越好**

Garry Tan 的重点是 evals。他建议直接让 agent 用多个前沿模型审查 skill file 的输入输出，并打分：为什么不是 10 分？怎样才能变成 10 分？多跑几次后，效果会快速提升。

**小明的今日判断**

今天这份 digest 的核心不是“又出了什么模型”，而是 **agent 基础设施正在变成一个完整产业栈**：

- 模型只是大脑；
- sandbox 是电脑；
- skill file 是操作手册；
- evals 是绩效考核；
- cron / workflow 是组织流程；

MAD Podcast 这一期采访 Daytona CEO Ivan Burazin，核心观点很硬：如果把 agent 当成“数字知识工作者”，那它就需要自己的电脑，也就是 sandbox。不是简单隔离环境，而是一个可以装工具、访问网页、跑脚本、执行代码的“可组合电脑”。
