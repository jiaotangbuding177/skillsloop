# EvoMind 清理版 · 064

本版按用户要求移除空AI回复和符合短时完全重发条件的用户输入。原始导出及063完整版本保留，清理操作逐条可追溯。

**[打开清理后全部会话](private/index.html)**。目录可筛选仍有顺序冲突、原来有冲突或本轮发生清理的会话。

- 移除空AI正文 **11,775条**，涉及657条会话。
- 合并疑似短时完全重发 **166条**，涉及46条会话。

- 顺序冲突信号在33条会话中消失，未出现新增冲突；原136条标记仍保存在每条会话中，不能把信号消失当作顺序已恢复。
- 19条内部用途会话仍在附表，按相同规则共移除89条记录；39条没有导出消息的元数据保持原样。主统计不混入这两类。

## 重复输入和混乱有什么关系

采用与063相同的顺序诊断规则：原行序与数字编号不一致、原行序用户日期倒退、用户日期与数字编号方向冲突。没有因为用户连续发言就判为混乱。

| 对比处理 | 仍检测到顺序冲突的会话 |
|---|---:|
| 不清理 | 136 |
| 只移除空AI正文 | 104 |
| 再合并符合条件的完全重复输入 | 103 |

因此本轮检测信号的减少主要来自空AI记录的移除；在此基础上，完全重复输入合并又使1条会话不再触发冲突。严格用户时间／编号冲突仍涉及36条会话，未减少。

这不能证明真实卡顿不存在，也不能证明语义相似输入没有影响；本轮没有删除语义相似但措辞不同的输入，没有做因果归因或模型语义排序。当前证据**不支持把多数顺序冲突直接解释为用户短时重复输入导致**。

## 实际采用的规则

### 空AI正文

角色为AI，正文去除首尾空白后为空，即从清理版消息／回合视图移除。没有把短回复、自言自语或失败说明当作“空”。原始记录、状态、来源位置保留在移除审计里。

主集有1条空正文记录携带非空payload；其工具等元信息完整保留在审计文件，不宣称该事件没有任何活动。移除的是对话正文视图，不是抹除历史证据。

### 疑似短时完全重发

同时满足下列条件才合并：

1. 同一会话，用户正文逐字符完全相同，不做语义相似合并或平台前缀剥离。
2. 去除空AI正文后，在原文件保留顺序中连续出现，中间没有非空AI或系统事件。
3. 两条都有已关联的用户时间，与本次保留的首条输入相差0—120秒。120秒是本轮可复现的工作阈值，不是已经证明的卡顿时长。
4. 原始附件元信息相同；不同附件即保留为不同输入。
5. 如果两条都能在同一数字编号体系比较，其编号之间不能夹着非空AI回复；这避免原文件错排时把已回答后的再次输入误合并。

时间缺失、超过窗口、不同附件、不同措辞、中间有回复或数字候选与连续性相矛盾，均保留。窗口始终相对首条保留输入，不按相邻120秒无限串联。编号无法比较时不臆造序号，此项核验可用性写入审计。

以上是“疑似重发”的操作性定义，**没有生产运行日志证明每条均由卡顿造成**。即使符合条件也可能是主动重申；原版和映射允许撤销清理。

## 复现与验收

项目根目录执行 `python research/datasets/evomind/clean_064/build_clean_dataset.py`。依赖既有063数据和其展示／诊断脚本，不访问网络，不调用模型，不修改Demo或原文件。

全量核验：34,283条保留记录和11,941条移除记录组成完整且互不重叠的原始主集；正文与原始记录均与063一致；每个合并目标确实保留；全部1,466会话存在；清理后没有空AI正文；回合视图覆盖保留消息。边界检查覆盖不同措辞、不同附件、有AI回复、编号矛盾、缺时间、超窗及禁止传递式无限合并等10种情况。这是数据处理验证，不是技能效果实验。
