## 三、Skill 候选清单（按 频次 × 广度 × 覆盖缺口 排序）

### P0-1 合同/协议多立场审查 `contract-multi-review`
**证据**：275 条 / 20 用户 / 99 会话，全是手工重复提示词。
用户反复手写的需求模式：
- 立场参数化：乙方/甲方/委托方/接收方/供应商/投资机构/股权出让方/签署人（「帮我站在接收方的角度审核一下这份合同」）
- 风险分级：「逐条审查条款风险，标出高风险/中风险/低风险」
- 产出延伸：修订模式直接改 docx（「修订尽可能少，只改核心重大风险」）、补充协议起草、法律意见函/说明函
**设计要点**：输入=合同文件+我方立场；输出=风险清单（等级/条款引用/修改建议）+ 可选修订版；内置常见合同类型模板（NDA/股权转让/委托加工/聘用/采购）。
**缺口依据**：现有 contract-review ×8、legal-risk-assessment ×3、合同风险审查 ×2，远低于需求。

### P0-2 简历-岗位批量匹配 `resume-job-matcher`
**证据**：490 条 / 20 用户 / 146 会话。固定句式：「请学习这份简历，并结合以下岗位要求…推荐面试」「同样的要求，看看这三位是否值得面试」「简历 3 不适合的原因是」。
**设计要点**：JD 结构化 → 批量解析简历（知识库 PDF 直读）→ 匹配评分+排序+理由 → 面试问题建议；候选人池/JD 池跨会话记忆。变体：岗位定薪咨询、组织架构生成。
**缺口依据**：human-resources-recruitment ×4、job-description-writer ×3。

### P0-3 会议纪要→结构化产出 `meeting-to-actions`
**证据**：128 条直接 + 大量间接；**用户明确要求沿用历史格式**（「请帮我按照以前的格式继续整理」「按照刚才乐语催收会议纪要的格式」）。
变体输出：① 客户会议 → 需求摘要+待确认事项+下一步任务表；② 面试录音 → 面试纪要+评估（一人 3 次面试全走此流程）；③ 融资沟通会纪要；④ 董事会决议格式。
**设计要点**：录音/转写/m4a 附件直读；**首次产出后自动沉淀格式模板**（直接呼应 311 条可复用信号）；行动项/负责人/期限提取。

### P0-4 报告/公文/申报材料 `gov-report-writer`
**证据**：679 条 / 28 用户（覆盖面最广）。
高频形态：行业分析报告、word 报告+嵌入可视化图、GB/T 9704 公文、申报表填报（科委概念验证/临港专家入库/NSFC/技术转移平台申报）、推荐函、PPT↔Word 互转（「根据这个 ppt 生成 word 版口语汇报」「简报整理成可下载 word 和 pdf」）。
**设计要点**：模板库驱动 + 图表嵌入 + docx/pdf 双导出；「修改第 N 页第 X 处」式增量返工是常态，需支持定点修订。

### P1-5 图片型 PPT 精修 `ppt-refine`（现有技能的补位）
**证据**：image-ppt-generation 被调 43 次，但生成后大量返工消息：「第三页还是换成这个图片内容，左上角 logo 去掉」「图 2 的字和图重叠」「原封不动转为可编辑模式」。现有技能只管生成、不管迭代。
**设计要点**：逐页指令式修改、保持全册风格一致、图字重叠检测、图片↔可编辑元素转换。

### P1-6 投资/尽调工具包 `deal-due-diligence`
**证据**：522 条尽调桶 + 436 条调研桶。子模式：TS/term sheet 投资人立场修改、股权结构推演（子公司 vs 主体融资/退出路径）、尽调问题清单（「把投资人关心且没回答好的问题总结一下」）、企业背调（已装 tianyancha/qichacha 类技能但调用少，说明入口分散）。
**设计要点**：把背调+条款审查+问题清单+结构推演合成一条链。

### P1-7 招投标/经营编排套件 `bid-ops-suite`（把个人自建泛化为组织资产）
**证据**：用户 ***9019 已自建整套编排技能并被调用：市场线索标准化移交、项目启动与 WBS、缺料与齐套检查、每日经营简报、测试与发布检查、重点项目健康度。另有手写招标解析提示词：「解析招标文件，输出评分规则表」「需求表与标准产品规格书逐项比对」「三方差异分析」「定制需求拆解为研发任务表和里程碑」。
**设计要点**：把这套已被一人验证的技能泛化，配套模板。

### P2 观察项
- **定时日报/晨报/周报**：AI 论文日报（定时任务已配）、晨报、质量效能周报 → 可做「日报模板」组合技能。
- **多智能体辩论会 / 数字分身 / Brainstorm Monitor**：多用户高频复用的平台原生模式，不是 skill 缺口，但可产品化为一键模板。
- **财务会计问答**（怎么做账/会计分录/做账处理）：零散出现，暂不建技能。

## 四、附带运营洞察

1. **平台注入消息占比可观**：8026 条中约 354 条为 PromptGuard/人设/知识库/图谱注入（已清洗），另有大量消息被平台包装层拉长——分析用户真实意图时必须清洗，否则分桶严重失真（技能桶从 1376 虚高降到 1042）。
2. **用户消息中大量 UUID 原始副本已被 prune 机制清理**，目前 trusted 副本是主要分析载体（带系统前缀，需剥离）。
3. 该组织是 **skill 涌现机制的最佳试点**：用户已自发提出「沉淀为 skill」诉求（311 条可复用信号），P0 四个技能均有真实高频 prompt 可直接作为种子语料。
