# 上一位发言者：张文
先亮结论：**AI 智能体垂直落地的最大结构性障碍，是商业模式的闭环缺失，定级 P0。** 技术成熟度是 P1，组织接受度是 P2。原因如下——

---

**P0：商业模式闭环缺失 —— 签约≠交付，交付≠回款**

我最近在审一份合作协议时，拆出了 4 个 P0 级高风险项，其中 3 个都指向同一个结构性问题：**AI 智能体项目的结算前置条件模糊，导致"交付"的定义权完全在甲方手里。**

具体表现：
- **验收标准不可量化。** 传统软件项目有功能清单可以逐项验收，但智能体的输出质量高度依赖模型能力和 Prompt 工程，甲方很容易以"效果不理想"为由拒绝验收。合同里如果没有明确的 Benchmark 指标和兜底结算比例，乙方就是无限兜底。
- **成本模型不可控。** LLM 调用成本随模型版本、Token ***，但合同往往签的是固定总价或人天计价。一旦甲方要求"效果对齐 GPT-4 水平"但预算按国产模型算，中间的差价就是乙方的利润黑洞。
- **持续迭代责任边界不清。** 模型厂商每季度更新，智能体的行为会随之漂移。合同里没有约定"模型升级导致的输出变化是否属于乙方维护范围"，这个风险就是敞口的。

这三个问题不是技术能解决的，是商业设计层面的结构性缺陷。

---

**P1：技术成熟度 —— 不是不能用，是不能"承诺"用**

从 LLM 选型矩阵来看，当前主流模型在特定垂直场景（比如知识库问答、结构化信息提取）的准确率已经可以做到 85% 以上。但问题在于：**垂直行业客户要的不是 85%，而是"出了错谁负责"。**

我做过一个对比：同一个知识问答场景，用 RAG + 国产开源模型的成本是用闭源 API 的 1/5，但准确率差 8 个百分点。选哪个？取决于合同里 SLA 怎么签。如果甲方要求 99% 准确率兜底，那技术选型就不是工程问题，而是商务谈判问题。

所以技术成熟度是 P1 —— 不是做不到，而是做到什么程度、谁来为剩余差距买单，这个问题没有行业共识。

---

**P2：组织接受度 —— 被高估的障碍**

很多讨论把"客户不愿意用 AI"当核心障碍，但我的经验是反过来的：**一线业务人员对新工具的接受速度远快于管理层的采购决策速度。** 我们做跨企业 PR 日报汇总，覆盖 27+ 代码库，研发团队第二天就开始用了。但这个项目从立项到签约花了三个月，卡在"AI 产出算不算正式工作成果"这个管理认知问题上。

所以组织接受度是 P2 —— 它确实存在，但它会随使用密度自然消解。真正卡死项目的是 P0 的商业闭环问题。

**一、回答你的问题：合同完美但用户不需要的案例，有没有？**

所以我的 P0 框架没有缺前置条件——**它精确描述的是乙方的风险敞口**。你说的"用户根本不需要"是甲方的 P0，不是乙方的 P0。我们讨论的是同一个现象的不同切面，不是谁对谁错。

但你用产品制路径切入时，**你同时是甲方和乙方**——你自己承担"用户不需要"的风险，也自己承担"数据合规"的风险。这就引出了我要说的重点。

**二、数据合规：你的路径有一个 P0 级盲区**

你说"宁可功能少也不能越过数据合规边界"——我同意这个原则。但我要追问：**你有没有具体拆过，"教师真实痕迹提炼并署名"这条路径，数据合规边界到底在哪？**

我按风险分级拆一下：

**P0：教师行为数据的授权链路不清晰。**

"教师真实痕迹"——具体是什么数据？教案修改记录？课堂互动日志？带教评语？这些数据的生产者是教师本人，但管理权在学校。你从教导处拿预算进场，但教师的数据授权你找谁签？

- 如果让教师个人签：教育体系内，教师对"平台采集我的工作数据"这件事的敏感度极高，尤其在职称评审、绩效考核的背景下。授权率可能远低于你的预期。
- 如果让学校统一签：那就回到了你试图避开的"校长大采购"路径，而且多了一层法律风险——学校是否有权代替教师授权个人工作数据的外部采集？

**P1：数据一旦沉淀为"平台资产"，归属权不可逆。**

你说"内容从教师痕迹中提炼并署名，建立不可复制性"。这个策略在产品层面成立，但在法律层面有一个致命问题：**一旦教师离职或学校更换供应商，这些沉淀内容的归属权归谁？**

如果没有合同前置约定，按照现行法律倾向，数据主体（教师）有权要求删除。你的"不可复制的资产壁垒"可能在一次劳动纠纷后被迫清零。

**P2：教育行业的数据监管正在收紧。**

2024 年以来，多个省市教育厅已经出台针对"校园 AI 应用"的数据安全指引，要求 AI 产品不得采集师生行为数据用于商业目的。你的"师徒互动频率""提问路径偏好"这些数据，在部分辖区可能已经踩线。

---

**三、护城河：直接回应"模型可以换，关系换不了"**

这句话听起来有力，但我要拆它：

**关系网络作为护城河，有一个结构性弱点——它不可迁移，但可复制。**

你在一所学校建立了师徒关系网络，竞争对手进不来吗？如果竞品以同样的"带教工具"切入同一所学校的另一个教研组，你的关系网络不构成排他壁垒。它不是专利，不是独家数据，它是**使用习惯**——而使用习惯在教育行业被证明是脆弱的（教师轮岗、教研组长更换都会导致关系链断裂）。

反观我倾向的护城河路径——**合同条款锁定的知识资产体系化**：

- 合同有排他期，有数据使用授权范围，有切换成本
- 知识资产一旦结构化沉淀（比如行业 LLM 选型矩阵、合同风险分级模板），具有跨客户复用性
- 切换成本是合同层面的，不是习惯层面的

**一句话：你的护城河是"用户懒得换"，我的护城河是"合同不让换"。哪个更抗冲击，取决于你多快能形成规模效应。**

---

**四、路径边界条件：小而锐的天花板在哪？**

**核心问题 2：路径选择与边界**

- 小而锐是有效启动策略，但规模化面临"预算断层"（教导处小预算→学校级大采购）

**核心问题 3：数据合规与 IP 归属**

### 已讨论观点

**核心问题 1：最大结构性障碍**

- 张文（项目制视角）：P0 = 商业闭环缺失（验收不可量化、成本不可控、迭代边界不清）；P1 = 技术成熟度；P2 = 组织接受度
- 佳慧（产品制视角）：张文的 P0 隐含"项目制"前提。产品制的 P0 = 场景不可替代性是否真实存在
- 修正共识："用户不需要"是甲乙双方的共同 P0，项目制延迟发作（没有下一单），产品制即时发作（没有留存）

**核心问题 2：路径选择与边界**

- 小而锐是有效启动策略，但规模化面临"预算断层"（教导处小预算→学校级大采购）
- 佳慧提出替代规模化路径：横向网络效应驱动自下而上扩散（教师轮岗带走习惯→触发新校需求→多校小预算汇聚），但承认周期 18-24 个月
- 关键判断：产品制路径在规模化阶段可能不得不重新面对项目制规则

**核心问题 3：数据合规与 IP 归属**

- 张文攻击：教师行为数据授权链路不清（P0）、内容归属权不可逆（P1）、教育监管收紧（P2）
- 佳慧纠正前提：做的是"内容沉淀与署名分发工具"（类教师版小红书），合规模型是"用户协议+内容许可"而非"数据处理协议"
- 双方达成一致：内容归属权必须在 MVP 阶段通过用户协议前置约定

**核心问题 5：护城河**

- 张文："合同不让换"——切换成本锁定在合同层面，知识资产可跨客户复用
- 佳慧（修正版）："关系网络嵌入山头文化"——教研组长是节点人物，拿下一个山头即锁定一批用户，具有组织社会学层面的排他性
- 各自脆弱点：合同锁定被教师轮岗瓦解；关系网络受教研组长更换/轮岗冲击

**概念升级：双类型分类框架**

| 维度 | 效率工具型 | 关系载体型 |
|------|-----------|-----------|
| 价值来源 | 自动化已有流程 | 创造新连接模式 |
| 验收逻辑 | 可量化 ROI | 行为密度/网络密度 |
| 合规模型 | 数据处理协议 | 内容发布协议 |
| 护城河 | 合同锁定+切换成本 | 网络效应+组织嵌入 |
| 规模化路径 | 大单驱动 | 网络扩散 |
