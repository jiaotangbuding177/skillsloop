## 怎么标注

1. 左侧选会话，可按编号、来源标题搜索，也可筛选“AI归属不明”“仅用户暂无AI”或未完成会话。
2. 中间选待核验项。右侧上方显示待核对的完整原文，下方显示潜在匹配及推荐依据。
3. **勾选一条或多条**对应内容。可以展开全文、原消息编号和位置；候选不够时，点“查看本会话全部候选”，或直接搜索正文。
4. 当前可见会话中没有对应内容，选**无匹配**；拿不准，选**暂不能判断**。后者仍保留在待核验范围。
5. 点击**确认此项**或**确认并下一项**。勾选本身只是草稿，不会提前算作人工确认。可备注，也可撤销。
6. 每完成一批，点顶部**导出标注备份**，保存JSON文件。之后可以导入继续，也可以把备份路径给助手，用于后续数据整理。

若需要检查已有机器匹配，可切换“本会话全部用户与AI”，或者打开“本会话全部对话”后点击“标注这条”。机器已有对应也会显示，便于发现候选与上下文冲突。

## 保存在哪里

- 正常情况下，草稿和确认结果会自动保存在**当前浏览器、当前页面**的本地存储中。关闭后用同一浏览器和同一路径重新打开即可读取；文件网页的存储行为取决于浏览器，因此**导出的JSON备份是可搬移的保存结果**。
- 页面顶栏显示保存状态；若保存不可用或空间不足，会明确提示导出，不能只依赖页面里的进度。
- 读取旧保存失败时，不会自动覆盖旧数据。请导出本次工作。
- 导入会检查来源数据指纹、会话与消息编号；若与已有人工判断冲突，整次合并被拒绝，不静默覆盖。
- 页面不直接改写066原数据。导出文件中保留人工判断、草稿及修改记录，方便之后单独审计或生成新版本。

## 匹配与标注边界

潜在匹配首先复用066已有候选；用户侧反向展示哪些AI曾把它列为候选。数量不足时补充原位置邻近内容，并明确注明弱依据。仍可查找同会话全部另一侧正文，没有再次调用模型，也没有自动替用户勾选。

一条用户输入可以对应多条AI，同一AI正文也可以对应多条用户输入。两侧都有人工标注时会检查一致性，出现冲突须先撤销或修改对侧。机器候选不会冒充人工标注。

标注对象是去重后的正文组，所有出现位置可展开。这次确认的是“这段正文对应谁”，不能自动推导为“每次重复出现都发生在同一时间点”；也不证明答案正确、任务成功或资料完整。“无匹配”限定在当前可见会话范围。

“待核验项全部确认”只表示原来的这些疑难项均被明确标为匹配或无匹配；不等于全会话每条机器关系都已经人工核验。
