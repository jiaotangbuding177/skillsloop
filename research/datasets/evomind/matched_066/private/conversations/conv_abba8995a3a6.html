## 核心结论

搜狗 ssf 皮肤格式**不支持运行时代码**，所以不能靠皮肤包自身实现"打字→匹配关键词→换肤"的闭环。必须搞一个外部运行时代理来桥接。

我整理了 **6 条技术路线**，按推荐优先级：

| 优先级 | 路线 | 一句话 |
|--------|------|--------|
| 🥇 | **Web Demo** | 1-2天出活，单 HTML 文件模拟全流程，用来做传播和用户验证 |
| 🥈 | **Android 伴侣 App** | 无障碍服务监听输入 + 浮动层叠加动效，真正可用的产品 |
| 🥉 | **官方合作** | 给 `***@***` 发邮件，推动搜狗开放皮肤 API |
| 4 | **PC 端外挂** | Windows 键盘钩子 + 替换 ssf 文件，PC 版补充 |
| 5 | **独立输入法** | 自己造轮子，不推荐（获客成本太高） |
| 6 | **Xposed 魔改** | 需要 Root，仅 Geek 玩家场景 |

## 建议的节奏

1. **本周**：先撸 Web Demo（2天），验证概念+录视频发小红书
2. **同时**：给搜狗官方发合作邮件，不要等
3. **Web Demo 验证通过后**：启动 Android 伴侣 App 开发

Web Demo 我建议用纯单文件 HTML（不依赖框架），500行以内搞定虚拟键盘 + AC 自动机关键词匹配 + CSS 氛围切换 + Lottie 动效。快速出活、快速传播。

## Brainstorming 结果总结

按 `brainstorm-ideas-new` 方法论，从 PM / 设计师 / 工程师三个视角各出了 **5 个方案**，一共 15 个，然后加权打分排出优先级。

### 🏆 Top 5 结论

| 排名 | 方案 | 为什么 |
|------|------|--------|
| 🥇 | **AC自动机匹配引擎 + Canvas程序化动效** | 产品心脏，没这个就不存在 |
| 🥈 | **按键微交互 + 氛围过渡引擎** | 从"能用"到"wow"的关键，传播素材来源 |
| 🥉 | **零权限隐私架构** | 输入监听产品的准入门槛，不做好没人敢用 |
| 4 | **关键词自定义工坊** | Z世代圈层文化差异大，个性化决定留存 |
| 5 | **氛围分享卡片** | 获客引擎，一张图=免费广告位 |

### 几个关键决策

- **匹配用 AC 自动机不用正则** → 性能差 100 倍
- **动效用 Canvas 生成不用 Lottie** → 体积从 3MB 降到 50KB
- **浮动层叠加方案优于文件替换** → 不依赖 root
- **先做 Web Demo 再做 App** → 1/10 时间同等验证
- **Day 1 就设计零网络权限** → 隐私不是后装的补丁
