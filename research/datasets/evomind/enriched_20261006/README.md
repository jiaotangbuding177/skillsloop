## 三种用途的数据要分清

| 文件 | 用途 | 是否含研究标注 |
| --- | --- | --- |
| [source_inputs.jsonl](private/source_inputs.jsonl) | 后续任务识别、轨迹恢复的原文输入视图；全1,466会话，不只保留池 | 不含筛选任务、学习点、主题结论或071对应标签；未验收与Demo的直接适配 |
| [enriched_sessions.jsonl](private/enriched_sessions.jsonl) | 完整研究资料：原文、来源、对应依据、筛选、文件与执行线索 | 有；不能整包作为需要预测这些标签的模型输入 |
| [candidate_contexts_union.jsonl](private/candidate_contexts_union.jsonl) | 已筛选学习锚点及可回查上下文，供恢复与归纳研究 | 有；候选不是黄金轨迹，也不是已验证skill |

候选池另存[原711候选](private/candidate_contexts.jsonl)和[本轮补漏候选](private/candidate_contexts_supplement.jsonl)，保留旧判断与新建议。扩窗仅继承显式接受的内容对应，不把相似主题或工具同会话视为同一任务。新增正文成员的来源、种子身份和对应依据均可回查。

原文输入视图已经应用本轮固定清理与完全同文合并，各比较方法应使用相同版本。若研究算法自身识别重复/噪声的能力，需从完整审计资料导出共同的未清理输入，并移除研究标注；不能只给我方清理后的材料。

## 有哪些实际信息

1. 现有066的用户与AI消息组全文、每组的原始出现位置和次数；已知空AI、重试和其他事件另归历史审计，不进入学习正文。
2. 已确认移出的144条纯进度/控制回复继续标明原因；57条受保护短回复保持。清理后完全相同的同角色正文以别名合并展示，所有原组和出现位置继续保留。
3. 071显式对应与066自动候选分开。071标签中包含人工、AI和程序来源；“已完成标注流程”不等于所有关系都是人工黄金真值。没有对应不自动等于没有真实回复。
4. [3,578条工具记录](private/tools.jsonl)：保留实际参数、返回和来源定位；快照并不代表所有历史调用。只有消息定位可追溯时才关联到消息，其他仅属会话级证据。
5. [1,767条文件元数据引用](private/file_references.jsonl)：文件名、路径等已有信息。本轮未找回真实文件字节，没有把占位符变成真实文件。
6. 已有技能审计的分级线索，明确成功读取、执行、管理动作、未确认或失败等类别。记录数和覆盖会话数不能直接称为实际有效消费数量。

规范化正文只清理已知平台包装及明显凭据，不能认证完全脱敏；受控原始数据仍保存。原始标题仅是元数据，不能作为任务或正确配对的真值。

## 离线重建

在项目根目录执行：

```powershell
python -X utf8 research/datasets/evomind/enriched_20261006/build_enriched.py
python -X utf8 research/datasets/evomind/enriched_20261006/build_partition_hints.py
python -X utf8 research/datasets/evomind/enriched_20261006/verify_release.py
```

重建使用冻结来源、旧筛选和本轮固定补漏标注，不重新让模型决策，不调用企业服务，不执行历史工具命令。来源变更应另建版本，不能在正式评测中临时覆盖输入。上述工具只做研究数据处理，不修改Demo或启动技能生成与模型训练。
