## 🎯 方案核心设计

### 绩效结构
```
总分 (100 分) = 量化 KPI(70 分) + 行为评级 (30 分)
```

### 三序列 KPI 对比

| 序列 | 核心指标 | 权重最高项 |
|------|----------|------------|
| **研发** | 交付率、缺陷率、准时率、文档 | 需求交付完成率 (25 分) |
| **产品** | 上线率、NPS、转化率、文档 | 产品功能上线率 (25 分) |
| **销售** | 销售额、新客数、续费率、漏斗 | 季度销售额达成率 (35 分) |

### 行为评级三维度
- **研发**：技术能力、协作沟通、学习成长
- **产品**：用户洞察、跨部门协作、数据驱动
- **销售**：客户关系、专业能力、团队协作



```bash

□ 记录关键事件（正向/负向）

```

### 第 13 周：考核评估
```bash
□ 员工自评（第 1 周）
□ 上级评分 + 同事互评（第 2 周）
□ 绩效面谈（第 3 周）
□ 结果确认 + 申诉（第 4 周）
```

## 🔴 关键问题

### 1. 上级权重 60% 过高
```
当前：自评 20% + 上级 60% + 同事 20%
问题：本质仍是"上级考核"，不是真正的 360 度
建议：上级降至 45-50%，同事提至 35-40%
```

### 2. 缺少两个重要评价源
- **下级评价**：对 Team Lead/经理（20 人公司约有 3-5 人有下级）
- **客户评价**：对销售/产品岗位（直接影响业务）

### 3. 匿名机制缺失
同事互评如果不匿名，容易导致：
- 人情分（互相打高分）
- 不敢说真话
- 评价流于形式

### 4. 没有反馈报告
360 度的核心价值是**认知差距分析**（自评 vs 他评），当前方案缺少：
- 多源得分对比
- 盲区识别（自评高、他评低）
- 潜能识别（自评低、他评高）
