## 📄 PRD-云知师AI课堂分析MVP一期

保存在当前会话目录，按 8 节标准 PRD 模板撰写：

| 章节 | 核心内容 |
|:---|:---|
| **1. 概述** | 一句话定位："让普通教室变成AI录播+自动评课的智能教室" |
| **2. 联系人** | PM / Tech Lead / 校方 / AI负责人 |
| **3. 背景** | 教研资源稀缺、反馈周期长、评价不统一、数据无法沉淀。三个成熟条件：大模型能力→边缘算力平价→政策窗口 |
| **4. 目标（OKR）** | O1 链路跑通（1校1教室4周，30节+），O2 教师愿意用（周活≥3次，满意度≥4.0），O3 技术可行（P95≤5min，可用性≥99%） |
| **5. 用户与场景** | 两位核心用户（授课教师→教研组长）；两个场景（日常自动评课 + 教研数据驱动）；完整用户旅程 |
| **6. 价值主张** | 对比表：传统 vs 云知师 MVP（覆盖率/时效性/维度/数据/成本）。核心差异化：不卷"录音转文字"，直接给"分析结论" |
| **7. 解决方案** | 架构图（教室→边缘→云端）；**21个P0功能**分四模块（采集上传6项 / AI分析5项 / 报告查询7项 / 用户基础3项）；报告内容结构Mockup；技术选型表（单一DeepSeek、Whisper ASR、Python+PostgreSQL）；5个关键假设+验证+兜底方案；8项明确不做的范围 |
| **8. 发布计划** | 12周时间线（4阶段：技术准备→开发→联调→试点运行）；交付物清单；二期预览 |

---

几个关键决策说明一下思路：

1. **一期只用 DeepSeek**，不上多模型协同——先把一条路走通，验证"AI评课质量教师能接受"这个最核心的假设
2. **只做音频不做视频**——视频增加部署成本、网络带宽、隐私风险，音频数据已经足够支撑四个分析维度
3. **不做移动端**——试点只1间教室2-3个教师，PC端完全够用，二期再考虑H5
4. **目标设得比较保守**（≥90%成功率，不是95%）——MVP阶段容错空间要给足，关键是验证价值而不是打磨指标
