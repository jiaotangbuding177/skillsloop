## 三、核心模块分析

### 1️⃣ **prepare-digest.js**（165 行）

**职责**：数据聚合与准备

```javascript
// 核心流程
1. 读取用户配置 ~/.follow-builders/config.json
2. 并行获取 3 个 Feed:
   - feed-x.json (X/Twitter 帖子)
   - feed-podcasts.json (播客转录)
   - feed-blogs.json (博客文章)
3. 加载 Prompt 文件（优先级：用户自定义 > GitHub 远程 > 本地默认）
4. 输出统一 JSON 结构给 LLM
```

**关键设计**：
- ✅ **零 API Key**：所有内容从中心化 Feed 获取
- ✅ **三层 Prompt 优先级**：支持用户自定义摘要风格
- ✅ **错误容错**：非致命错误不影响内容输出

---

### 2️⃣ **deliver.js**（217 行）

**职责**：多通道投递

| 投递方式 | 配置要求 | 实现方式 |
|---------|---------|---------|
| **Telegram** | BOT_TOKEN + chatId | Telegram Bot API |
| **Email** | RESEND_API_KEY + email | Resend API |
| **stdout** | 无 | 直接输出（OpenClaw 处理） |

**关键特性**：
- ✅ **消息分块**：Telegram 4096 字符限制自动分块
- ✅ **Markdown 容错**：解析失败自动降级为纯文本
- ✅ **速率限制处理**：分块间 500ms 延迟

---

### 3️⃣ **SKILL.md**（466 行）

**职责**：AI Agent 行为定义

**核心工作流**：

```
首次运行 → Onboarding（8 步）
  ├─ Step 1: 介绍
  ├─ Step 2: 推送频率设置
  ├─ Step 3: 投递方式（OpenClaw 跳过）
  ├─ Step 4: 语言偏好
  ├─ Step 5: API Key 配置（仅投递需要）
  ├─ Step 6: 展示信息源
  ├─ Step 7: 配置说明
  ├─ Step 8: Cron 定时任务设置
  └─ Step 9: 欢迎摘要（立即生成）

定时运行 → Content Delivery（6 步）
  ├─ Step 1: 加载配置
  ├─ Step 2: 运行 prepare-digest.js
  ├─ Step 3: 检查内容
  ├─ Step 4: LLM 重组内容
  ├─ Step 5: 应用语言
  └─ Step 6: 投递
```
