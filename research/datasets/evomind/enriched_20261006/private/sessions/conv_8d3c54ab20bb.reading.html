## 三、核心模块分析

### 1️⃣ **prepare-digest.js**（165 行）

**职责**：数据聚合与准备

```javascript
// 核心流程
1. 读取用户配置 ~/.follow-builders/config.json
2. 并行获取 3 个 Feed:
   - feed-x.json (X/Twitter 帖子)
   - feed-podcasts.json (播客转录)
   - feed-blogs.json (博客文章)
3. 加载 Prompt 文件（优先级：用户自定义 > GitHub 远程 > 本地默认）
4. 输出统一 JSON 结构给 LLM
```

**关键设计**：
- ✅ **零 API Key**：所有内容从中心化 Feed 获取
- ✅ **三层 Prompt 优先级**：支持用户自定义摘要风格
- ✅ **错误容错**：非致命错误不影响内容输出

---

### 2️⃣ **deliver.js**（217 行）

**职责**：多通道投递

| 投递方式 | 配置要求 | 实现方式 |
|---------|---------|---------|
| **Telegram** | BOT_TOKEN + chatId | Telegram Bot API |
| **Email** | RESEND_API_KEY + email | Resend API |
| **stdout** | 无 | 直接输出（OpenClaw 处理） |

**关键特性**：
- ✅ **消息分块**：Telegram 4096 字符限制自动分块
- ✅ **Markdown 容错**：解析失败自动降级为纯文本
- ✅ **速率限制处理**：分块间 500ms 延迟

**核心工作流**：
