# 后续分集所需的来源分组

本轮离线处理已生成 1,466 条会话的来源分组线索，**没有随机划分正式训练集或测试集**。所有会话已经用于项目探索或筛选，不能只换一个文件夹便宣称成为未接触的盲测数据。

## 实际盘点

- 34 个原始账户标识。账户来源于已有导出，不是按语言风格或 IP 推测。
- 32 组完全相同的规范化用户输入序列，涉及 118 条会话；全量共有 1,380 种规范化输入序列。
- 其中 8 组跨账户出现。仅按账户切分仍可能把相同输入放到学习和测试两边。

这里比较的是清除已知平台包装、合并空白之后的**全部用户消息组序列**，保留文字和重复次数。序列使用导出中的组展示次序，不认证实际时间。输入一样，不代表附件、AI回复、真实任务或业务结果一样；本轮没有因此合并或删除会话。不同写法的近重复、共用附件和同一任务模板也尚未全部识别。

## 文件

- [逐会话来源分组](private/session_families.jsonl)：稳定会话、账户、完整输入指纹；分集状态统一为尚未分配。
- [完全相同输入组](private/identical_input_groups.json)：32组及成员编号，供后续核查。
- [账户分组](private/owner_groups.json)：按已有账户归组。
- [统计与来源冻结](summary.json)。

## 怎样使用

1. 同一原会话、从中选出的片段及后续生成的所有变体，始终跟随同一个来源家族，不能拆到学习和最终测试两边。
2. 构造交错会话若混入 A、B 两个来源，则它同时继承 A、B；先分来源再构造，禁止跨分集合成。
3. 完全相同输入组先核对附件与任务身份。相同任务实例或同一资料副本必须同侧；只是通用措辞相同则记录判断依据，不自动声称泄漏成立。
4. 跨用户复用另外按账户隔离，并检查这 8 组跨账户输入及尚未识别的近重复。
5. 时间留出需要可用日期及信息可见截止点；不能根据人工整理后的展示顺序猜时间。已参与研究的数据优先用于开发或诊断，正式未见消费评测另留新任务。

这是分集准备信息，不是任务家族黄金标注，也不能单独保证无泄漏。重建命令：在项目根目录执行 `python -X utf8 research/datasets/evomind/enriched_20261006/build_partition_hints.py`，不会调用模型或修改原数据。
