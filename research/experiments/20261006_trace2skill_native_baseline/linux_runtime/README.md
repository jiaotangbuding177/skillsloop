# Linux后续环境准备

此目录目前是准备方案，**尚未构建或验收**。本机Docker Desktop只做了一次隐藏启动，两分钟内没有取得daemon版本；不能把该Dockerfile当作已就绪运行环境。

目标是将项目挂载到容器 `/workspace`，使用作者原Bash工具及原LibreOffice重算脚本，保留作者核心，不继续修改失败的Windows宏组合。

放行步骤：

1. 确认Linux服务可用，保存系统、Docker、Python、LibreOffice版本、基础镜像digest、完整包版本和最终镜像ID。Dockerfile包含浮动镜像标签及部分未固定包，必须在实际解析后冻结，不能现在声称字节级环境可复现。
2. 挂载本项目，确认原git commit及源码哈希一致；实际读取检查器，核非空目标技能正文和原系统注入结果。
3. 不使用模型，运行原重算脚本的两构造样例：正常工资公式必须产生真实缓存，除零公式必须产生错误缓存并被报告；评分器正／反例、Bash Python依赖也必须通过。
4. 将真实控制证据写成运行环境文件。`native_runner.py`公式任务入口要求该文件声明通过、实际缓存非空及证明报告哈希一致；缺失时会在模型前退出。
5. 新建不可覆盖的运行目录，保存实际编排源码副本、输入、配置、原仓库哈希、完整请求及响应，再运行公开原生校准；后续两道独立工资题分别加载初始／演化技能。不能在同一运行中临时改脚本或提示。

凭据只传进程环境。Docker容器用完移除，凭据不写入镜像、Dockerfile或报告。每次运行必须重新通过免费环境控制；宏配置需要在同一实际执行环境中可用，不能只引用另一台机器的“通过”。

本环境方案不解决原Creation初稿、论文版本映射或服务模型模式未知。也不保证Linux一定修复：必须以原脚本实际缓存、原评分和模型任务结果来验收。
