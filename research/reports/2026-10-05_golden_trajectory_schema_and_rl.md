# 黄金轨迹：数据结构、判定条件与不完整经历的恢复学习

日期：2026-10-05。状态：本项目拟采用的形式化定义与训练方案；不是已实现的认证器、已运行的强化学习或学界统一定义。承接[人话定义](../memory/2026-10-05_golden_trajectory_plain_definition.md)及[已有训练方案](2026-10-04_trajectory_model_sft_and_rl_plan.md)。

## 1．定义必须同时给出数据对象和判定方法

**黄金轨迹是：相对于预先声明的学习范围和核验协议，能够完整支持该范围内必答学习问题、且不把失败／自述／未知误当成成功操作的、经过核验的任务经验图。**

这里有三个不同对象：

1. 原始经历X：实际收到了什么材料。
2. 恢复记录T：算法怎样组织和解释这些材料。
3. 黄金资格Gold(T;Ω,P)：相对于学习范围Ω和核验协议P，这份记录是否足以用于指定的经验学习。

产生JSON、通过格式检查、任务最终得1分，均不能代替第三项。黄金也不要求历史里的Agent处处正确；它要求我们对历史的解释及允许学习的结论有充分依据。

## 2．输入X=(E,C,V)

\[
X=(E,C,V),\qquad E=(e_1,\ldots,e_n).
\]

| 输入 | 必要内容 | 说明 |
|---|---|---|
| E事件 | 编号、原顺序／时间、会话、行动方、类型、正文／参数／返回、调用关联、来源 | 用户、助手、工具、产物均为观察；“已经完成”只先算一条观察到的声明。 |
| C上下文 | 内容、有效版本、适用对象／时间、来源、可使用权限 | 公开工具、政策、可访问附件；不能拿当前政策无依据地解释旧版本执行。 |
| V评价 | 对象、标准、范围、结果、证据和核验方法 | 总任务得分与针对具体字段／动作的检查分开。 |

事件顺序只是可见顺序，不自动推出因果。缺失时间、附件、回执或配对信息都显式保留。

## 3．恢复输出：带证据的任务经验图

\[
\mathcal T=(g,\mathcal N,\mathcal R,\mathcal J,\mathcal L,\mathcal U).
\]

| 符号 | 数据内容 |
|---|---|
| g | 任务目标、对象、要求及生效版本。多任务材料输出一组T，共享来源可引用，不伪造共同执行历史。 |
| N | 实际局部动作、可见产物、声明、计划及条件事实等节点。 |
| R | 任务归属、输入依赖、调用—返回、要求替代、反馈目标、重试／修订等有类型关系。 |
| J | 对指定节点、属性和版本的检查记录。 |
| L | 拟交给聚合器的经验：可参考做法、失败边界、已验证修订、待验证建议。 |
| U | 未知、冲突、缺失来源及未决关系，并指出阻塞哪些学习问题。 |

每个局部动作／产物节点的核心表示是：

\[
n_i=(id_i,\tau_i,\rho_i,k_i,o_i,P_i,x_i,a_i,y_i,Q_i,\sigma_i).
\]

- τ：属于哪次尝试、哪个要求版本。
- ρ：行动方；k：实际动作、可见文本产物、计划或完成自述。
- o：操作对象；P：前置条件；x：实际输入；a：实际动作。
- y：实际输出／回执；Q：已观察到的后置事实，不是模型期望发生的效果。
- σ：来源引用及身份：原始观察、依据推导、后来补取的证据、新实验、假设。

前后条件均以“对象、属性、值、时间／版本、来源、依据类型”表示。缺失值用null并记录缺口。公开规则给出的是规范要求；原轨迹里出现的是当时观察，二者不能混成必然规律。模型拟合的隐藏环境状态不能直接写进已观察事实。

关系也带来源，例如：

\[
r=(\text{from},\text{to},\text{type},\text{evidence},\text{verification}).
\]

局部动作依赖子图应满足合法执行先后，但不要求把目标修改等全部语义关系硬压成一条线。不同尝试的同类步骤仍是不同节点，不能拼成历史上不存在的成功路径。

## 4．局部对错落实到“动作×检查标准”，不存一个万能success

每项检查为：

\[
j=(\text{target},\text{criterion},\text{scope},\text{version},
\mathcal E^+,\mathcal E^-,\text{verifier},\text{verdict}).
\]

只有来源可定位、对象／时间一致、标准确实覆盖该属性、且核验协议接受的证据才计入E+／E−。协议不接受的模型推测另存候选，不通过“有引用”自动成为支持。

\[
\operatorname{verdict}(j)=
\begin{cases}
\text{SUPPORTED} & \mathcal E^+\ne\varnothing,\ \mathcal E^-=\varnothing,\\
\text{REFUTED} & \mathcal E^+=\varnothing,\ \mathcal E^-\ne\varnothing,\\
\text{CONFLICT} & \mathcal E^+\ne\varnothing,\ \mathcal E^-\ne\varnothing,\\
\text{UNKNOWN} & \mathcal E^+=\varnothing,\ \mathcal E^-=\varnothing.
\end{cases}
\]

这是一种保守的证据状态规则，不是逻辑完备的真值判定器。检查不适用时另记NOT_APPLICABLE，不能用它冒充通过。

“调用正常返回”“满足最低价要求”“数据库写入正确”是三个不同标准，分别判断。总任务／总尝试分数保留在对应层；不能复制给每个局部节点。原任务失败也不能直接奖励删除全部方法。

经验条目记录为：

\[
\ell=(\text{applicability},\text{instruction},\text{kind},
\text{supportingNodes},\text{supportingChecks},\text{limits}).
\]

kind至少区分：观察过的方法、有依据的失败边界、核验过的修订、待验证假设。一次成功支持“在该条件下观察到该结果”，不自动证明任意同类条件都有效；推广是后续聚合与新实例评估的另一个问题。

## 5．黄金资格的严格判定

先声明范围：

\[
\Omega=(\text{task/subgoal},\text{object/version},\mathcal Q_\Omega).
\]

QΩ是独立于恢复器输出、事先固定的必答学习问题。例如“目标订单是什么”“修改前状态是什么”“执行了哪个操作”“操作结果是否支持修改成功”。问题可以有负面答案，但不能在模型答不出来后删除该题来获得资格。

协议P规定什么证据足以回答问题：日志精确关联、公开规范、产物检查、环境验证、独立人工核验等。模型自评或另一模型附和，不自动满足协议。

定义：

\[
\boxed{
\operatorname{Gold}_{P}(\mathcal T;\Omega)
=\mathbf1[H\land A\land D\land B\land W]
}
\]

| 条件 | 明确检查内容 |
|---|---|
| H：历史忠实 | 该范围所有作为事实使用的动作、结果和条件均有合格来源或核验推导；新增试验没有冒充旧执行。 |
| A：关联核准 | 支持该范围的任务、对象、要求版本、尝试、反馈及评价关联均通过P核验；关键归属不靠未决猜测。 |
| D：依赖闭合 | 必答问题所需的输入、前后条件、相关反证与修订都在记录内或可访问引用内；所需未知不能被删除。 |
| B：必答问题覆盖 | 每个q∈QΩ都有P接受的确定答案及依据；关键问题UNKNOWN／未解决CONFLICT使该范围不通过。 |
| W：学习用途忠实 | 每项输出经验不超核验范围；失败不当推荐成功，自述不当动作，新组合不当旧成功路径，假设不当规律。 |

其中：

\[
B=\bigwedge_{q\in\mathcal Q_\Omega}
\mathbf1[\operatorname{Verify}_P(q,\operatorname{answer}_{\mathcal T}(q),X)=\text{PASS}].
\]

Verify可以确认“本次没有完成修改”这样的负面答案；要求的是答案正确有据，不要求业务成功。

所有条件是相对于P的操作性认证；核验者也可能出错，必须报告核验协议、覆盖及一致性，不宣称数学意义的绝对正确。未知可在非关键区域存在；若未知正是本次拟学习结论的前提，就不能把这个结论认证为黄金。

局部范围可提前按子目标制定，例如“识别用户”“定位订单”“修改地址”；某局部通过不改变整任务未通过。报告必须同时给原任务数量、局部覆盖和未认证部分，防止只挑容易片段制造高黄金率。空输出或全UNKNOWN不能覆盖这些必答问题。

## 6．一个字段具体怎样记录

下面是构造示例，JSON采用中文键便于阅读，并非现有API的逐字schema。假设可见材料为：e1用户请求，e2真实查询调用，e3对应查询返回状态shipped，e4真实修改调用，e5对应返回明确拒绝，e6助手说已改好，e7用户感谢；c1是当时工具的公开状态规则。

```json
{
  "任务": {"目标": "修改订单地址", "对象": "订单A", "要求版本": 1},
  "学习范围": "解释本次修改被拒绝的状态边界",
  "局部节点": [
    {
      "编号": "n1", "类型": "实际动作", "行动方": "assistant",
      "操作": "查询订单", "输入": {"订单": "订单A"},
      "输出": {"状态": "shipped"}, "来源": ["e2", "e3"],
      "证据身份": "原始观察"
    },
    {
      "编号": "n2", "类型": "实际动作", "行动方": "assistant",
      "操作": "修改地址", "输入": {"订单": "订单A", "新地址": "用户给定地址"},
      "前置条件": [{"谓词": "订单状态为pending", "依据": "公开规则", "来源": ["c1"]}],
      "输出": {"结果": "拒绝", "理由": "状态不允许"},
      "来源": ["e4", "e5"], "证据身份": "原始观察"
    },
    {"编号": "n3", "类型": "完成自述", "内容": "已经修改", "来源": ["e6"]}
  ],
  "关系": [
    {"起点": "n1", "终点": "n2", "类型": "同一目标对象", "来源": ["e2", "e4"]},
    {"起点": "n3", "终点": "n2", "类型": "声明该操作完成", "来源": ["e6"]}
  ],
  "检查": [
    {"对象": "n2", "标准": "调用满足pending状态前提", "结论": "REFUTED", "反证": ["e3", "c1"]},
    {"对象": "n2", "标准": "本次修改获接口接受", "结论": "REFUTED", "反证": ["e5"]}
  ],
  "经验": [
    {"类型": "失败边界", "内容": "按当时规则确认允许的订单状态，再使用该修改接口", "依据": ["c1", "e3", "e5"]}
  ],
  "未知": ["其他接口是否支持该状态下修改"],
  "认证": {"范围": "本次接口拒绝的状态边界", "状态": "待独立核验"}
}
```

不能凭调用先后额外断言n2使用了n1的某个输出作为参数；只有来源支持数据依赖时才添加该关系。示例有明确原政策才能把拒绝与状态条件归纳成规范边界；没有c1时先保留本次回执观察，不能任意推广成全域规则。

## 7．缺失轨迹怎样变成黄金：先判断缺失的性质

| 缺失类型 | 恢复动作 | 可以得到什么 |
|---|---|---|
| 信息在原始材料中，只是问答交错／关联缺失 | 搜索与绑定原调用、对象、要求版本、迟到反馈 | 可恢复原历史关系，核验后认证相应范围。 |
| 信息被导出遗漏，但原日志／附件仍可合法读取 | 按ID和版本取回，记录补取来源 | 可补全原历史证据；不能用相似任务的结果代替。 |
| 条件没写在对话，但当时工具／政策有明确规定 | 加入有版本的C，检查当时是否满足 | 可补规范条件；不能因此伪造当时已检查条件。 |
| 原行动结果永久缺失 | 保留UNKNOWN；若环境允许，另做有边界的重执行／验证 | 新证据可以支持新方法，却不能证明旧尝试结果。 |
| 某步骤从未执行，只是承诺 | 作为假设；若要验证，在新尝试里真实执行 | 形成新的受验证经历，原承诺身份不变。 |
| 无环境、无原日志、关键附件永久缺失 | 保留原任务未认证；输出预先定义的有充分证据局部 | 不能保证整条变黄金。 |

形式上有两种转换：

\[
\text{历史恢复：}\quad \widehat{\mathcal T}=R_\theta(E\cup E_{\rm recovered},C,V).
\]

\[
\text{新增验证：}\quad \mathcal T_{\rm new}=R_\theta(E_{\rm new},C_{\rm new},V_{\rm new}),
\quad \mathcal T_{\rm old}\xrightarrow{\rm tested\ hypothesis}\mathcal T_{\rm new}.
\]

新增验证必须保留新执行的时间、环境快照、输入、版本和结果。现在查询到某地址，并不能单凭这一点断言过去某次调用修改了它；其他动作也可能改变状态。即使复现相同初始快照并成功，也只是支持新运行及该条件下的方法，不恢复原随机调用已发生的结果。

一个不可识别性例子：若H1表示旧写入成功、H2表示旧写入失败，而回执丢失后两者给恢复器的输入完全相同，

\[
\operatorname{Obs}(H_1)=\operatorname{Obs}(H_2)=X,
\quad \operatorname{Outcome}(H_1)\ne\operatorname{Outcome}(H_2),
\]

则任何只读X的恢复器都不能保证给两者分别输出正确确定结果。模型先验可以给概率猜测，但不能把不可辨识事实认证为历史真值。这是本例的逻辑判断，不是对所有POMDP的不可学习定理。

## 8．用强化学习语言描述恢复

**训练的Agent是“整理与核验经历的恢复器”，其动作是接关系、判范围和选择补证据。**原业务Agent是否完成订单是另一层问题。

若只读取固定输入并一次输出结构，首版可直接建模为有结构输出的上下文决策：

\[
\widehat{\mathcal T}\sim\pi_\theta(\cdot\mid X),
\qquad \max_\theta\mathbb E[R(\widehat{\mathcal T},X)].
\]

不必为了叫RL就强造环境交互。若加入检索和主动验证，再使用多步恢复过程：

\[
z_t=(X_{\le t},\widehat{\mathcal T}_t,\mathcal U_t,budget_t),
\qquad a_t\sim\pi_\theta(\cdot\mid z_t).
\]

z是恢复器当前的信息记录；这里没有假定任意压缩后的z必然满足Markov性质。需要时保存完整决策／观测历史，或建模隐藏事实的信念分布。部分可观测环境的belief状态思想可用于描述这种不确定性；具体模型与可辨识假设必须单独建立。[POMDP研究](https://www.jmlr.org/beta/papers/v12/ross11a.html)、[ICML 2022离线POMDP研究](https://proceedings.mlr.press/v162/guo22a.html)。

动作集合可以包括：

- SPLIT／LINK：拆任务、绑定要求、动作、回执与反馈。
- JUDGE：给某项标准判SUPPORTED／REFUTED／CONFLICT／UNKNOWN，并引用依据。
- RETRIEVE：从允许的原日志／附件补取信息。
- VERIFY：执行有限检查，或在允许环境中发起另一次明确标注的新验证。
- ABSTAIN／STOP：证据不够时保留未知，或已达到范围条件后结束。

没有“生成一条缺失成功回执并写成事实”的合法动作。想象／世界模型模拟若加入，只能输出假设，仍需外部验证才能成为相应范围的证据。

## 9．奖励明确奖励“理解对”，避免奖励“编得完整”

建议先训练结构化恢复，再考虑生成技能后的间接效用。定义一个待开发集定权的示意奖励：

\[
R=\alpha F_{\rm relation}+\beta F_{\rm judgment}
+\gamma C_{\rm answerable}+\eta U_{\rm calibrated}
-\lambda H_{\rm unsupported}-\mu D_{\rm omitted}-\nu Cost.
\]

| 项 | 实际依据 |
|---|---|
| F_relation | 独立核验的任务／要求／尝试／反馈关系，与预测对齐后按类型计分。 |
| F_judgment | 对同对象同标准的局部判断是否正确；使用有标签的标准，未标注不默认失败。 |
| C_answerable | 可从当前输入或允许查询正确恢复的必答问题覆盖率；分母由参考标注确定，不由模型自己挑问题。 |
| U_calibrated | 在确实不可确定时正确保留未知；对确实可答的问题乱弃权受到覆盖及判断损失。按可答／不可答分层报告。 |
| H_unsupported | 编造动作／返回、扩大评价范围、将自述当执行等已核查错误。来源存在不等于语义支持。 |
| D_omitted | 漏掉必须保留的条件、反证、相关失败和输入依赖。 |
| Cost | 模型token、检索和新增验证开销；预算固定，不能靠全空输出省费获胜。 |

质量门槛、预算与各项分数必须同时报告；不能只靠成本惩罚的权重碰运气。已知不可支持的确定断言拒绝认证；语义错误的实际检测能力仍需独立评估，不能声称程序保证零幻觉。

完整任务得分可以作为后续技能效用奖励，但不能拿它代替F_judgment：任务0分时，查询仍可能正确；任务1分时，未执行承诺仍然没有执行证据。

ProcessBench将步骤错误定位作为独立评测对象，可借鉴其“过程判断需要独立标签”的思路；它是数学推理任务，不能把其标注直接当企业工具轨迹的真值。[原论文](https://arxiv.org/abs/2412.06559)。

实现训练时可从已核验样例SFT起步，再用GRPO对同一输入采样多份恢复结果，以该奖励比较：

\[
A_i=\frac{R_i-\overline R}{\operatorname{std}(R_1,\ldots,R_K)+\epsilon}.
\]

这是组内优势的示意，实际策略更新使用正确的采样策略概率、裁剪与KL设置；确定性程序补写的内容不能当成模型自己采样的token计算梯度。候选奖励全相同则没有这组的相对学习信号，不能人为指定赢家。GRPO机制来源于DeepSeekMath，不是本项目创新。[原论文第4节](https://arxiv.org/html/2402.03300v3#S4)。

## 10．缺失数据的训练目标必须跟着“可见性”改变

推荐训练样本：

\[
d=(X_{\rm full},\mathcal T_{\rm ref},M,X_{\rm observed},Y_{\rm observable}),
\quad X_{\rm observed}=D_M(X_{\rm full}).
\]

先有经过核验的记录，再按可复现遮罩M进行交错、删除显式关联、遗漏回执／附件等处理。Y_observable必须重新说明在当前可见材料和允许查询范围内，哪些可答、哪些必须未知。

| 训练输入变化 | 正确目标 |
|---|---|
| 删除任务标签，但正文与调用ID仍足以区分 | 恢复正确任务和调用关系。 |
| 删除回执，但允许检索同一调用的原审计记录 | 选择正确检索，取回后再判断。 |
| 删除唯一成功回执，且其他信息无法区分成败 | 输出UNKNOWN；不能因教师知道隐藏答案而惩罚它没有猜中。 |
| 原轨迹没有修复，环境允许新尝试 | 将新修复执行单独记录；新成功支持修复候选，不篡改旧失败。 |

教师可见完整材料用于构造和核验奖励；恢复器不可见隐藏答案。仅有原终局分数还不够，仍需补局部关系／标准标签。先按任务或任务族划分训练开发测试，再生成损坏变体，避免同一原轨迹的不同版本跨集合泄露。

主动查询可以按“每单位成本增加多少已核验必答问题”选择，而不是追求模型主观熵下降：

\[
\Delta(a)=\mathbb E[N_{\rm verified}(z_{t+1})-N_{\rm verified}(z_t)\mid z_t,a]
-\lambda cost(a).
\]

这是拟议决策目标；现实运行没有全部标签时需可校准估计器和真实返回核对。预算结束仍缺关键证据就返回候选，不强迫每条轨迹到达Gold。

## 11．一个缺失回执的恢复回合

构造输入：记录保留查询动作、修改调用、助手“已完成”和用户“谢谢”，但修改回执遗漏。

| 回合 | 恢复器决策 | 新证据与结果 |
|---|---|---|
| 0 | 将查询与修改分成局部节点；完成声明单列；修改结果UNKNOWN | 不因为感谢填成功。 |
| 1 | 发现修改调用ID可定位原审计日志，选择RETRIEVE | 取得同一调用的明确状态拒绝回执，并记录补取来源。 |
| 2 | 将回执绑定修改节点，检查当时工具规则 | 查询经验保留，修改拒绝与状态条件对应。 |
| 3 | 输出失败边界及未支持完成声明；按P核验Ω的必答问题 | 对“该次修改拒绝的边界”可获黄金资格，业务失败事实不变。 |

若第1步查不到任何证据，则不能给该拒绝结论。可停止并保留查询局部；或在允许的新环境快照下验证候选方法，得到另一份新经验。RL应奖励前一种情况下的正确补证据，也奖励后一种情况下的合理未知，而不是固定奖励“最后写成成功”。

## 12．对应当前实现和候选研究贡献

当前代码有来源、关系、局部检查、未知与程序聚合的基础结构；尚无本文完整Ω／P黄金认证协议、训练数据集、SFT／GRPO或主动取证策略。新增schema是论文设计，不声称已逐字段落地。

候选研究问题可以写为：**在部分可观测、多任务混杂的经历中，如何恢复支持技能学习的局部关系与条件，并以有范围的证据判断控制经验归纳；必要时用有限额外观测消除关键缺口。**

当前主线优先固定输入的恢复学习；主动补证据作为未来可选扩展，明确新增预算并向基线提供同等证据条件。图、过程奖励、GRPO或主动取证本身都不单独作为创新。更具体的待验证贡献在：恢复错误减少能否传递为错学条款减少、有效经验保留和新任务收益。
