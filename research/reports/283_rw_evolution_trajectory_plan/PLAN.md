# 26个独立GUI来源的演化轨迹采集方案（执行前方案）

日期：2026-10-04。用户要求“依据这个，开始生成演化集轨迹，先给我方案和你的期望产出……会在本次产出的轨迹集上构建skills库”。本轮先完成可审查方案与只读设施/数据链路审计，不启动模型或参考应用。来源候选沿用[281/280的26主任务＋1候补](../280_gui_pool_sufficiency/README.md)，不重新扩充。以下为拟执行协议，不把建议当作已运行的事实。

## 1. 目标和任务单位

交付目标是**26个应用家族的可追溯完整交互链**，能还原“为什么探测参考、观察到什么、如何实现、运行出了什么错误、反馈如何导致修改、最终验证如何”。不是交付26段经验总结、62个点击脚本或预写skills。

| 平台 | 目标完整应用任务 | 备注 |
|---|---:|---|
| Ubuntu | 7 | 需要独立原生GUI沙盒准入 |
| Windows | 5 | 需要独立Windows交互桌面/宿主准入 |
| macOS | 3 | 需要真实macOS宿主准入 |
| Android | 6 | 需要API35模拟器/控制通道准入 |
| Web | 5 | 现有官方Web路线已有历史执行，5个新参考仍未准入 |
| 合计 | 26 | MacPass条件候补不启动、不计目标 |

一个应用对应一个完整复刻任务。原62个主池流程只提供探索/训练验证器的候选检查维度，不分别算62道训练题。参考应用可观察的本地核心、页面/菜单、必要状态和交付范围须在采集前明确；不能运行后因模型做不出而缩小题目。联网同步、真实账户、Package Manager安装/卸载/root等已排除能力在任务定义中显式披露，因此自己的训练问题不是官方250题的同难度替代版本。

这类轨迹主体是任务指令、agent多轮GUI/编码/运行工具交互和环境回执。纠错轮之间由控制器回传真实训练验证反馈，不额外编造用户对话、老师答案或隐藏思考过程。[论文§3.1](https://arxiv.org/html/2609.22000v1#S3.SS1)提供同类参考探索→实现→运行验证轨迹的依据；本项目做skills素材，而非重现作者35,000条SFT采样配方。

## 2. 执行前先解决的门禁

**事实**：26个新参考的runtime accepted仍为0。已有端到端经验主要是官方Web旧canary；源码已取得不能证明五平台已可运行。只读核对显示Docker Desktop停止，WSL另有其他聊天使用的独立dockerd；不能通过重启Desktop或复用其他实验的桌面/容器来“顺便”准备新实验。本机未发现已准入的Windows/macOS SSH目标；WSL有/dev/kvm但当前执行用户无读写权，adb/emulator/qemu/xvfb-run未在当前PATH。具体证据见[runtime审计](runtime_audit.md)。

逐应用门禁必须完成：固定依赖/编译或受控官方构建；参考可启动；统一字体/locale/viewport；GUI控制/图像通道可达；本地fixtures可导入；动作能改变真实状态；重置和重开可重复；独立candidate环境可运行；来源/家族及访问边界复核。

先准备Web和Ubuntu12候选；Windows5、macOS3、Android6保留待宿主/通道准入。可准备资源不等于12个已经准入。macOS不能靠Windows/WSL改皮肤代替，Windows不能把当前研究桌面直接当干净target，Android不能把mobile UI当普通网页。没有宿主时如实waiting_resource，不记模型失败或填0。

## 3. 先冻结训练验证器，再调用模型

每个训练应用使用**独立新写、参考运行证据支持**的行为检查和视觉检查；不读取、移植250评测私有tests/gold，也不按250的分数反调训练题。

1. 在固定reference上运行每项检查，确认参考能通过，保存输入/操作/输出和成对截图。
2. 至少覆盖一次关键状态变化、输入变化或合法/非法边界；有保存/导出功能时核对实际工件与重开。计时/播放软件必须检查实际时间/暂停/寻址，而非静态标签。
3. 用缺少对应行为的负对照确认检查能发现问题；检查自身flaky或环境失败先修，不能交给模型承担。
4. 冻结任务说明、检查集合、评分口径、视觉阈值、fixtures、环境与hash。首轮看到结果后不能降低阈值或删难项。

“成功”应指全部冻结必要行为检查通过、合法交付、视觉检查有效并通过预先设定标准。视觉评分/检查没完成记UNKNOWN；HTTP200、进程退出0、出现文件或界面好看都不是成功的充分证据。功能部分完成保留逐项分数，模型失败保留原结果；不用success标志覆盖原生评分。

训练验证器的公开失败摘要可以供纠错轮使用：实际失败步骤/回执、运行错误、可核对的截图差异和通过/失败项。不给参考实现、标准补丁、250私有断言或人为写好的“应学教训”。反馈规则全任务一致。

## 4. 同一任务最多三轮，是真实纠错链

拟执行：首轮从空的candidate工作区开始；正式交付后运行冻结训练验证器。通过则停止。未通过且有可用纠错信息，第二轮继承自己上一版代码及真实反馈；第三轮同理。第三轮未达到标准仍停止，保留失败。

最多三次完整agent调用/正式candidate提交与训练验证反馈，含首次；resume模式接续到新纠错轮也计数。每轮内允许官方agent正常探索、写代码、编译、运行和自查，但不能把正式评分后的无限修复藏进一个trajectory。不同版本、多个流程、跨平台端口和更换任务目录不重置应用家族计数。

不同应用之间保持空的会话/工作区，不传入其他应用的旧代码、经验提示或新生成skills；本批采集结束才交给用户建库。不会自动启动AutoSkill学习或250题评测。

基础设施中断保存原request/轮次/部分trace，能安全接续时仍归原轮次；不能重生成另一条模型答案后挑高分。若必须从头重新调用agent，该调用也消耗三轮额度，不能另列“infra重试”取得第4次模型纠错。参考没有准入或模型还未启动的准备失败不冒充任务轨迹。

## 5. 模型、harness、预算与批次

- 拟沿用用户为RW指定的`deepseek-v4-flash-vision-exp`供应商资源。采集前验证真实截图输入、工具参数/回执、finish完整性和错误传播，记录请求别名与供应商实际返回身份；不把别名当checkpoint已证。不改其他聊天模型/账本。
- 基础harness以218的pinned官方vendor/Claude Code调用协议为起点，必要传输/视觉桥接显式另建新冻结版本。不能直接继承267/v17针对corravale的fidelity提示、专用guard或人工分数指导。
- 代码事实：官方`agent_invocation.py`的完整run默认72,000秒（20h），模型请求1,800,000ms（30min）、工具180,000ms（3min），`max_turns=None`。方案沿用官方完整run安全上限，避免恢复旧240秒绝对API截断。20h不是期望每题耗时，不强行跑满；如果另设更短任务预算，必须在首轮前统一冻结并披露，不能超时后按模型失败/基础设施故障混写。
- 26题每题1–3轮，**目标26条应用家族链、最多78个完整轮次**。78不是78条成功轨迹；若每轮都触及20h，理论上限为1,560 worker-hours，不能现在许诺一天完成或费用。首次端到端后报告实测token/请求/时间再估算剩余量，记录所有费用。
- 起步1 worker。首批选五平台各1个已准入参考（拟Squoosh、Calculator、Caesium、To-Day、OpenCalc）；不要求在缺宿主时伪凑五平台。它们就是26题中的正式首轮，保留并计数，不丢掉重跑。确认输入/图像/回执/真实验证/落盘完整后继续剩余21题。运行设施允许时再最多2个独立worker；不能共享一个native桌面/session，不能挤占其他实验内存。

## 6. 交付四层数据，避免“文件在、学习却没看到”

| 层 | 交付内容 | 作用 |
|---|---|---|
| 原始证据 | 原生CLI JSONL、公开工具调用/回执、图像块/截图、stdout/stderr、模型请求完成/失败、candidate源码及关键提交hash | 保真、定位错误与复核 |
| 标准交互链 | 26个family chains；每事件保留顺序、role、tool_call_id、round、时间、图片hash、父轮/代码关系、actor是否看到该信息 | 可重放且不丢纠错因果 |
| 学习视图 | 机械导出的原生AutoSkill trajectory文本输入；保留真实公开调用/回执，不由LLM先总结成“经验” | 给当前SDK可消费的素材 |
| 结果和质量索引 | 准入/等待、完整/部分trace、成功/部分失败/预算耗尽/基础设施/评分UNKNOWN，验证证据、usage、hash与分组 | 控制学习口径和复现实验 |

截图原图必须与事件可关联；图像路径不是视觉描述。区分模型真正收到的图像、动作后监控截图和验证器配对图，绑定consumer/模型request引用，不能把91张监控图直接说成模型看过91张图。原生AX/DOM或工具提供的OCR文字可以原样保留，但不后加“标准视觉答案”。原始日志受控归档；公开学习视图排除凭据、私有系统信息、judge gold及供应商隐藏reasoning，不伪造agent解释。

当前官方`extract_from_agentic_trajectory`会把传入文件或结构化data转成一个text unit，再以单user消息与synthetic success=True处理；这不是benchmark成功，传messages/events字典也不能据此宣称结构化导入。218已说明当前学习text-only，截图仅provenance。见[数据合同审计](trajectory_contract_audit.md)。

因此本次先确保raw/standard信息完整，并提供可验证的native文本视图；不热改AutoSkill算法，也不宣称现在已接通多模态skills学习。训练成绩始终保存sidecar，最后轮的评估如果agent未看到不能伪装成其工具回执；下一轮确实收到的反馈则自然进入公开轨迹。是否让学习器读取额外成败标签、接入图像或新结构化适配，属于后续独立学习配置，不能由synthetic success猜测或自动套用另一聊天tau域的盲提取决定。

原始全集保留成功和失败；按应用默认给一个完整chain，避免三轮失败应用在默认学习中自动三倍加权。另提供逐轮事件片段及成功、实际纠错、最终任务失败、infra诊断的**索引**，不销毁失败、不按最高分只保留末轮，不强制凑负例或skill数。逐轮索引保留父链上下文/图片/产物引用，不冒充多个独立应用。超学习上下文的长链不能静默截断，切片/去重/上下文重放均需另有manifest；目前不许诺SDK无限长度。

本次还核到两个具体限制：官方collector默认可跳过大于64MiB的session文件，不能据“trajectory.jsonl在”称完整证据已捕获；当前AutoSkill connector还可能保留user文本尾部而截掉头部，`max_input_chars=0`不是关闭截断而可能得到空user。新采集必须登记原始文件跳过/缺失；正式学习接口须核对序列化后的实际请求与原始内容，未准入不称“完整链已被学习”。支持结构化messages/events的`AutoSkill.ingest`配合官方offline trajectory提示运行时，是可选的**新外部输入适配**，现有218/208未实现/验收，不能靠给generic importer一个JSON数组就宣布接通。

官方SDK在`client.py:114`将每次ingest的技能候选上限硬夹为0–1。26个完整chain各首次ingest一次时最多提出26个候选，最终可能因空抽取/合并/更新更少；这个上界不是所有其他学习编排的总上界，也不是成功技能保证。以后若按逐轮或有证据的片段学习，需明确新的输入粒度/权重和上下文策略，不为凑数量悄悄改编排。本次交付完整链与索引，使用户后续选择可复核；不预写skills。

## 7. 数据验收与期望产出

可承诺的采集质量目标（需执行核验，不是已达到）：任务/家族/轮次对应100%；记录中所有模型工具调用有可核对回执或明确中断标记；模型实际看到的图片都有可访问原图/hash；反馈对应真实前轮candidate与验证结果；源/环境/提示版本可追溯；无隐藏评测资料、人工成功、伪回执、秘密重试、未说明裁剪；完整输送覆盖可按事件数/hash核对。

目标产出26条应用链、26–78完整轮次（以全部26参考准入且执行为条件），覆盖五平台和62拟议行为观察维度。实际完成/成功/纠错对数、图像数、token/费用和能学出的skill数量现在未知。若宿主缺失，交付已完成的真实子集及waiting_resource登记，不能把12个Web/Ubuntu候选宣称五平台26完成。

研究期望：真实素材可能支持控制变量探索、状态/数值建模、合法动作与错误恢复、保存/导出、GUI焦点/权限、动态时间/播放，以及最后编辑后的行为/视觉自查等skills类别。是否产生多技能、是否正确、能否迁移到250题必须在用户随后建库和评测时验证，本轮不预先编写这些skills作为结果。

首个端到端样本必须人工核对raw→standard→native学习视图，给出实际事件/图片/回执计数、每项损失/未消费说明以及真实成败。先证明“轨迹确实被记录且可用于所选输入链路”，再批量，不能只看已生成文件数或controller心跳。
