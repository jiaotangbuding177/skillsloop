# RecreationWorld 演化轨迹采集方案审计

日期：2026-10-04。范围：科研方案；本轮未启动模型、应用、评分器、采集或 AutoSkill。本文不修改旧实验 freeze、共享服务、旧 267 STOP 或 250 题评测输入。

## 结论与当前证据

26 个主候选已经足够开始**运行准入和小规模 canary**，暂不增加应用。当前应先把每个应用变成一份完整、可观察、可独立验证的复刻任务，再采集轨迹；不能直接把 62 条拟议观察流程当成 62 道题或 62 条已经合格的轨迹。

建议以“一应用一完整复刻任务”为单位：先选每个平台 1 个 canary；每个应用首轮与纠错合计最多 3 轮；同一应用家族跨端口、版本、工作流均不重置计数。canary 属于原 26 个任务，不是额外 5 道题。每个通过准入的应用产生一个完整任务轨迹包，其中可包含 1—3 个正式提交轮次。全池上界为 78 轮，不代表会得到 78 条成功轨迹或任何确定数量的 skills。

## 与官方任务思路的对应边界

本地官方 README 将任务描述为：交互访问运行中的 reference，交替探索 GUI、独立实现、构建运行和视觉自检，最后以冻结、经 reference 验证的功能及视觉断言评估。实现语言和架构可不同，评分依据可观察行为而非源码相似度。

因此，本研究可以复用官方五平台的执行/控制/产物框架，但训练应用与独立训练验证器由我们准备。这不能被称为“官方训练集已取得”，也不能把只完成两个简化流程的实现称为完整应用复刻。官方 Web 服务可向浏览器提供 HTML、样式、脚本和资产；本研究仍禁止给 actor 本地 reference 源码归档、仓库地址供克隆、源码挂载或整站复制工具。允许的 public 交互边界与禁止复制边界须在新版本 manifest 明写。

依据：[本地官方 README](../../experiments/218_recreationworld_glm_pipeline/vendor/RecreationWorld/README.md)、[Web guide](../../experiments/218_recreationworld_glm_pipeline/vendor/RecreationWorld/docs/providers/web.md)、[Linux guide](../../experiments/218_recreationworld_glm_pipeline/vendor/RecreationWorld/docs/providers/linux.md)、[Windows guide](../../experiments/218_recreationworld_glm_pipeline/vendor/RecreationWorld/docs/providers/windows.md)、[macOS guide](../../experiments/218_recreationworld_glm_pipeline/vendor/RecreationWorld/docs/providers/macos.md)、[Android guide](../../experiments/218_recreationworld_glm_pipeline/vendor/RecreationWorld/docs/providers/android.md)。本轮只读原生文档，没有读取评测 tests。

## 一应用一完整任务如何冻结

1. **固定 reference。** 沿用 280 注册表的 repository、SHA、平台和家族 ID；记录安装/构建包及依赖 hash、操作系统/显示尺寸/语言、启动方式、fixture 与 reset 方法。源码只给可信基础设施用于构建 reference，actor 工作目录不含它。
2. **观察完整公开 GUI。** 在运行准入后登记主窗口/路由、菜单、对话框、可编辑对象、主要模式、导入导出、撤销历史、持久化及关键状态转换。62 个流程只帮助找到这些状态，不能自动充当完整功能清单。
3. **形成一份任务 brief。** 明确目标是复刻该固定版本的公开核心 GUI 和行为，列出全部已纳入窗口/模式/功能域及观察入口。actor 可探索 reference、写自己的代码、构建启动、自检；不向 actor 传 reference 实现、私有数据或 250 题的测试答案。
4. **处理无法纳入的行为。** 云同步、付费登录、外部服务、未能可靠观察的行为必须逐项登记。若它们是应用核心，应用保持 `admission_blocked`，不能悄悄删掉后称“完整应用”。若决定做离线/功能子集，须明确另列 `scoped_variant`、冻结取舍并报告子集；它不是本方案默认的完整任务，也不能增加家族的三轮配额。
5. **冻结独立验证器。** 在第一次 actor 调用前完成 reference 运行验证与清单覆盖审计；任务、fixture、断言、视觉基准、工具协议、模型配置和评分归属全部 SHA 固定。运行中不因 actor 表现差调整目标。

建议每个任务的 `scope_inventory.json` 包含：`family_id`、`reference_sha`、所有核心窗口/模式与功能域、纳入/排除理由、对应正例/负例/持久化断言、reference 验证结果、无法覆盖项。只有功能域清单与验证器相互对应，才可标记为完整任务准入。未覆盖项必须显示，不以“通过两条流程”遮盖。

注册表有两种流程字段形式：`name/observe/implement/check` 与 `sequence/validator_expected/evidence`。后续转换应统一 schema 并保留每条来源，不可只读取第一种形式而丢掉 Web/macOS/Android 观察流程。部分 `sequence` 已包含观察→实现→自检三个阶段，它们不是三个独立任务或三次纠错轮。

## 三轮控制：正式提交、真实反馈和终止

官方单条轨迹的 explore–implement–verify 循环可包含许多模型和工具调用。**调用数不是纠错轮数**。本方案将用户三轮上限落在候选正式提交及其冻结训练验证反馈上，禁止把额外整套重跑藏进同一轨迹。

- **第 1 轮：** 从干净 actor 工作区开始，模型自行观察、实现、构建、运行与自检。提交一个候选；可信验证器在恢复后的 reference/候选环境中运行冻结断言，保存完整结果。
- **第 2、3 轮：** 仅当上一轮未达到预先冻结的完成条件且配额仍有余量时，保留同一任务、同一候选工作区和真实历史，回传上一轮的训练验证失败与运行错误。模型修复后再正式提交；不得重新装成全新任务或偷偷给正确实现。
- **提前结束：** 首个满足冻结完成条件的提交即结束，不为提高分数继续采样。完成条件需事先定义为全体关键行为通过、功能/视觉结果齐备且无基础设施 UNKNOWN；视觉数值门槛若使用，须在模型启动前确定。尚未定义门槛时不能先跑再选择有利门槛。
- **第 3 轮仍不达标：** 记录 `terminal_not_met`，保留真实分数/未交付/失败/UNKNOWN。最终提交为最后一轮，不能挑前面最高分当最终结果；各轮可另行做纵向分析。

轮内允许 agent 对自己的候选正常自检和修改代码，但不能无限获取正式冻结评分反馈然后修到满意。正式验证调用有持久计数；失败后反馈引起的新候选提交进入下一轮。这样区分正常的多步任务解决与历史 corravale 同一题反复整套重跑。

三轮计数按 canonical 家族保存于独立 append-only 账本，第一次 actor 调用前预留 `attempt_id`。换 source SHA、端口、任务名、操作系统移植、观察流程或控制器都不能重置。跨进程恢复须确认旧 actor/controller 身份退出且没有用户 STOP，沿原 `attempt_id` 恢复，不启动并行重复 actor。

错误归属必须区分：

| 情况 | 记录与处理 |
| --- | --- |
| 模型生成的候选无法编译、启动或行为不符 | 真实 agent 结果；提交轮计数保留，不借口基础设施免除 |
| 模型端点传输失败、控制进程/桌面服务故障 | 保存请求与基础设施证据；未得到可判结果为 UNKNOWN，不能填 0 或成功 |
| 完全相同检查点的传输恢复 | 可继续同一 attempt，但不得新建候选、追加纠错提示、擦掉失败或重置配额；恢复记录独立保留 |
| 需要模型根据错误再次修改 | 使用下一轮；第三轮后没有第四次纠错，即使另命名“基础设施 retry” |
| 验证器自身不稳定/错误 | 暂停该任务，保留旧 freeze 和提交；如需改任务/断言，建新版本和归属说明，家族配额仍不恢复 |
| 可用性/凭据/平台不足或用户 STOP | waiting_resource / user_stop；不计模型失败、不强制重启 |

不要用“每轮固定几小时截断”换取假完成。执行版本须明确自然终止、停止与资源故障如何记录；若需要运行预算，应在执行前单独明示并冻结，不能静默改变现有用户约束。真实进展监测看模型完成、工具事件、构建/运行状态和文件变化，不看 controller 心跳独自判健康。

## 独立训练验证器与反馈内容

训练验证器从**训练应用的公开运行行为**与受控合成 fixture 得出，不复用 250 题隐藏断言，不将 benchmark 私有测试或 gold 暴露给制题者/actor。可用原生平台的控制/评估接口，代码和期望值必须另行冻结。

- 功能：状态转移、正例/负例、对象关系、撤销/重做、取消、导入导出、跨窗口一致性、保存重开。已知数值/图结构/文件可解码及尺寸应有客观断言，不只检验文件存在或按钮能点。
- 视觉：固定 viewport、字体/缩放/主题/语言和确定 fixture；取得 reference 对应状态截图，检查布局、层级、控件状态、遮挡和画布内容。功能与视觉分别记录，不用一个替代另一个。
- 可信性：每条冻结断言在 clean reference 上通过，重复 reset 后应可重现；明显违反关键行为的独立受控负例应被拒绝。reference 不稳定时断言 UNKNOWN，而不是把不稳定结果反馈为 agent 错误。
- 反馈：只包含本训练任务实际执行的动作/状态、期望与观察、失败类型、可复现错误及截图/日志引用。保持本轮原始返回，不由研究者改写成“应该如何实现”的答案或人工 skills。

actor 知道任务目标与工具协议是前提。启动前必须验证消息/工具格式、图像输入、上传下载、构建和评分返回链路；这些无模型的基础设施 smoke 不消耗纠错轮。若首次真实 actor canary 暴露格式问题，它仍是真实 attempt，保留记录，不能通过改版本不断获得新的三轮。

## 轨迹格式和 AutoSkill 学习输入

应保留任务级完整多轮记录，而非只存最后答案或两段屏幕操作。原始轨迹应包含：任务 brief、actor 输入/可公开响应、全部工具调用及原始回执、reference/候选观察与截图引用、代码修改/构建/运行、每轮提交 hash、训练验证反馈、轮次连接、结束原因、模型/API 完成与失败、成本/耗时和 provenance。保留全部候选与负结果，不只下载/留下高分者。

原始审计包与学习视图分开：剔除凭据、私有推理、250 题 tests/gold、reference 源码与控制面秘密；保留 actor 真正看见的公开观察、工具错误和上一轮真实反馈。训练分数/UNKNOWN 可保留在审计 metadata，不把未完成冒充成功。未另获授权前不额外注入研究者总结出的“教训”或把其他实验的奖励标签策略自动移植到本任务。

学习适配验收必须逐项证明：原生 trajectory 接口收到的是该任务的真实 role/tool/observation 顺序，截图如何表示，所有纳入事件是否进入输入，失败与轮次是否保真。如果沿用泛文件导入器导致整个 JSON 被包成一条 user 消息并带 synthetic success=True，就不能宣称已经保留原生多轮语义或真实成功标签；应先将适配问题作为新版本验收项，而不是静默沿用。

建议先完成采集，再以冻结的 official AutoSkill trajectory 抽取→维护→导出生成库；基础 actor 在采集阶段使用同一空库或同一冻结库，不在应用间偷偷加入刚学出的 skills。这样可以解释 skills 的来源，也避免技能反馈改变后续采集样本的生成条件。失败轨迹和空抽取结果独立保留，不能靠删掉它们提高产出率。

学习阶段需逐任务 `total/processed/failed/skipped`、输入 manifest/hash、官方抽取维护事件、新增/合并/更新/删除/无新增决策及 embedding 真实成功/失败证据。只允许验收真实语义 embedding 的 attempt；不得以 hashing/BM25 回退冒充语义库。需要多库/隔离的设计应在后续正式学习版本明确，本方案不触发学习或评测。
