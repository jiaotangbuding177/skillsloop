# 本地技能评测准备：EvoMind补交范围与Trace2Skill强基线

日期：2026-10-05。性质：已有材料审计、官方实现核对与评测准备方案。本轮未安装环境、执行基线、调用模型或运行新任务。适用目标：从真实企业会话沉淀技能库，并确认技能在本地新任务中能够实际加载、使用工具、交付和评分。

**同日第2版修订：学习输入冻结为已给的真实历史会话与轨迹，不要求重跑旧任务采样rollout，也不要求找回全部中间产物。** 历史材料有则补证、丢失保留未知；新任务消费所需文件/环境/评分单独准备。上一版统一P0要求过严，已在正文和清单替换；[上一版存档](2026-10-05_local_evaluation_readiness_and_trace2skill_v1_archive.md)保留，[精简交付要求](2026-10-05_frozen_history_evomind_supply.md)为当前发给数据方的入口。

## 1. 当前判断

**现有数据可以开展会话分析和有证据边界的技能生成探索，但尚不能宣布“企业任务执行→技能消费→产物评分”的本地评测环境就绪。** 不能用技能文件生成成功替代执行收益，也不必等完整kmagent源码才能推进。

当前学习端直接使用已有真实会话、工具记录与已恢复轨迹，不等待遗失的历史稿件。最重要的新增交付是**新任务实际输入、可消费技能/工具的运行条件和独立评分依据**。可取得的历史原文件、版本、产物与日志用于增强证据，不作为全量学习门槛。公共基准是可选的受控补充，不替代自然历史数据主实验。

全量整理会话保留自然缺陷；缺失不能靠模型填成历史事实。先对有限任务范围补齐执行环境，再分开报告“可执行任务子集”和全部自然会话覆盖，不能偷偷丢弃难例并称全量有效。

数据库名与表名依据本地平台源码/导出脚本，数据方先核对生产schema，**不声称所有历史表都已启用且留存完整**。文件与技能接口、实例路由和查询模板见[原补交清单](2026-10-05_evomind_data_supplement_request.md)及[来源标注](2026-10-05_evomind_skill_provenance.md)。原清单对技能的“条件P1”现按本次实际执行目标提高为选定任务的P0；原“历史无实际技能”表述已被后续工具证据更正。

**“回复中的占位符”分开处理：** 文件名/路径不能替代文件；“已读取”回执不能替代完整技能正文或工具返回；被脱敏的技能名须恢复ID映射；没有真实消息时间不能造时间；真未生成的产物不能补造成功稿。拿不到的项目写入缺口清单，不用AI生成替代品当原始文件。

## 4. 建议的一次性交付目录与关联方式

```text
evomind_eval_supply/
  README.md                      # 范围、线上版本、字段和已知缺口
  manifest.json                  # 文件hash、版本、导出时间
  sessions_and_bindings.jsonl     # 用户/实例/原生会话键，原顺序语义
  events_all_roles.jsonl          # 原消息、工具调用与返回；补缺即可注明范围
  files_manifest.jsonl           # 输入/参考/输出/中间稿与消息/尝试对应
  blobs/<内容hash>/<原文件名>    # 实际字节；保留不同版本
  skills/<技能ID>/<版本>/        # 完整包、许可、来源与作用域
  environment/                   # 镜像或构建文件、锁文件、字体、路径说明
  tools/                         # schema、适配入口、服务说明
  tasks/                         # 任务请求、可见资料、重置说明
  evaluation_private/            # 标准、标签和参考答案，与执行输入隔离
  outcomes/                      # 历史验收与本次回溯评审分开
  unresolved.jsonl               # 拿不到/已删除/只剩当前版/来源不明
```

一条文件对应记录至少说明“哪个会话、哪个用户/实例、哪条消息、输入还是输出、历史路径、实际文件hash、哪个版本、当时是否可见”。用户和执行Agent只获得本题可见输入；历史输出、评分答案、隐藏归属属于单独权限层。缺字段注明，不生成伪关联。

工作区初始状态包含本题附件、模板和正常可见参考资料；历史最终稿不可放进去帮助新执行。业务连接以测试账号/状态快照隔离，每次恢复；只重放旧工具返回可以用于学习/恢复诊断，但不能算新Agent真正完成在线任务。

## 5. Trace2Skill强基线还需要什么

本轮重新查阅[官方仓库](https://github.com/Qwen-Applications/Trace2Skill)。下述为官方设置核查和本项目适配建议，非已完成复现。

### 5.1 先建立官方表格通路

官方发布重点在表格任务，包含SpreadsheetBench-Verified的400题复现资料及运行/评分入口。说明用前200演化、后200评测，并在演化側验证后再评测；固定版本、初始化与模型设置至关重要。官方说明也承认长流程难以保证逐项完全重现。主研究计划沿用[073协议](073_rq1_trace_recovery_controlled_experiment.md)，任何内部开发划分/模型替换标为本项目设置，不冒充原论文配置。[官方复现说明](https://github.com/Qwen-Applications/Trace2Skill#4-reproduction-note)

这条线不需要EvoMind额外提供合同数据，需要我们准备官方代码commit、完整公开输入/答案/评分器、实际模型服务、初始技能、依赖与可用执行环境。官方默认OpenAI兼容API；当前曾使用的Anthropic协议端点不能直接假定可用，需确认兼容服务或协议适配，并记录模型差异。不能用已经在同批演化题上学习的released技能冒充未经学习的初始库。

### 5.2 企业数据上的机制适配

Trace2Skill论文v5附录A的轨迹采集是每题一条，§2.2允许先收集轨迹再分析，**不要求同题多rollout**。本企业主线用固定历史记录替代采集阶段，不运行旧任务制造更多经历。[论文§2.2及附录A](https://arxiv.org/html/2603.25158v5)。其失败分析有产物/参考文件核查能力，成功分析读取轨迹；必须保留局部补丁和合并机制及可用的分析能力，不能让缺文件触发路径错误后记基线算法失败。[失败入口](https://github.com/Qwen-Applications/Trace2Skill/blob/main/analysis/run_error_analysis.py)、[成功入口](https://github.com/Qwen-Applications/Trace2Skill/blob/main/analysis/run_success_analysis_llm.py)

历史学习直接使用已给请求、正文、轨迹、工具记录及可见反馈；产物和独立历史验收只在实际存在时补证。明确结果的子集可用官方成功/失败分流，报告覆盖；未知不得伪标签。全量自然材料如使用结果中立候选分析入口，各组共同使用并注明新增适配，不称原生Trace2Skill。失败因果不可解释时保留不可核验，不能编造。新任务消费单独准备真实输入、共同基础技能、工具环境和独立评分。方法比较与额外采样旧轨迹无关。

恢复研究应避免为基线拼接日志时偷偷用人工正确轨迹。目标已知的比较允许各组看到相同目标请求、混合原文及同等材料；隐藏归属仅评分方持有。失败分析器在演化侧是否可看参考文件，各组同权；测试答案不进入生成、恢复或执行输入。自然未知结果仍保留在全量探索材料，不要求把所有失败会话清洗成成功。

企业适配不能叫“合同任务官方复现”。官方表格通路用于确认强方法机制及执行/评分正确；企业通路用于评测真实材料迁移与工程价值，两类结果分开。

### 5.3 对比和所能说明的问题

| 比较 | 固定条件 | 回答什么 |
|---|---|---|
| 相同基础技能/不从本批经历学习 | 相同新任务、模型、工具、输入、预算 | 从经历学习是否有净收益 |
| 混合材料直接给Trace2Skill | 同目标、同可见证据、同初始化与分析合并器 | 无显式恢复的强对照；允许自然理解，不故意截断 |
| 普通LLM整理＋Trace2Skill | 同额度前处理及相同下游 | 是否只是任意一次整理就足够 |
| 我们恢复＋相同Trace2Skill | 主要改变恢复，其他共享 | 恢复对技能学习的贡献 |
| 我们完整恢复/聚合/封装 | 下游消费者与工具固定 | 整体方法效果；不能单独归因恢复 |

正确归属的同源轨迹可另作参考条件，不是理论上界。预算需计恢复、分析、合并、生成、验证与重试；最终测试只做测量，不回流修订。若比较首次涌现，用相同弱初始草稿；若比较深化，用相同人工基础技能。当前已有74/81技能证据，不可把历史材料谎称完全从零产生。

## 6. 已有真实数据能不能做评测集

可以，在独立留出可执行任务、真实输入文件、重置环境和可靠标准补齐后，它能够成为企业评测集。不是因为“真实会话”天然只能做演化集。当前主要缺的是可执行性与可验证性，而非必须公开这一属性。

回复关联的人工标注可用来评估部分语义匹配，不等于任务/尝试/反馈完整关系的真值，更不等于合同质量答案。历史AI产物可帮助回溯诊断，不能未经业务核验当正确参考。合同审查不宜逐字比对参考答案：可以用专家列出的必要问题、来源条款、立场约束、不得修改事项、文件格式和修改记录评分，接受合理不同表述。

公开SpreadsheetBench-Verified与企业评测建议双线使用：前者支撑可重复强基线和受控交错恢复实验；后者支撑自然数据的有效技能和执行价值。一个题的修订、相同附件/模板副本及近重复请求应归同一数据组，先冻结演化/开发/最终测试集合，再做生成和调参。时间/跨用户可作切分轴，但必须进一步检查对象与文件泄漏。

## 7. 首批最小准备包与验收目标

**建议先合同审查/文档交付一个任务族做通路验收；这是准备建议，不是已执行或统计充分的正式实验规模。** 学习案例从既有历史材料冻结，不要求数据方补成完整轨迹。独立新合同可从未参与学习且有可用输入的历史任务留出，也可业务方交当前新任务；这里的执行是技能消费评测，不是为学习旧任务额外采样。全部81项不默认都需要搭建。

以038合同多立场审查为例，以下为应交材料描述，不是假定原数据已具备的文件：

| 环节 | 需要的真实输入 | 可验收输出 |
|---|---|---|
| 使用旧案例 | 已给会话/轨迹与工具反馈，原合同/中间稿仅有则补 | 从明确用户要求、反馈与实际回执学习，缺文件的条款事实/修改效果未知，不重跑或补造 |
| 学习并封装 | 演化侧材料、初始基础技能包和共享工具说明、已核实结果/未知状态 | Trace2Skill和本方法各自实际技能目录、补丁/引用及生成日志 |
| 消费新技能 | 未参与学习的新合同、新要求、干净工作区、同样基础工具及依赖 | Agent实际加载本组技能并执行，交审查/修订文件及工具日志 |
| 验收 | 隔离的业务标准、条款证据、必要项/禁止项和产物检查 | 技术执行结果与业务质量分开；真实新产物评分，不拿旧稿重命名 |

对平台原生技能，必须拿实际包和专属服务入口；对公开技能，也需核对运行版本与平台改动。LibreOffice等第三方程序不用KM源码，可安装并冻结版本，但要能和技能脚本、中文字体、路径共同工作。

## 8. 何时才可以说评测准备就绪

1. **材料可用**：历史源冻结且缺失标记明确，不要求全量可复跑；新消费任务必需输入文件真实可解析，答案不混入执行工作区。已有恢复视图可直接生成；评价恢复时仍用原会话输入，不绕过算法。
2. **工具可用**：每个必需工具真实完成小任务，有返回与预期效果；外层exitCode=0不代替全部子命令/内容检查。环境镜像/锁文件与重置可复现。
3. **技能可消费**：完整包能被固定Agent发现和读取，必要脚本可调用，提示/上下文证据表明本组技能实际进入任务；不得仅有库列表。
4. **任务可评分**：新交付物能对应独立验收项，评分器/专家流程先用已知合格及已知缺陷产物校准；不能让生成器同时充当唯一裁判。
5. **强基线通畅**：官方/适配身份明确，成功/失败分析与补丁合并真实运行，技能用于留出任务，API与文件接口没有隐藏断点。
6. **条件固定**：输入、集合、代码commit、模型、基础技能、生成技能、环境及预算存档；正式实验开始后故障保留，修复后新运行版本重测受影响对照，不拼接多次临时修补的最好结果。

首批可以开始的条件是选定范围通过上述检查，不是拿到所有历史数据。环境错误与方法质量失败分开汇报，覆盖任务与不支持任务分开但同时统计。无法在开跑前保证任何运行绝不失败；可保证的是依赖和评分通路先验收、状态可重置、失败可归因、结果可复算。

## 9. 当前阻塞与下一步责任

- **EvoMind/KM方**：优先给新消费必需的技能/工具/服务与文件条件；历史额外材料有则补、无则登记，不重新生成已给轨迹或旧任务经历。
- **业务方**：提供独立评测任务/标准；历史结果依据可选，不要求全量回溯评审或手工恢复轨迹。
- **研究端**：使用已给工具记录作逐依赖核对、文件映射、任务分集、环境适配与技能加载检查；准备官方Trace2Skill代码和公开数据，实施公平适配与评分隔离。不能把这些算法/适配工作全转给数据方。

现有生成原型与此前单案例验收不升级成全量环境已就绪。历史中间稿缺失不再作为整个实验阻塞；当前主要前置为新任务真实输入与评分、必需基础包/服务/环境，以及研究端冻结划分和完成结果未知的基线适配。已有会话/轨迹/工具记录直接用，KM完整源码不是默认阻塞。自然缺失本身是实验条件，须报告算法如何使用证据/避免错误经验，不能声称补齐不存在的事实。
