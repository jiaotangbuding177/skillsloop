# 黄金轨迹：局部理解、证据归属与技能归纳的重新设计

日期：2026-10-05。状态：文献调研、源码审阅及研究设计，**没有修改代码、执行模型或开展新实验**。承接用户对当前轻量管道的批评，保留原实现和负结果，不把本设计写成已完成能力。

## 1．当前缺的是局部理解，不是再加几个字段

用户的质疑成立。当前代码能恢复任务、要求版本、尝试及评价对象，局部语义主要仍由一次模型提议。程序检查来源存在、编号绑定和时序相容，但没有充分检查：**某个评价标准究竟覆盖哪项动作或哪条声明，其他部分是否仍未知。** 三种条款用途和合法 JSON 不足以证明局部理解。

此前[高质量轨迹设计](2026-10-04_standardized_trajectory_recovery_method.md)已有来源忠实、关系正确、条件一致、依赖、结果范围和覆盖的原则，但未完整落实成可核验的局部经验单元及黄金认证协议。上一轮交付的是功能原型，不是已经具有黄金轨迹理解能力的算法。

| 当前具体问题 | 已有实现及产物依据 | 缺少的判断 |
|---|---|---|
| 宽方法被整体降为警示 | `live03` m1“提取原条款编号并生成审阅意见”引用旧回复，被标为失败边界 | 编号被改错，不说明“生成意见”整个行为错误；“提取编号”还是模型抽象，不能冒充可观察内部动作 |

## 2．相关研究实际上提供了哪些机制

以下只讨论已核对的原论文机制，不把预印本统称为WWW已发表工作。

| 工作 | 值得借鉴的实际机制 | 不能直接等同的能力 |
|---|---|---|
| [Trace2Skill，§2.3—2.4](https://arxiv.org/html/2603.25158v5#S2) | 成功侧单次分析；失败侧检查产物、对照参考并验证修复；轨迹补丁分层去重、解冲突 | 当前简化入口没有它的主动检查／验证修复，不能说局部理解已经强于该基线 |
| [SkillGen，AAAI 2026，§3](https://arxiv.org/html/2511.14670#S3) | 用动作图及子目标进展，通过TD信用分配识别高价值动作；以短片段和步骤技能提供上下文 | 价值和进展不等于事实／政策正确性；其进展信号不能凭空从企业聊天里获得 |
| [SkillGLoW，§3.2—3.4](https://arxiv.org/html/2609.02217v1#S3) | 比较同任务相邻尝试差异与验收结果；按流程家族聚类、压缩，再执行检验 | 多处同时变化时，分数改善不能证明每处修改都有因果贡献 |
| [AgentTether，§III](https://arxiv.org/html/2607.06273#S3) | 把决定—执行—反馈组成转移单元和依赖图，使用正常行为模型与运行局部异常检测缩小失败片段，再诊断 | 图上的相关依赖与异常分数不是确定根因；其重点是运行修复，非混合会话的技能学习 |
| [AgentPRM，§3](https://arxiv.org/html/2511.08325v1#S3) | 区分当前状态／动作的未来成功可能性与相对进展，训练过程价值模型 | 以后还能成功，可能因为后续纠正；不能给当前错误动作盖正确章 |
| [ProcessBench，ACL 2025](https://aclanthology.org/2025.acl-long.50/) | 用专家标注评价首个过程错误，独立于最终答案对错 | 数学过程标注不可直接充当企业技能真值，但支持分开过程与结果评价 |

更早的 [ExpeL §4.2](https://arxiv.org/html/2308.10144v3#S4.SS2)已经比较同任务失败／成功和跨任务成功经历，且指出成功轨迹也可能次优并误导经验生成。**成功失败对比、图、子流程、聚类或PRM本身都不能单独作为我们的新贡献。**

补充近邻：[LifeMem §4](https://arxiv.org/html/2609.12655v1#S4)归组流程并抽象共同约束；[GSE §3](https://arxiv.org/html/2608.06153v1#S3)使用技能关系图辅助更新并回放；[AWM §2.3](https://arxiv.org/html/2409.07429v1#S2.SS3)已有子流程和参数抽象。它们帮助确定差异，不能被描述成完全没有局部理解。另有同名EDA Trace2Skill `2605.21810`，本项目对照的是 `2603.25158`，不混写。

## 3．本项目怎样定义黄金轨迹

### 3.1 工作定义

> **面向技能学习的黄金轨迹，是相对于预先声明的学习目标、适用范围和核验协议，忠实恢复可观察行动及产物变化、保留有关依赖和反证、逐标准说明局部声明的支持与违反，并能约束技能条款用途和推广范围的可审查经验记录。**

这是本项目拟议的操作定义，不是文献已统一认可的术语，也不表示我们已经产出了经认证的黄金数据。

“黄金”描述学习材料的证据质量，任务成功另记。失败过程可以达到该标准；没有失败的成功轨迹也可能包含冗余、错误事实或未知步骤。缺失附件、结果或关系不能靠整理补成事实。

为避免“截一小段就叫黄金”，先确定任务目标、可分辨的局部交付／标准、关键关系和允许信息，再认证相应范围。不能看完模型输出后，把所有难点排除以宣布通过。

### 3.2 六项必须检验的条件

| 条件 | 具体要求 | 不合格表现 |
|---|---|---|
| 忠实 | 动作、产物、评价均有原始出处；观测和模型推断分开 | 凭“我检查过”补出不存在的检查 |
| 对象与要求清楚 | 任务、对象、有效要求及适用时段接准 | 用新增表格要求否定之前合法的文本输出 |
| 局部可判 | 单元按能分别接受检验的动作／产物声明拆分 | 把“生成正确意见、保留编号、输出表格”作为一个好坏标签 |
| 标准覆盖准确 | 判断注明检查了什么、没有检查什么及核验者 | 同一回复被验编号后，其所有方法都叫成功 |
| 依赖和对照完整 | 保留输入来源、必要前提、失败分支、修订差异、反证与可比性缺口 | 删除失败，拼出从未实际执行过的成功路线 |
| 能约束学习 | 每条规则连回支持和反证；条件、警示与未知在正文中不被改写 | 中间记录写未知，最终技能却保证有效 |

判“黄金”还需要独立核验这些关键语义，不能由同一模型提议后再自我确认。程序可核验引用和逻辑，规则／执行检查、人工或经验证的局部判别模型各自保留权威来源。模型置信度不是核验。

### 3.3 三种不同交付，不混为一个gold标签

- **标准化候选轨迹**：可追查，但关键语义尚未核验。当前Demo主要处于这里。
- **局部黄金经验片段**：某个预先定义的学习范围具备充分证据，相关必要条件、依赖和反证都留下。其他部分不继承其资格。
- **任务级黄金学习记录**：该任务学习所需的关键关联和局部判定已按协议核验，缺口明确且不影响拟归纳声明；若缺口影响关键声明，只能交付局部片段。

另记“黄金成功实例／黄金失败实例”的结果属性。业务结果未知的轨迹仍可正常生成候选，但不能称已验证成功全轨迹。大量弃权不算恢复准确；原文可判但系统没有恢复的关键关系必须算覆盖损失。

轨迹认证证明材料可用于学习；技能验证证明条款在新任务上可用和能否迁移。前者不替代后者。“最适合模型归纳”在这里是设计目标，仍需比较证据一致性、有效经验保留和下游任务表现，不能凭定义宣布最优。

## 4．把学习原子改成局部经验单元

局部单元按可检验的声明划分：一次工具调用可以有多个参数／业务标准；一条文本回复可以有多个产物声明。不暴力拆成每个词，也不把整回合强行当一个动作。

每个单元都应解释：

**当时的目标和条件 → 可见输入及来源 → 实际行动／可见产物变化 → 对应检查标准 → 分维度判断 → 反馈及后续修订 → 可以学什么、适用多远。**

其中“前后状态”只包含可见的对象／产物事实，是部分观察，不是假装知道企业或环境完整世界状态。文本审阅可用原文位置与输出版本；有工具时使用参数、回执及可见状态。未展示的内部推理或操作不补造。

### 4.1 每个局部判断至少分三轴

| 判断轴 | 回答的问题 | 可用依据 |
|---|---|---|
| 有效性 | 对哪项要求满足、违反、未知、不适用或证据冲突？ | 原要求、工具回执、产物比对及范围评价 |
| 目标进展 | 满足了哪个子目标、提供了哪个必要输入、是否有绕行？ | 可见完成状态；无可观察进展时只作估计 |
| 学习支持 | 可用作执行经验、失败边界、修订经验还是假设？ | 前两项及条件、来源、修订对照共同决定 |

有价值但未被证明正确的动作，仍是未验证候选；技术执行成功可能违反政策；为了找到答案而探索失败也不自动成为错误方法。合法、必要、有效和最优是不同判断，不能压成一个步骤分数。

### 4.2 核心中间结构：标准—局部声明覆盖矩阵

用 `J(局部声明, 标准)` 记录满足／违反／未知／不适用／冲突。每格同时记录原始证据、覆盖维度、评价来源与核验方式。目标ID相同仅证明关联对象相同，不证明标准覆盖整个声明。

没有覆盖关系的评价不传播；模型提议的覆盖关系没有语义核验时仍是提议。有总分0但无局部检查时，记录整体失败，不填每格失败；用户感谢只支持态度反馈，不填业务成功。

### 4.3 成功、教训、修订经验的证据契约

| 经验 | 最小支持 | 正确表达 |
|---|---|---|
| 可观察执行经验 | 有实际动作／产物及条件、输入输出来源 | 这种方法被实际采用过；效果未验时保留未知 |
| 局部成功经验 | 声明被对应标准和结果覆盖 | 在这些条件、这项标准下通过；不扩成整个工作流有效 |
| 失败教训 | 可定位的违反行为／产物、触发条件、违反标准与识别信号 | 哪种具体行为应避免；不把所有相关祖先动作都禁止 |
| 修订经验 | 已有缺陷、真实修改、被比较要求对齐及新检查 | 这项表现后来得到修正；其他差异及未知保留，不自动声称唯一因果 |
| 改进假设 | 有建议但缺执行／后验检查 | 明确作为设计建议，不冒充历史成功办法 |

用户明确要求是规范依据；它不等于方法已执行。观察到最终正确编号，也不证明助手实际运行了“先检查编号”的内部流程。可以工程建议增加编号检查，但其来源需标为设计建议或新验证，不能伪称从历史观察学到。

## 5．算法一怎样深化：恢复局部证据和作用范围

本项为**设计建议，未实现**。不增加十二阶段的顶层数量，是阶段2／3内部深化。

1. **先建立来源和依赖图。** 固定可靠调用返回、产物版本、显式对象关联；模型提出任务、要求、引用和数据依赖候选，程序联合选择相容结构。当前能力可复用。
2. **在任务内定位可观察局部单元。** 将复合产物拆成分别可核验的声明，保留共同出处；给出对象、有效要求和输入输出。模型不能凭抽象流程补出未观测动作。
3. **建立覆盖矩阵，分配局部判断。** 显式字段、规则和已执行检查优先；语言标准需语义判别或人工依据。程序负责按真实覆盖传播结果，禁止从回复节点一跳到所有方法。
4. **沿依赖回溯相关片段。** 从失败标准找到对应产物及生产／消费链，缩小需分析部分。回溯得到的是“相关依赖”，不是自动确定根因。缺可见坏输入时不能说下游继承了错误。
5. **对已有修订做条件对齐和差分。** 比较同一标准对应的有效要求，而非机械要求整个版本号相等；列出改了哪些局部声明、哪些输入／对象／工具／环境同时变化。多因素变化不作唯一原因断言。
6. **编译三种学习视图。** 有依据的主干、具体失败及修订分支、未决和反证；全部回连原始记录。不同尝试的节点不能被拼成一条从未发生过的执行史。

局部异常检测或PRM可用于排序最需要检查的单元，但不充当真值。当前首先利用已有V、公开C和可见产物，不默认增加每步骤模型调用或通用环境重跑。

## 6．算法二怎样深化：从局部经验归纳有边界的方法

本项同样**未实现**，属于阶段4内部深化。

1. **先对齐方法骨架。** 比较输入输出、对象绑定、步骤依赖、所满足标准及条件；动作名称／主题相似只作候选召回。共享对象编号要参数化，但其前后身份一致性不能删除。
2. **共同步骤形成主干，差异保留条件。** 对齐后的共用方法合并；不同政策、有效要求和结果标准成条件分支。缺少相容依据就不推广。
3. **把失败片段作为有范围的反证。** 一个负例可以反驳覆盖该例的无条件推荐，但不能证明所有同类动作都应禁止。明确违规可由公开规范支持禁用边界；环境失败则需保留环境条件。
4. **条款从证据包编译。** 推荐、警示、修订经验、假设分别引用局部单元，保留必要支持、反证和条件。不是把整个簇再交给模型自由写一遍。

程序应产出“保留必要支持与反证的充分证据包”，不宣称求得数学最小包。依赖闭包检查、覆盖传播、重复经验合并、条件冲突处理和条款支持核对是实际计算职责；语义步骤匹配仍由模型承担并须验证。

这样，改变某条评价的覆盖或撤销某条关系，会明确影响特定方法和技能条款，其余有依据的部分仍保留。这种可追踪变化比新增提示语更接近可检验算法贡献。

## 7．用当前协议案例说明应得到的输出

原案例为构造材料，见[输入](../../enginering/demo/examples/ecv_contract_mixed.json)；沿用既有V，不新增法律判断或实验结果。下表是拟议局部表示，不是代码新产物。

| 局部事实／声明 | 原材料能支持什么 | 应学习的内容 |
|---|---|---|
| 用户要求保留原编号2.1 | 明确有效要求；是规范依据 | 编号保留规则，不叫已执行操作 |
| 旧回复将2.1写为1 | 对应编号评价失败 | 警示“不得擅自把原编号改成新序号” |
| 旧回复提出补验收标准 | 可见有建议，专业质量未验 | 保留观察候选，不继承编号失败 |
| 用户新增表格和待确认项要求 | 改变后续交付要求；没有否定此前文本形式 | 工作流按有效格式要求绑定，不把旧格式判失败 |
| 新回复使用2.1 | 对应编号评价通过 | 限定编号维度的成功实例；不证明全部意见正确 |
| 新回复采用表格及待确认栏目 | 可见产物形式变化；没有格式／完整性独立检查 | 观察候选，相关质量待验 |
| 中途培训通知 | 另一个任务及可见输出，效果未验 | 独立通知方法，不污染协议轨迹 |

供技能生成器阅读的记录应近似下面这样：

```text
任务：按当前立场审查协议；保留条款身份。
要求：采购方立场持续有效；后来从文本改为表格，新增待确认项。

已核局部事实：
  旧版编号2.1被写成1，违反编号标准。
  新版编号2.1保留，通过同一编号标准。
  对法律意见、格式完整性、全部疑点覆盖没有独立评价。

可学习边界：
  原编号是任务约束，不能擅自重新编号。
  本次有编号表现的修正，但不能认定所有格式/内容修改都因此有效。

观察候选：
  输出形式可随用户新要求改变。
  待确认项应按当次要求处理；本记录未证明全部待确认项齐全。

禁止升级的结论：
  不说协议审查方法整体失败，也不说新版专业内容全部正确。
  不补造未记录的内部编号检查操作。
```

真正适合模型归纳的关键是**每条经验已经带有支持条件、反证和未知，生成器不用再次从混杂原话猜对错**。同时保留来源可查；压缩不能删除决定结论的上下文。

## 8．实施应收敛到两件事，不堆技术名词

### 优先一：局部标准覆盖与修订恢复

在现有恢复输出补局部单元、标准覆盖矩阵、观察与推断区分、分维度判定和对照差分。先修正已暴露的m1错伤及m3支持越范围。免费反例只能证明具体计算正确；语义准确需对关键关系作独立标注。

### 优先二：由局部证据约束流程归纳

把覆盖结果和条件真正传入方法对齐、合并及最终条款。保留失败中的有依据方法；不因最后成功就吸收曾违反要求的动作。用多条具有共同方法但不同条件的案例核验合并实际发生，不能再只用单例簇验收聚类效果。

之后如果启用训练，优先训练关系和标准覆盖判别：预测任务／对象／版本、标准覆盖哪个局部声明、满足／违反／未知及修订对齐。不能拿终局reward给所有步骤造标签。PRM或RL的价值目标可作为另一个辅助头，不能替代这些语义监督。

本轮没有授权／执行这些开发和训练。推理预算仍优先缓存、索引、程序传播和已有反馈；必要的语义核验应批处理、记录来源及成本。不能承诺增加局部理解必然零额外资源，须比较全部生成、核验和后续消费开销。

## 9．可主张的研究方向与需要证明的链条

当前更具体的研究问题为：

> 在任务交错、要求漂移和稀疏评价的原始会话中，怎样恢复标准对局部声明的真实作用范围，保留成功、失败和修订经验，并使这些关系约束可复用技能的推广范围？

候选新增在**混合会话关系恢复 → 局部证据归属 → 流程与条款支持**的联动，不能仅说使用了图、PRM、黄金轨迹或正反聚类。同样输入E/C/V也必须给强基线，避免把增加信息误作算法收益。

至少应核对三类机制行为：①只把编号评价移给正确局部声明，其他内容不继承；②发现失败后保留不受该失败反证的有依据方法；③条件或对象改变后，合并和推荐范围按证据变化。随后才验证新任务效果。当前原型尚无相应独立效果证据，本文也没有宣布新方案已经达到投稿要求。
