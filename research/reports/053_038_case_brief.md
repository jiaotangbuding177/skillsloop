# 合同审阅会话如何变成技能：五阶段案例简版

这次选取了同一用户的两段真实会话：一段从**供应商立场**审阅协议，一段从**委托方立场**审阅合同。最终链路是：

**48条原始消息 → 8轮问答 → 2条任务轨迹 → 3套候选工作流 → 3个技能包。**

## 1．会话采集：找到正文，整理成问答

系统先根据索引找到这两段会话，再从原始数据中取回正文，共48条消息，其中8条来自用户、40条来自助手。按顺序整理后，两段会话各有4轮问答。

例如，供应商第一次要求“尽量少改，只处理核心和重大风险”，助手随后连续发了22条进度说明和回答。这22条一起归入第一轮，原文全部保留，没有拆成22个任务。

**这一步得到：8轮能回查原文的完整问答。**

## 2．任务识别、线索标注：判断每轮在做什么，和前面有什么关系

大模型阅读用户和助手的完整问答，提出任务归属及关联线索；程序核对这些判断能否在原文中找到依据。

以供应商会话为例，下表按原意概括：

| 用户这一轮说了什么 | 系统标出的任务线索 |
| --- | --- |
| 站在供应商角度审协议，只改核心和重大风险 | 开始一项协议审阅任务 |
| 第6.4条这样改，对方会不会接受？ | 在原任务中追问某条修改建议 |
| 按折中方案把这一条重新改一下 | 继续原任务，出现选择方案的线索 |
| 不要重新输出文件，只发这一句的修改 | 继续原任务，出现改变交付形式的线索 |

委托方的4轮问答也归到自己的合同审阅任务下。其中，“两个厂区仍会使用原来的处置单位”被识别为补充业务背景的线索。

**这一步得到：8轮问答的任务归属和前后关联线索，共指向2个主任务；这些关联还要交给下一阶段复核。**

## 3．轨迹恢复：把线索串成任务的完整经过

系统复核上一阶段的关联，恢复用户要求、助手尝试、追问和修订的先后关系，形成两条各有4次尝试的任务轨迹。

**供应商轨迹：**

整体审阅协议 → 追问第6.4条修改的可接受性 → 选择折中方案重新修改 → 要求只输出修改文字。

**委托方轨迹：**

整体审阅合同 → 聚焦排他条款 → 补充两个厂区的业务安排 → 重申按该安排修改条款。

例如，供应商最后一句“只发修改文字”被放回前文，系统知道“这一句”指向正在讨论的第6.4条，也知道这是**本次交付形式变化**。助手说过“校验失败”“文件改好了”的过程同样留在轨迹里；由于缺少实际文件和工具回执，只能记为未核实的说法。

**这一步得到：2条包含目标、要求变化、尝试、反馈及可见结果的任务轨迹。** 现有会话已串起，历史文件和业务结果仍未知；委托方末轮重申要求被误升成新版本的问题也保留在验收记录中。

## 4．工作流聚合：把相近经历归并成值得复用的做法

两条轨迹进入同一批轨迹池。模型提炼流程和方法，比较它们的目标、输入输出及适用条件；程序据此聚类、核对来源，再由模型整理成工作流。

本例提炼出5个流程片段、7项做法，实际归并为3套候选工作流：

| 候选工作流 | 从哪些经历聚合而来 | 下次可以复用的过程 |
| --- | --- | --- |
| 合同／协议审阅与修订 | 两条轨迹中的整体审阅过程 | 明确立场和修改范围 → 识别风险 → 形成修订及说明 |
| 特定条款调整 | 委托方补充业务背景后的修改；供应商选定方案后的修改 | 接收新条件或已选方案 → 修改目标条款 → 检查是否满足要求 |
| 单独输出条款修改文字 | 供应商最后一轮的交付要求 | 接收已有修改内容 → 按要求单独输出文字 |

原来“两份不同合同怎么处理”的经历，由此变成“以后遇到同类条件怎么做”的流程，立场和适用条件随方法一起保留。

**这一步得到：3套写清输入、步骤、适用条件和预期输出的候选工作流。** 高价值是筛选目标，当前还不能说三套都已证明有价值；尤其第三套可能只是前两套的输出分支，独立成技能是否必要仍待验证。

## 5．技能封装：把工作流写成后续代理能使用的技能

三套工作流分别交给真实模型代理，按技能封装指南写出：什么时候使用、需要什么输入、按什么步骤做、怎样检查完成、有哪些限制。程序核对方法是否完整写入，再用官方工具打包。

最终得到三个技能候选：

1. **合同／协议审阅与修订**：包含4项审阅和修订做法。
2. **特定条款调整与文件更新**：包含2项结合业务背景或选定方案调整条款的做法。
3. **特定条款修改文本单独输出**：包含1项文字提取与格式整理做法。

**这一步得到：3个已通过结构和封装检查、等待个人采纳的技能包。** 目前每包只有技能说明；实际文件编辑和新任务效果尚未验收，第二包正文仍要求用户自行写回文件。

本简版按最终链路说明过程。本次曾经历失败与修正，最后复用了已保存的真实模型回答完成验收；运行历史见[正式验收报告](051_targeted_first5_acceptance.md)，原始阶段产物及技能正文见[详细案例文档](052_038_first5_case_walkthrough.md)。
