# SkillsLoop：从现有数据到实验指标与研究证据

实验规划摘要｜2026-09-27｜正文7页＋指标与文献附录

**当前前提：你能提供企业原始会话，但没有人工任务标签、方法参考答案或统一业务验收。**本方案保留C1轨迹恢复、C2工作流选择与技能蒸馏、C3复用与持续演化三条主线，不把“已有数据”写成“已有标准答案”。[D1]

**不必先标注全部会话再开始研究。**原始企业会话用于学习和真实分布分析；公开标签用于恢复正确性测试；公开可执行任务用于技能效用和演化测试。企业真实准确率、方法漏学率、工时节省等结论，需要另外的小规模独立参考或真实使用记录。

# 1．原始会话如何变成可评估的数据

先分清“学习材料”和“判断对错的依据”

## 1.1 企业原始数据先做整理，不要求你补整库人工标签

保留消息正文与角色、原始顺序、会话来源，以及实际存在的用户／团队标识、附件和工具记录。按“一条用户消息＋下一条用户消息前的全部助手回复”整理问答；只有文件名或消息编号时，不补造正文和执行结果。缺少稳定用户标识，就只能做会话级实验，不能声称跨会话个人学习。[D1；D3]

先冻结学习、开发、测试用途，再运行方法。企业主协议按时间留出后续工作；同一任务及同一文档的连续修订不能一部分用于生成、一部分伪装成独立新任务。无法判断是否重复的样本单列。任务族可以跨期出现，这是复用的目标；同实例泄漏与同类新实例应分开。

**粒度约定：同一具体工作的碎片在C1恢复；同族但不同实例在C2聚合。**研究定位文件中“同任务族拼接”的措辞有歧义，本方案采用契约中“同实例恢复、跨实例归纳”的口径，不把两个独立交付算成同一任务。[D1；D4]

## 1.2 没有人工标签，不等于没有任何可用评价

| 判断依据 | 能得到什么 | 不能据此声称什么 |
| --- | --- | --- |
| 公开数据已有人工标签 | 对照公开线程、回复边计算F1 | 企业自然会话也达到了同样准确率 |
| 公开任务的结果检查器 | 新执行的文件／程序通过率和成本 | 所有业务要求都已覆盖；真实用户工时已节省 |
| 程序构造时保存的来源和条件 | 构造交错的任务归属；明确条件的遵循 | 自动知道自然会话的真实归属与全部方法 |
| 另一个模型的评审 | 来源支持度、偏好符合度等代理评分 | 模型共识等于人工真值或业务正确性 |
| 少量独立复核／真实使用 | 企业任务、方法与交付的可信局部参考 | 少量样本足以无条件代表整个企业 |

## 1.3 本方案提供两条路线

**路线A：暂不新增人工标注。**先做E0、公开／构造E1a、可执行E1b与E3，再做E2a的代理评价和E2b的受控适配。结果分别标为“公开测试”“受控构造”“模型评审”，不能合成一个企业准确率。

**路线B：在路线A上补小规模评价集。**不是标全部数据；随机抽取一小批完整会话窗口，独立核对任务归属、关键关系与可复用方法，再对少量新任务验收。优先标评价集，不将人审任务线索提供给被测系统。

模型可以先帮助起草开发标注，但正式核验应避免只改本方法的输出；模型评审要随机化候选顺序、隐藏方法名、允许平局并报告分歧。换一个模型仍不自动获得真值。相关评审研究已指出位置、冗长和自我偏好等偏差。[P20]

# 2．E1a：没有企业标签，怎样评价轨迹恢复

C1：逐对识别与非连续任务恢复

## 2.1 公开标签实验：先确认恢复算法本身是否可靠

**数据：Ubuntu IRC人工标注部分。**作者仓库区分人工标注数据与自动解交错语料；只把前者当参考。原样保留公开任务的消息单位和评分协议，隐藏参考连接与线程标签，不强行把多人聊天配成企业问答。[P1；P2]

**实验：**同一测试输入，比较连续分段、完整上下文强模型、通用回复连接／线程恢复、SkillsLoop恢复。使用相同历史访问机会和可比预算。需要适配的中文或问答机制单列，不能拿未适配的英文模型失效当创新证据。

**指标：**同任务／同线程Pair-F1（M02）、连接F1（M03）、ARI／VI（M04）、非连续接回（M05）、完整trace精确匹配（M06）、成本（M37）。公开回复标签不自动等于方案选择和修订关系标签，因此不能直接报企业关键工作关系F1（M07）。

## 2.2 受控交错实验：已知来源，测“做别的工作后再回来”

从公开已标线程，或具有已知任务身份的独立运行中取片段；保持每项任务内部顺序和依赖，把A1、A2、B1、A3、B2等交错排列。构造程序私下保留来源标签，去掉人工线程编号、目录命名等额外答案线索。测试增加同主题不同对象、不同间隔和多个未结束任务。

**不能把任意企业session直接当成一个真任务再混排。**它本身可能包含多个任务。公开工具动作也不能随意改成用户问答；多轮用户请求若由脚本或模拟器产生，要标为构造数据。只有脚本明确规定并核验的关系，才有构造关系答案；单有任务来源不足以生成M07全部标签。

**指标与结论：**M02／M05／M06测受控条件下的抗交错能力；改变间隔后比较下降幅度。结果不能外推为自然企业交错准确率。还可固定后续蒸馏器，在相同来源“正确分组／交错恢复”下比较新任务效用差（M19）。

## 2.3 企业无标签实验：只能先做运行检查和代理审查

**数据：全部合格原始会话，不只抽成功或关键词命中的案例。**目前可直接记录M01逐对覆盖、待定量、引用能否回查及处理成本；用独立模型检查归属和关系时，结果称“模型评审通过率／分歧率”，不能称任务准确率。

实际系统中的task号、replyTo若可靠，可以评价其覆盖子集；共同文件或同一session只作为线索，不能当完整任务真值。要报告企业M02、M05、M07，需要小规模独立复核；否则保留为待测。

**本实验要支持的判断：C1不仅处理了每一对，还能在有真值的测试上找回同一工作的片段；自然企业效果由另一条证据补充。**不把公开分组F1、企业覆盖率和模型一致率混成一个数字。

# 3．E1b：没有方法标注，怎样评价选择性技能蒸馏

C2：先判断哪些工作流值得生成，而不是每条trace都生成

## 3.1 采用有真实运行和结果检查的公开任务

优先用SkillFlow的办公任务族或SpreadsheetBench；用公开学习子集执行固定Agent，记录真实请求、操作、输出和允许的反馈。所有比较方法先共享同一批来源轨迹，然后分别聚合、选择和生成技能，再到互不重叠的独立任务中使用。[P5；P12；P18]

**具体链路：公开学习任务 → 固定Agent运行 → 共同轨迹池 → 不同生成方案 → 独立新任务运行 → 原生检查器评分。**使用真实输入文件，不将官方参考解、测试脚本、测试答案或测试用精选技能交给生成器。任务族标签只用于划分和分析；若把它直接给聚类器，必须单列“已知任务族”条件。

| 同一轨迹池上的方案 | 主要检验什么 |
| --- | --- |
| 逐轨迹生成；同池强批量归纳 | 直接生成与强提示是否已经足够；允许强基线输出零到多个技能 |
| 普通语义聚类＋共同生成器 | 是否只是主题分组起作用 |
| Trace2Skill适配；预算允许补AWM／GSE | 与已有经验合并、工作流抽象和回放验证比较 |
| SkillsLoop生成前选择；全部生成后再同等筛选 | 是否把选择前移后降低开销，且未牺牲独立任务表现 |

**先报：**新任务原生成功率及差值（M19／M21）、生成数量和总长度（M18）、结构／加载通过率（M17）、总成本（M37／M38）、质量—成本曲线（M20）。C2没有源方法真值，也可以通过独立任务收益证明其整体价值，但不能因此宣称已精确测出所有漏学。

## 3.2 两类“覆盖率”不能偷换

**来源方法覆盖率MC（M10）**需要从原始材料独立建立的方法参考；当前企业数据没有它。公开任务的参考解也未必是唯一合法流程，不能把照抄参考解当覆盖。可以补小规模方法核验；不补时只报独立模型形成的“代理方法保留分数”，并明确它可能遗漏方法。

**Skill Coverage（M30）**检查已经写进技能的行为是否被执行覆盖。它能发现技能写了但没被测试到，却找不到生成时根本没有写进去的方法。工具能辅助评价，不能替代MC。[P10]

## 3.3 “少而有用”的可检验证据

选择前移后，生成成本／技能负担更低，同时独立新任务通过率达到预先设定的非劣要求或提高，才支持“更值得”。仅仅不显著下降，不等于已证明不退化。无技能、无生成的基线必须保留，以排除“其实完全不生成就够了”。

没有独立任务数量和语义审查时，企业M13不能用模型恢复的任务数作分母来宣称“每100任务无效候选”。临时可报“每千原始问答生成量／格式失败量”，但必须改名，不能当语义无效率。低频重要方法M11仍需业务依据。

# 4．E2：企业历史能否帮助个人与组织的新工作

把企业适配价值与公共任务通用能力分开验证

## 4.1 E2a：企业后续请求的离线重放

用同一用户较早会话生成个人技能、偏好摘要和历史检索库；冻结后，取较晚的独立请求。只向执行Agent提供该时点实际可用的请求、必要上下文和附件，不能把未来助手答案、后续纠正或本次最终稿提前给它。各方案在全新的隔离工作区、相同工具和预算下执行。

**对照：**无新增技能、同历史强生成技能、通用工作指南、个人偏好摘要、历史片段检索、AutoSkill适配、SkillsLoop。先固定技能库测内容价值，再测完整库里的自动发现与读取，避免把“知道该用哪个技能”当成默认条件。[P11；P21]

**无新增人工时能得到：**预先可编程要求的通过率、结构与产物可用性、独立模型给出的要求符合度和配对胜率、实际机器成本。语义评分称“LLM评审”，不要直接称真实个人满意度或企业DSR。历史最终答案只能提供讨论线索，不能自动作为正确答案。

**重放资格必须在运行前确定。**缺少原合同的请求不能证明真实合同修订；它可用于C1和文本交互研究。另准备公共／构造文件的测试，标为改编实验，不替代原合同验收。报告全部候选请求中有多少具备可重放条件，不能只挑成功运行的样本。

## 4.2 E2b：可自动检查的个人／团队差异实验

从公开任务选择材料完整的实例，独立设定可检查的工作要求，例如“固定模板栏目”“引用标注方式”“修改区域外保持不变”。在学习期的构造交互中表达这些要求，再用新文件、新内容评价；也设置当前请求明确改变旧习惯的反例。要求必须先确定、与任务相容，不能由生成技能自己定义评分标准。

**指标：**构造条件下的适用要求符合率（M24）、相对通用／摘要基线的适配增益（M25）、原任务验收分数和产物完整性（M21）。生成器和各基线获得相同历史机会；企业强制规则应当共同提供。多人汇总历史更多时另做等量／等长度控制。[P11]

**可支持：**方法能够从历史要求中学习并在明确的受控范围内复用。**不可直接支持：**真实企业用户更满意、真实团队已经受益、减少了多少人工时间。模拟角色不等于真实成员；没有可靠团队标识和授权就不报组织结果。

## 4.3 怎样把“个性化有价值”写成证据，而不是愿景

公开任务给出可重复的行为与产物证据；企业后续请求给出真实分布上的初步适配证据。要升级为企业DSR、真实返工减少和跨成员收益，需要独立业务验收及针对当前新输出的真实反馈。M27所有追问不等于M28纠错返工，二者不能混算。

**禁止跨域偷换：**企业合同历史生成的技能在不相干表格题上表现，不能直接证明企业个性化有效；公共数据应沿用相容工作方法，或作为独立算法补充实验。

# 5．E3与实施顺序：先做可验证的迭代，再补企业实证

C3：下一项工作是否受益，旧能力是否受损

## 5.1 E3：从公共任务序列启动，不需要企业人工标签

采用SkillFlow任务和检查器。其原协议按任务族顺序演化、跨族重置；论文报告任务成功、成本、技能数量与复用。你的长期共享库或额外保持集属于扩展协议，应与原协议分开报告。[P12]

各分支从同一初始库开始：冻结库、周期强重写、AutoSkill／SkillClaw式更新、SkillsLoop更新。每次先运行当前题并锁定结果，再释放允许的反馈并更新，下一题才测迁移。反馈应针对各自真实输出；不能机械复用历史用户对旧回答的纠正。[P13；P21；D5]

同时预留独立保持集，检查旧版成功→新版失败（M33）和旧版失败→新版成功（M34）。保持集结果只供评价，不回灌更新器；任务太少不足以兼顾学习和审计时，应补独立实例或缩小结论，不能反复调同一批测试题。主要结果是累计相对冻结收益（M32）和全成本，而非升版次数。

## 5.2 当前条件下，建议按这个顺序开展

| 顺序 | 要做的实验 | 交出的研究证据 |
| --- | --- | --- |
| ① 原始数据与环境检查 | E0；公开任务环境冒烟测试 | 原文完整性、配对覆盖、依赖与费用记录；不报语义准确率 |
| ② C1基础与受控压力 | E1a：公开人工标签＋有标签的构造交错 | 任务与连接F1、返回能力、恢复成本；明确适用数据域 |
| ③ C2与实际技能价值 | E1b：共同来源记录→不同筛选→独立新任务 | 成功率差、质量—成本权衡；去选择与先生成后筛选消融 |
| ④ 企业适配与持续演化 | E2a代理＋E2b受控；E3公开序列 | 适配的初步证据、累计收益、退化与成本 |
| ⑤ 按最缺的结论补证据 | E4：小规模独立参考／真实用户任务 | 企业C1与MC；真实交付、个人／组织收益和主动人工时间 |

## 5.3 小规模补证不等于标注整个企业库

先用少量随机会话校准尺度，同时补抽长间隔返回、同主题不同对象、无可复用方法和低频重要流程。挑战样本与随机样本分开统计；不能只挑模型分歧例后外推总体准确率。参考方法在看候选前建立，允许多种正确流程，不规定必须生成几个技能。

样本规模根据先导差异和用户／任务相关性确定，不预填“标几十条就足够”。预算只够模型评分时，保留代理结论；多模型一致、引用格式合法和自洽均不代替独立参考。

**共同统计规则：**同任务配对比较；重复运行先在任务内平均；按用户／任务族等真实独立单位计算区间；失败成本保留、未知值不填零、空分母为N/A。统计全请求中的验收覆盖。真实人工工时只由实际计时获得，不能从缺失时间戳或模拟回合推算。
