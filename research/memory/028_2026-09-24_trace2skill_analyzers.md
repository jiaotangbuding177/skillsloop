# 028｜Trace2Skill 是否微调及成功／失败分析器定义

日期：2026-09-24。

## 用户问题

Trace2Skill 是否进行模型微调；成功分析器和失败分析器究竟是微调后的模型，还是程序处理算法。

## 已确认观察

1. Trace2Skill 固定 agent 参数 `θ`，通过技能演化函数修改技能文件，不更新模型参数。论文形式化目标是 `S* = E(S0, D_evolve; πθ)`，变化的是技能目录 `S`。
2. 同一个 `πθ` 可以作为轨迹生成器、分析器和合并算子，不要求额外 teacher model。
3. 成功分析器 `A+` 和失败分析器 `A-` 是同一 LLM agent 在不同提示词和流程下承担的角色，不是两个微调模型，也不是纯粹的传统规则程序。
4. `A+` 对成功轨迹单次分析，寻找可复用行为模式；`A-` 使用 ReAct 式流程检查轨迹、工具产物和目标，验证候选修正。无法因果解释的失败不进入 patch 池。
5. 后续 merge operator 由 LLM 层次合并 patch，文件应用带确定性路径、冲突和格式防护；这不是模型权重更新。

## 对本项目的意义

- 单次调用 skill-creator 写一个新 SKILL.md，不等于 Trace2Skill。
- 若本项目增加逐轨迹 patch 提议、patch merge 和 apply，可以称借鉴其核心机制的适配；仍不涉及模型微调。
- 失败经验必须保存原因、修正依据和验证证据，不能只把 FAILURE 标签交给模型总结。

[Trace2Skill v5 原文第2节](https://arxiv.org/html/2603.25158v5#S2)及其第4节分析。本轮无新增企业实证。
