# 2026-10-06：Trace2Skill 官方源码核查与单主题试跑方案

## 用户已确认要求
- 用户希望在 Trace2Skill 上试跑一个类别的数据，看效果；先调查是否有源码并汇报方案。
- 本轮仅方案，不把此前局部开发／验收授权延伸为克隆、安装或新模型实验授权；默认科研模式。
- 固定企业自然历史、未知正常候选、减错学和完整成本、冻结复现要求持续有效。

## 证据支持的观察
- 官方仓库为 https://github.com/Qwen-Applications/Trace2Skill ，论文 arXiv 2603.25158。公开重点为表格；官方补丁／分层合并可从保存的经验 JSON 开始，不必重新采样过去的任务。
- 除验证型失败分析，仓库还提供单次 LLM 日志失败分析；缺文件不等于不能学习。原成功／失败入口并不原生支持未知任务结局；成功提示预设首条用户=单任务及最终成功。
- 官方组合应用入口检查固定 quick_validate.py 路径；在线对应路径未读取到，须固定 commit 后核全树并处理。项目已有 OpenClaw 检查器，但版本／兼容未核验。只看不写模式仍调用模型。
- DATA 类 43 个候选来自 43 父会话，但非纯电子表格。8 个相关种子全在最新 blind model_inputs，681 消息／278042 字符；两条长会话占552／247439。
- 首轮建议另6条：129消息／30603字符，20文件元数据引用、11工具记录ID。无附件字节，整任务成功均unknown，真实时序未认证；不是可执行成功轨迹或黄金集。
- 来源：research/datasets/evomind/task_topics_20261006/private/model_inputs.jsonl；候选目录仅选样盘点，不作模型答案输入。种子跨会话主主题，按编号全量抽取而非只读 DATA 会话分区。

## 建议及研究假设
- 建议窄主题“表格生成与核验”，首批6完整会话；2长会话留作下一批共同窗口协议，不能截尾或直接承诺当前恢复器能处理。
- A整会话→共同企业分析适配→官方Trace2Skill；B同证据→只做任务／关系恢复→同一官方下游；C同初始弱技能不学习历史。B不加我方workflow聚合，便于归因恢复。
- 未知经验须有中立入口和补丁提示适配并公开差异，不能塞入成功/失败渠道伪标签；保留作者补丁结构／分层合并／程序应用，称“官方核心＋历史输入适配”，非原论文完整复现。
- 拟构造6独立表格任务，固定OpenClaw消费器，3组共18任务执行（非18API请求）；考察可消费性、新增条款错学、新任务完成数、全成本。测试文件与答案不得进入历史学习。
- 假设恢复能减少混淆，尚无本轮收益证据；初始一轮一个种子，预算付费前冻结，失败不临时改提示混入同run。
