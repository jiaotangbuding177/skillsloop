# 轮次 011：复用已有表，收敛新增模型建议

日期：2026-09-20。

## 用户要求

用户针对此前三个新表提出能否复用已有表。将此视为方案取舍讨论，不视为已授权改 schema 或运行迁移。当前源码范围与科研模式不变。

## 工作与依据

读取 README、CHARTER、STATE、009／010 记忆和 010 方案；核对 ZclawSession／ZclawMessage、Observation、AnalysisSnapshot、Cluster、Candidate 的当前 schema，以及快照 upsert 和到期清理。FastCtx 仍报 Transport closed，使用只读 shell 查询兜底。

产物：[数据层复用建议](../reports/011_reuse_existing_tables.md)。在 010 方案顶部和第 6 节追加更正入口，保留原建议及历史依据。

## 观察与建议

观察：已有消息与工具载荷、观察处理和快照存储，可复用。Observation 双消息必填，Snapshot 目前一对一关联 Observation 并级联删除；不能不改契约就容纳失败和多回合任务修订。Cluster 是企业任务类，Session 是会话，均不等同于任务实例。

建议：完整首版从三个新表收敛为一张 TaskInstance；Observation 承接采集，AnalysisSnapshot 扩展为区分旧样本与追加式任务修订。现有候选、作业、个人／企业库和版本继续复用。仅阶段 A 的采集改造可以零新表。完整零新表也可通过 Snapshot 逻辑 taskId 和 revision 表达，但当前状态查询、一致性及并发更复杂，不列为首选。

这是一项工作建议，尚未经用户最终选定。用户明确的是质疑新增表必要性，不是同意“一张新表”。更正此前将三个逻辑对象直接映射成三张新增物理表的过强建议。

## 边界与后续

未新增算法假设或有效性结论。本轮无新增运行实证发现；没有修改业务源码、数据库或 MCP 索引。生产兼容迁移成本、现有数据量和删除策略待开发授权后核验。少建表不自动等于改动小，Snapshot 的唯一约束、读写逻辑、清理和保留都必须同步设计。
