## 观察：有源码支持，不是生产实证

- 完成入口排除选 skill 回合；Recorder outcome 默认 SUCCESS。消息总数来自整个 session，学习样本却是一对问答。
- 工具活动已持久化；应接入现有工具记录，不需要重建全部遥测。
- Cluster/workflow 为企业级，候选门禁使用个人 observations 与 Progress。纠正早期混淆建模阈值与个人候选阈值的表述。
- 工作流提示词、输出规整与 Gate 期待的分支／工具／价值字段存在接口差异；频次可单独放行；Evaluator 传 isDuplicate:false。
- 已建模 cluster 接收新 observation 不自动重新建模；数量水位与滚动窗口可能漏识别新证据，也不能标识同任务修订。
- 快照可以被 upsert 改写；指纹阶段回查原消息，路径阶段优先读快照。
- 有作业幂等／租约／重试、个人 revision、组织版本，可复用。
- 候选封装先产生真实个人文件后隐藏配置，采纳主要改变可见性；同 key 更新存在先写文件风险，尚未复现生产事故。
- draftFilesSnapshot 有模型字段，但本轮 API 搜索未找到主流程写入，不能视为已实现独立草稿。
- skill 选择、正文加载、实际执行应分开；固定 savedHours 不是实测收益。
- 组织文件分发与数据库事务分步完成；组织提交依赖前端多请求。

完整路径与行号见报告第一节。

## 建议，未经实施或用户逐项确认

- 复用原库、调度、候选和作业；新增轻量事件、任务实例、不可变轨迹修订三个核心模型。
- 同用户／企业／会话优先关联，跨会话仅凭明确依据；任务频次按 taskId 去重。
- 运行完成不作为业务成功；失败、取消、使用 skill 的任务都留证，内部生成会话不计需求。
- NEW／UPDATE／SUPPORT／PREFERENCE／DIAGNOSTIC／DEFER／IGNORE 分流。
- 候选绑定证据集合与基准版本；新证据刷新 workflow；草稿隔离后再开启更新。
- 四阶段：A 记录事实 → B 整理任务 → C 候选质量与安全采纳 → D 使用后演化和组织发布。
- 每次使用形成观测，无新增可信信息不强制生成版本。
