# 054 个人使用后技能进化：单例协议

本轮验证的问题：已经生成的技能能否真正被Agent读取；同一会话里的使用与修改意见能否再次形成完整轨迹，自动归到该技能的精确旧版本，形成有出处的更新候选，并由个人采纳后再次使用。

## 固定材料与边界

- 起点：051 run05 的第三个技能“特定条款修改文本单独输出”，不是本轮手工新写技能。原实验库只读。
- 新输入：研究人员构造的文本整理任务，没有真实合同附件，不验证法律意见。
- 首轮只要求按原技能整理三个指定条款；第二轮通过普通会话表达长期个人格式偏好：多条保持原编号且每条独立代码块、不要额外说明、不改变字词金额。不会预先要求首轮按这个隐藏偏好输出，也不会强迫首轮失败。
- 反馈用于当前答复修订，也作为可复用个人偏好。未知业务效果保持未知，不把助手回复当用户验收。
- 更新仅进入个人候选，使用既有采纳API提交为下一版本；不发布组织库。

## 处理链

导入已验收候选及必要来源记录 → 个人采纳v1 → 新任务真实消费 → 同会话自然反馈与修订 → 阶段1—3恢复轨迹 → 阶段4形成带出处的方法/workflow → 阶段9按真实读取回执锁定技能版本 → 现有证据补丁执行器局部修订并官方封装 → 个人采纳v2 → 新会话无重复偏好提醒的迁移探针。

源码审查发现新版UPDATE工作流原来停在冻结处。本轮只补通stage9交接、精确版本/来源校验和个人库更新候选可见性，复用现有表、补丁编译器与creator打包器；不将新轨迹压回旧规则识别链路。

## 验收与停止条件

1. v1、v2真实读取回执，完整会话、反馈边、轨迹和方法出处都保存。
2. UPDATE必须对应同一技能的v1/hash；不额外生成NEW技能，不丢原包文件。
3. 更新内容有用户反馈依据，并将个案数字/名字排除出通用规则。
4. 探针使用不同条款编号和内容，不重复偏好、不携带旧会话；检查编号、原文字词、独立代码块和无额外说明。
5. 不保证产生更新；已有规则足够可SUPPORT，证据不够可DEFER。只表示完成单例通路，不等于证明总体质量提高。
6. 最多10次新外层派发（常规3次消费+2次前端分析+2次workflow+1次补丁，余量为冻结前明确追加的探针），内部agent请求和tokens如实统计。失败不自动重发、不边跑边覆盖旧结果。必要修正须新运行版本，先保留失败。
7. 先冻结代码与提示，再执行；保存每步结果。后续另以相同新探针、v1/v2固定条件对比，仅在需要判断增益时追加，不把同分解释为收益。

## 结果解释

运行修订（run01已终止，run02开跑前登记）：run01首次消费发生真实技能读取，第二次模型请求HTTP200后未在300秒内完成，宿主超时终止。保留整个run01，不继续该库；不能计作技能能力失败。run02显式设置OpenClaw已支持的thinking=off、deadline=600秒，其他任务/反馈/验收标准不变。新增一个可选运行参数，不改变默认配置；run01的1次外层、2次内部请求另计。本轮总外层上限因此为11，run02仍最多10。两版本不得合称首次运行一次通过。

本例能回答“使用会话是否成为更新经验”的机制问题。即使v2遵守偏好，也不能用一例宣称优于不使用技能、减少人工时间、降低无效技能比例或具备论文创新。若v1也遵守相同格式，只能确认经验写回与再执行，不能证明能力提升。
