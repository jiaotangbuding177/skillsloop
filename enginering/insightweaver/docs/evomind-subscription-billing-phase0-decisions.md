# EvoMind C/B 端套餐与权益批次 Phase 0 决策记录

## 背景与目标

本文是 `docs/evomind-subscription-billing-design.md` 的 Phase 0 决策冻结记录，用于把后续 Phase 1 数据模型设计必须依赖的概念先固化下来。

Phase 0 只做概念冻结和验收口径确认，不落地代码、不修改数据库、不运行 migration、不实现 API，也不修改现有充值积分系统。

本记录同时参考 `docs/evomind-consumer-enterprise-migration-plan.md` 中的默认企业化约束。套餐与权益批次设计必须与 C 端默认企业改造保持一致，后续新设计不得继续引入空 `enterpriseId`、`-1` RagFlow、默认空间 personal agent 等旧口径。

Phase 0 的完成标准是“概念冻结可审查”，不是功能可运行。

## 冻结决策

### 企业类型

企业类型枚举固定为以下三类，Phase 1 不另起命名：

| 枚举 | 语义 | 套餐能力 |
| --- | --- | --- |
| `b2b` | B 端企业，真实客户组织 | 只能购买 B 端企业整体方案 |
| `consumer` | 普通 C 端企业 | 企业下用户身份购买 C 端主月包和充值包 |
| `evomind_consumer` | 平台唯一默认 C 端企业 | 用户侧展示为“个人空间”，底层承载个人空间权益 |

EvoMind C 端企业必须唯一。后续 Phase 1 使用固定默认企业身份承载个人空间权益，但用户侧不把它展示为普通协作企业，也不开放普通企业组织管理语义。

企业类型必须进入后端校验、后台配置约束和权益计算流程，不能只靠前端展示区分。

### 权益归属

权益归属固定为两类：

| 归属类型 | 最小归属键 | 适用场景 |
| --- | --- | --- |
| 企业整体权益 | `enterpriseId` | B 端企业方案、企业共享空间、企业整体 token 池 |
| 企业用户身份权益 | `enterpriseId + userId` | C 端主月包、C 端 token 充值包、C 端空间充值包、EvoMind 个人空间 |

C 端权益禁止只按 `userId` 归属。同一用户可能同时拥有 B 端企业身份、普通 C 端企业身份和 EvoMind 个人空间身份，各身份之间的余额、批次、订单和消费流水必须互不串用。

### 计费口径

新体系不再扩展积分模型。套餐配置、用户侧余额展示、冻结、扣费、释放和流水统一使用：

- 计费 token：按系统当前 token 转换比例从上游原始 usage 换算后的 token。
- 空间容量：以 bytes 作为存储口径，前端可按单位展示。

套餐里的 `tokenLimit`、充值包里的 `tokenAmount`、AI 任务固定冻结的 `100000` 都是计费 token，不直接使用模型厂商返回的原始 token。

订单、权益批次和流水必须保留足够快照信息，避免后续 token 转换比例调整后历史账务无法解释。

### C 端主月包

C 端主月包按同一 `enterpriseId + userId` 单队列排期：

- 同一 `enterpriseId + userId` 同一时间最多只有一个 active 主月包。
- 同一 `enterpriseId + userId` 可以存在多个 scheduled 主月包。
- 当前 active 主月包不被新购买打断，不做立即升级或立即降级。
- 购买同级或低级主月包时，排到当前队列末尾。
- 购买高级主月包时，高级主月包插入下一个可用周期；所有尚未开始且等级更低的 scheduled 主月包整体后移。
- 已开始的 active 主月包不重排；已过期的 expired 主月包不重排。
- 不同企业身份的月包队列互不影响。

主月包到期后，未使用 token 不结转；基础空间容量回落。容量回落不删除文件，但禁止新增或增大文件，直到实际占用不再超额。

### C 端充值包

C 端充值包分为 token 充值包和空间充值包，二者都依赖有效主月包：

- 购买充值包时，当前 `enterpriseId + userId` 必须存在有效主月包。
- 主月包有效时，未过期充值包可用。
- 主月包过期后，未过期充值包继续倒计时，但暂停可用。
- 重新购买有效主月包后，未过期充值包恢复可用。
- 充值包自身过期后，剩余额度清零，并写入过期流水。

展示层可以把充值包显示为“暂停可用：缺少有效月包”，但账务计算必须以依赖条件是否满足为准。

### 0 额度初始化

新用户、未购买套餐用户或无有效套餐用户的默认权益为：

```text
0 token
0 storage
```

0 token 和 0 storage 是正常业务状态，不是系统异常。用户仍可进入入口、购买页或受限工作台。

受限工作台允许查看、下载、删除、查看历史记录和续费；禁止发起 AI、上传、新建、复制、编辑后变大、知识库同步新增存储等会增加 token 或空间消耗的操作。

不得继续用历史默认 10G 或默认积分作为新用户兜底。如果需要历史兼容，必须通过独立灰度配置或迁移批次表达，不能隐式写入新体系。

### AI 任务冻结与无欠费

AI 任务一期固定冻结：

```text
FIXED_TASK_TOKEN_HOLD = 100000
```

规则固定如下：

- 每次 AI 任务启动前，按当前企业空间身份尝试冻结 `100000` 计费 token。
- 可用计费 token 小于 `100000` 时，拒绝启动任务，并引导购买主月包或充值包。
- 任务完成后，先把上游原始 usage 换算为计费 token，再进入 capture/release。
- 真实 usage 小于冻结额时，capture 真实 usage，release 剩余冻结。
- 真实 usage 超过冻结额时，只 capture 已冻结额度，记录 overrun 异常，不追扣成负数。
- 任务失败且无 usage 时释放冻结；任务失败但已有 usage 时按真实 usage 和冻结上限结算。

新体系禁止负数 token。任何并发扣减、重复回调、重复结算、过期清零和人工调整都必须通过事务锁、条件更新、幂等键和流水审计防止余额扣成负数。

### 幂等、任务记录与追加日志

所有任务、冻结、capture、release、过期、退款、后台发放和补偿必须幂等。

Phase 1 需要围绕以下审计链路建模：

- 任务主表：保存任务当前状态、冻结额度、已 capture、已 release、usage 快照、overrun 标记和最近错误。
- 任务事件表：追加记录任务启动、冻结成功或失败、上游调用、usage 回填、结算、失败、重试等过程。
- 权益流水表：记录批次余额变化，包含 before/after、变化类型、引用对象、幂等键和操作人。

不能只在单条业务记录上反复 update 状态来覆盖历史过程。

## 明确不做

Phase 0 不做以下事项：

- 不修改 `packages/db/prisma/schema.prisma`。
- 不新增或修改 migration。
- 不修改后端、前端、测试或 seed 文件。
- 不运行 Prisma generate、migrate、build 或测试。
- 不实现套餐、订单、权益批次、流水或任务表。
- 不实现 consumer membership 接口。
- 不创建 EvoMind C 端企业真实 ID。
- 不迁移历史积分、充值订单、默认空间、RagFlow 或 personal agent 数据。
- 不设计具体 UI 视觉。

## Phase 1 输入约束

Phase 1 数据模型设计必须按本记录建模，至少产出以下模型或等价结构：

- 企业类型字段：支持 `b2b`、`consumer`、`evomind_consumer`，并支持默认企业唯一性约束或校验。
- 套餐表：支持 B 端企业方案、C 端主月包、C 端 token 充值包、C 端空间充值包及其企业类型限制。
- 订单表：统一支持套餐订单，拆分支付状态和权益发放状态，并保存套餐快照。
- 权益批次表：表达来源、归属主体、有效期、剩余额度、冻结额度、状态和订单关联。
- 权益流水表：表达发放、冻结、capture、release、过期、补偿、退款和人工调整。
- 任务主表：表达 AI 任务冻结、运行、usage、结算和 overrun 当前状态。
- 任务事件表：追加式记录任务生命周期。

Phase 1 必须明确以下兼容边界：

- 现有 `RechargePackage`、`RechargeOrder`、`CreditLedger` 是历史积分充值体系，不作为新套餐订单主模型继续扩展。
- 现有企业 token quota batch 可作为后续权益批次设计参考，但需要重新区分来源、订单快照、有效期、归属主体和流水。
- 默认企业化相关旧口径，如空 `enterpriseId`、`-1` RagFlow、personal agent，不在 Phase 0 解决，但 Phase 1 设计不得继续引入这些口径。
- 历史余额如需迁移，必须生成 `migration_grant` 或等价来源的权益批次，并写入流水；禁止直接改余额。
- 后台预配置、试用、补偿和人工开通都必须进入批次和流水，不允许无流水直接改总余额或批次余额。

## 验收清单

Phase 0 文档验收必须覆盖以下冻结项：

- 企业类型：`b2b`、`consumer`、`evomind_consumer`。
- 默认企业唯一性。
- 个人空间展示语义。
- 权益归属：`enterpriseId` 与 `enterpriseId + userId`。
- C 端主月包单队列排期。
- 高级主月包插入下一个周期，未开始低级 scheduled 月包整体后移。
- C 端 token 充值包和空间充值包依赖有效主月包。
- `0 token`、`0 storage` 初始化。
- `100000` 计费 token 固定冻结。
- 计费 token 口径。
- 无欠费和禁止负数 token。
- 任务幂等、任务事件追加日志和权益流水。
- Phase 1 输入模型清单。
- 历史积分体系和默认企业化旧口径的兼容边界。
