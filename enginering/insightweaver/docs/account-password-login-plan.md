# 账号密码登录与超管账号管理方案

## 背景与目标

当前系统主要依赖手机号短信验证码登录。为了支持更稳定的账号登录方式，需要新增手机号密码登录，并允许用户在登录后创建或修改自己的密码。同时，为了处理用户忘记密码、账号禁用、平台超管重置密码等账号级操作，需要把“密码管理”从组织成员管理中拆出来，放到平台超管的账号管理能力中。

本方案只规划账号级密码能力，不改变组织成员管理的边界。组织管理员不能修改成员密码，因为同一个用户可能同时属于多个组织，密码属于全局用户账号，不属于某个组织成员关系。

## 现状确认

### 登录与用户模型

- 当前登录页是短信验证码登录。
- 后端 `AuthService.verifySms` 会通过手机号查找或创建用户，并签发访问 token 与刷新 token。
- `users` 表目前没有账号密码字段。
- `/api/auth/me` 当前返回用户基础信息、头像、手机号、余额等，不返回任何密码相关信息。

### 组织成员管理

- 组织管理-成员管理查询的是 `enterprise_memberships`。
- 该列表只包含真实企业下的成员，不包含只使用默认空间的个人账号。
- 组织管理员现有权限适合管理组织成员角色、状态、配额等组织内属性，不适合管理全局账号密码。

### 默认空间

- 当前系统已经存在默认空间用户的超管管理能力，例如默认空间用户启用/禁用接口。
- 代码和测试中已有个人空间、默认空间、`scope=personal`、`enterpriseId=-1` 等语义。
- 因此不建议为了账号密码能力把默认空间整体改造成一个真实企业。

## 方案决策

### 采用独立平台超管账号管理页

推荐新增平台超管账号管理页，例如 `/admin/users`，用于管理全局用户账号。该页面负责展示用户账号信息、所属企业、默认空间状态，并提供超管级账号操作。

选择该方案的原因：

- 密码、登录状态、账号禁用是全局账号属性，不属于任何单个组织。
- 同一用户可能属于多个企业，组织管理员修改密码会产生权限边界不清的问题。
- 当前系统已经把默认空间作为个人/默认空间能力处理，继续单独管理风险更低。
- 新增超管账号页改造范围可控，不需要迁移大量个人空间、图谱、RagFlow、配额和工作区数据。

### 不采用默认空间企业化

不建议把默认空间改成 `enterpriseId = -1` 的真实企业并同步修改所有数据库数据和代码。

原因：

- 现有个人空间和企业空间在数据模型上已经分离。
- `enterpriseId=-1` 更像前端或业务层哨兵值，不适合作为真实企业主键长期落库。
- 企业化会影响个人知识库、知识图谱、RagFlow dataset、配额、工作区排序、访问控制等多条链路。
- 本次需求的核心是账号密码和账号管理，默认空间企业化属于更大的架构迁移，不应混入本次任务。

## 功能设计

### 1. 用户密码字段

在 `users` 表新增：

```prisma
passwordHash String? @db.VarChar(255)
```

规则：

- 可空，兼容历史短信登录用户。
- 只保存密码哈希，不保存明文密码。
- 数据库字段使用 `VARCHAR(255)` 存储密码哈希；明文密码长度规则不直接映射为数据库字段长度。
- 不通过任何用户查询接口返回 `passwordHash`。
- `/api/auth/me` 返回 `hasPassword: boolean`，用于前端判断展示“创建密码”还是“修改密码”。

明文密码规则：

- 长度为 8-18 位。
- 必须同时包含字母和数字。
- 只允许英文大小写字母、数字和常见半角符号。
- 不允许空格、中文、全角字符。

密码哈希建议：

- 使用 Node 内置 `crypto.scrypt`，避免引入额外依赖。
- 保存版本化格式，例如 `scrypt:v1:<saltHex>:<hashHex>`。
- 校验时使用恒定时间比较，避免时序侧信道。

### 2. 手机号密码登录

登录页改成两个 tab：

- 手机号验证
- 手机号密码

手机号密码登录流程：

1. 用户输入手机号和密码。
2. 后端按手机号查找 phone identity。
3. 用户不存在、已删除、已禁用、未设置密码、密码错误时返回统一登录失败提示。
4. 校验成功后复用现有 token/cookie 签发逻辑。

建议接口：

```http
POST /api/auth/password/login
```

请求：

```json
{
  "phone": "13800138000",
  "password": "password123"
}
```

响应与短信登录保持一致：

```json
{
  "user": {
    "id": "...",
    "role": "user",
    "status": "active",
    "phone": "138****8000",
    "hasPassword": true
  }
}
```

### 3. 创建密码与修改密码

左下角头像菜单在“更换头像”下方增加密码入口。

按钮文案：

- 当前用户无密码：创建密码
- 当前用户有密码：修改密码

创建密码：

- 不要求旧密码。
- 输入新密码和确认新密码。
- 两次新密码一致后保存。

修改密码：

- 必须输入当前密码。
- 输入新密码和确认新密码。
- 当前密码正确且两次新密码一致后保存。

建议接口：

```http
PATCH /api/auth/me/password
```

请求：

```json
{
  "currentPassword": "old-password",
  "newPassword": "new-password",
  "confirmPassword": "new-password"
}
```

说明：

- 无密码用户创建密码时，`currentPassword` 可省略。
- 有密码用户修改密码时，`currentPassword` 必填。
- 修改成功后撤销该用户已有 refresh token，并重新登录或重新签发当前会话 token。默认建议重新签发当前会话 token，减少用户打断。

### 4. 忘记密码

忘记密码通过手机号验证码完成，不通过组织管理员重置。

流程：

1. 用户点击“忘记密码”。
2. 输入手机号并发送验证码。
3. 后端只允许已存在手机号账号发送找回验证码。
4. 用户输入验证码、新密码、确认新密码。
5. 验证码正确后更新密码。
6. 重置成功后撤销该用户所有 refresh token。
7. 前端提示用户使用新密码重新登录。

建议接口：

```http
POST /api/auth/password/forgot/send-code
POST /api/auth/password/forgot/reset
```

发送验证码请求：

```json
{
  "phone": "13800138000"
}
```

重置密码请求：

```json
{
  "phone": "13800138000",
  "code": "123456",
  "newPassword": "new-password",
  "confirmPassword": "new-password"
}
```

约束：

- 不存在手机号账号时，不创建用户。
- 找回密码验证码可复用现有短信发送能力，但 Redis key 应与登录验证码区分，避免互相覆盖。
- 找回密码验证码应保留冷却、过期、错误次数限制。

### 5. 平台超管账号管理

新增平台超管账号管理页：

```text
/admin/users
```

页面能力：

- 按手机号、用户 ID、账号状态筛选用户。
- 查看用户基础信息。
- 查看用户是否已设置密码。
- 查看用户所属企业列表。
- 查看默认空间状态。
- 超管重置用户密码。
- 超管禁用或启用用户登录账号。

建议接口：

```http
GET /api/admin/users
GET /api/admin/users/:userId
PATCH /api/admin/users/:userId/password
PATCH /api/admin/users/:userId/status
```

用户列表筛选参数：

- `userId`：用户 ID。
- `phone`：手机号片段。
- `accountStatus`：全局账号状态，仅支持 `active`、`disabled`，对应数据库 `users.status`。

用户列表返回字段：

```json
{
  "items": [
    {
      "id": "...",
      "phone": "138****8000",
      "role": "user",
      "accountStatus": "active",
      "hasPassword": true,
      "createdAt": "...",
      "updatedAt": "...",
      "enterpriseCount": 2,
      "defaultSpaceStatus": "active"
    }
  ]
}
```

用户详情返回字段：

```json
{
  "user": {
    "id": "...",
    "phone": "138****8000",
    "role": "user",
    "accountStatus": "active",
    "hasPassword": true,
    "createdAt": "...",
    "updatedAt": "...",
    "defaultSpace": {
      "status": "active",
      "agentId": "...",
      "accessStatus": "approved"
    },
    "enterprises": [
      {
        "enterpriseId": "...",
        "enterpriseName": "...",
        "role": "member",
        "membershipStatus": "active",
        "department": "...",
        "joinedAt": "..."
      }
    ]
  }
}
```

重置密码请求：

```json
{
  "password": "new-password"
}
```

禁用或启用账号请求：

```json
{
  "accountStatus": "disabled"
}
```

账号禁用规则：

- 更新 `users.status = disabled`。
- 撤销该用户所有 refresh token。
- 后续短信登录、密码登录、refresh、受保护接口访问均应失败。
- 平台超管不能禁用自己的账号，避免误操作锁死。

状态字段语义边界：

- `accountStatus` 是 API 层对 `users.status` 的命名，只表示全局登录账号状态。
- `enterprise_memberships.status` 表示用户在某个企业内的成员关系状态，组织管理员禁用企业成员只修改该字段。
- `zclaw_agent_instances.status` 表示默认空间或企业空间 Agent 实例状态，本页面只读取展示，不替代现有默认空间启用/禁用接口。
- `zclaw_access_requests.status` 表示默认空间访问申请状态，本页面只展示最新申请状态。
- `enterprises.status` 表示企业自身状态，本页面只展示用户所属企业状态，不修改企业状态。

## 权限边界

### 普通用户

- 可以短信登录。
- 可以手机号密码登录。
- 可以创建自己的密码。
- 可以校验旧密码后修改自己的密码。
- 可以通过手机号验证码找回密码。

### 组织管理员

- 不能修改成员密码。
- 继续管理组织成员、角色、状态、部门、配额等组织内属性。

### 平台超管

- 可以查看全局用户账号列表。
- 可以查看用户所属企业和默认空间状态。
- 可以重置任意非受保护用户的密码。
- 可以禁用或启用用户登录账号。

## 前端交互要求

### 密码输入

所有密码输入框默认加密显示，即 `type="password"`。

每个密码输入框右侧提供眼睛按钮：

- Eye：点击后显示明文。
- EyeOff：点击后恢复掩码。

适用范围：

- 手机号密码登录。
- 创建密码。
- 修改密码。
- 忘记密码重置。
- 超管重置密码。

### 登录页

登录页保留现有视觉风格，登录表单改为两个 tab。

手机号验证 tab：

- 保留当前手机号验证码登录流程。

手机号密码 tab：

- 手机号输入。
- 密码输入。
- 登录按钮。
- 忘记密码入口。

### 左下角头像菜单

在“更换头像”下增加密码按钮。

文案由 `/api/auth/me` 的 `hasPassword` 决定：

- `hasPassword=false`：创建密码
- `hasPassword=true`：修改密码

### 超管账号管理页

建议布局：

- 顶部筛选区：手机号、用户 ID、状态。
- 用户表格：手机号、用户 ID、角色、账号状态、是否有密码、企业数量、默认空间状态、创建时间、操作。
- 操作：查看详情、重置密码、禁用/启用。
- 用户详情弹窗或详情页展示所属企业列表和默认空间状态。

## 后端安全要求

### 登录与 token

以下场景必须拒绝：

- 用户不存在。
- 用户已删除。
- 用户 `status != active`。
- 密码登录时用户未设置密码。
- 密码错误。

### JwtAuthGuard

为了确保禁用账号立即生效，`JwtAuthGuard` 不能只验证 JWT 签名，还需要查询用户状态：

- 用户存在。
- `isDeleted=false`。
- `status=active`。

否则旧 access token 在过期前仍可能访问受保护接口。

### Refresh token

以下操作后应撤销相关 refresh token：

- 用户修改密码。
- 用户忘记密码重置成功。
- 平台超管重置密码。
- 平台超管禁用账号。

## 测试与验收

### 后端测试

- 无密码用户不能用密码登录。
- 无密码用户可以创建密码。
- 有密码用户修改密码必须提供正确旧密码。
- 忘记密码必须通过手机号验证码。

- 超管不能禁用自己。
