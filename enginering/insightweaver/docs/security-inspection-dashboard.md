# 安全安检看板说明

## 1. 页面用途与访问权限

安全安检看板用于展示单个企业在 AI 对话、文件使用、登录认证和资源授权方面的安全运行情况。页面接口为：

```http
GET /api/dashboard/security-inspection?enterpriseId=<企业 ID>
```

接口要求登录态 JWT，并通过企业管理员或所有者权限校验。查询始终以请求中的 `enterpriseId` 为隔离边界，不能跨企业读取数据。

页面请求失败时保留前端最后一次成功数据并显示错误提示，不使用整页静态 Mock 回退。

## 2. 时间口径与更新方式

- “今日”、最近 7 日和前一周期统一按 `Asia/Shanghai` 划分自然日。
- KPI 数值为今日值，迷你图为截至今日的最近 7 个自然日。
- 安全评分使用最近 7 日，与其前一个 7 日周期比较。
- 接口每次请求实时读取数据库与审计日志；页面重新进入或主动刷新时更新。
- 登录失败和 AI 越权审计从本功能上线后开始积累，不补造历史记录。

## 3. 顶部 KPI 指标

| 页面指标 | 实际含义 | 数据来源 | 是否进入评分 |
| --- | --- | --- | --- |
| 今日安检任务 | 企业今日 `normal_conversation` 与 `skill_conversation` 事件总数 | `HumanEfficiencyEvent` | 否 |
| 风险拦截次数 | 企业安全审计拦截合计（短信/密码登录失败、AI 越权、分级策略拒绝），与合规趋势「拦截」同一口径，按今日计数 | `AuditLog` | 否（底层短信/密码/AI 越权已由其它 KPI 计入评分，本项不重复扣分） |
| 敏感数据检测 | 企业用户 AI 消息 `rawPayload.files` 中的文件条目数，包括本次上传和工作区引用 | `ZclawMessage` | 否 |
| 外部攻击拦截 | 企业当前有效成员的短信验证码错误次数与密码登录错误次数之和 | `AuditLog` | 是 |
| 高危调用发现 | AI 对话或知识检索中，实际访问无权限资源并被专用授权守卫拒绝的请求次数 | `AuditLog` | 是 |

所有 KPI 均返回 `key`、`value`、`unit`、最近 7 日 `series`、`source`、`isMock` 和相对昨日的 `trend`。前端根据语义化 `key` 映射中英文文案。

### 3.1 阿里云 WAF/SLS 状态

当前仓库未配置阿里云 WAF/SLS 客户端，也没有平台域名与企业 ID 的归属映射。因此「风险拦截次数」暂用企业安全审计合计（`source: "audit"`），与右侧合规趋势「拦截」及风险事件列表同源，不再使用模拟值。

评分中的 `realCloudInterceptions` 仍保留为 0，供后续接入真实云防护日志时使用；接入时应建立受保护域名到企业的映射，通过 WAF `DescribeSecurityEventLogs` 或 SLS 查询真实拦截日志，并仅把云防护真实事件写入该字段以免与现有审计扣分重复。

## 4. AI 越权的精确识别

后端普通 403 同时可能表示账号过期、配额不足、Agent 停用、企业上下文缺失、角色不足、分享密码错误和文件访问拒绝等情况，因此看板不按 HTTP 状态或异常文案统计。

只有专用 `AI_RESOURCE_ACCESS_DENIED` 拒绝类型且原因码在白名单内时，才记录 `security.ai.unauthorized_resource_access`。对外 HTTP 状态和原有业务行为不变；原本会降级继续对话的检索仍会降级，但会留下安全审计。

### 4.1 计入原因码

| 原因码 | 含义 | 粗粒度资源类型 |
| --- | --- | --- |
| `shared_path_not_visible` | 组织或部门可见范围不包含目标共享路径 | 共享工作区路径 |
| `shared_path_read_denied` | 用户没有目标共享路径的读取权限 | 共享工作区路径 |
| `ragflow_document_owner_mismatch` | 尝试读取其他用户的个人 RagFlow 文档 | RagFlow 文档 |
| `ragflow_document_enterprise_mismatch` | 文档所属企业与当前企业上下文不一致 | RagFlow 文档 |
| `enterprise_dataset_membership_denied` | 非目标企业有效成员请求企业知识库 | 企业数据集 |
| `graph_dataset_context_mismatch` | 图谱、数据集、企业或个人上下文不匹配 | 图谱数据集 |
| `graph_personal_dataset_owner_mismatch` | 尝试使用其他用户的个人知识图谱数据集 | 图谱数据集 |

### 4.2 明确排除

以下拒绝不计入“高危调用发现”：

- 账号过期、余额不足、会话配额不足、工作区容量超限。
- Agent 未开通、停用或企业实例不可用。
- 缺少企业上下文、普通企业角色不足、后台管理权限不足。
- 分享密码错误、分享过期、禁止下载或复制。
- 普通 API 或健康检查返回的 403。
- KM Agent 只返回通用 403、但没有结构化资源权限原因的情况。

### 4.3 去重规则

一次用户消息或一次直接知识检索请求最多写入一条越权审计。请求内部多个拒绝点、重试或多资源失败会合并为唯一原因码集合，避免重复计数。

## 5. 旁路审计、AI 增强与隐私

安全事件复用 `AuditLog`，不为审计另建事件表：

| action | 记录时机 |
| --- | --- |
| `security.auth.sms_verification_failed` | 已能解析到真实用户的短信验证码校验失败 |
| `security.auth.password_login_failed` | 已能解析到真实用户的密码登录失败 |
| `security.ai.unauthorized_resource_access` | AI 边界捕获到白名单内的结构化资源拒绝 |
| `security.asset.classification_policy_denied` | 管理员显式保存不合法的分级配置，或非管理员尝试执行分级 |

所有业务代码只调用 `SecurityAuditRecorder` 的语义化方法。Recorder 在原业务结果已经确定后异步记录，内部统一捕获错误；审计数据库或 AI 服务失败均不会改变 HTTP 状态、回滚业务事务或阻塞用户操作。同一请求 ID 内的同类事件会去重。

审计只保存用户 ID、企业 ID、原因码集合、粗粒度资源类型、请求入口、结果和时间。禁止保存手机号、验证码、密码、Prompt、文件内容或完整路径。

AI 仅在事件落库后作为后台增强，输入不包含原文敏感数据，输出双语摘要、解释和处置建议到 `AuditLog.meta.aiAnalysis`。AI 不创建正式事件、不改风险级别、不改拦截结果和评分；服务不可用时保留真实事件，页面显示固定说明。

登录请求发生时通常没有企业上下文，因此未知手机号不记录。已识别用户的登录失败会被记录；企业看板查询时仅统计该企业当前有效成员的事件。一个用户属于多个企业时，其认证失败可能出现在这些企业各自的看板中，这是当前归属模型的限制。

## 6. 下半区定义

### 6.1 实际检测链路

流程图按真实处理顺序展示：

`请求进入 → 身份认证 → 企业上下文 → 文件校验 → 权限校验 → AI 处理 → 审计记录`

### 6.2 风险事件列表

展示最近 20 条真实事件：短信验证失败、密码登录失败、AI 越权和分级策略拒绝。每条包含事件事实字段；点击事件可展开 AI 摘要与建议。

### 6.3 安全分级资产

统计真实共享工作区文件，不统计目录，路径去重并支持文件夹最长前缀继承：

- `core_secret`：核心机密，禁止直接附入 AI 对话（显式声明计入看板；不再强制仅 owner/admin 可读）。
- `important`：重要数据（显式分级标签；可见范围由组织/成员分享独立配置）。
- `general`：一般数据（显式分级标签；可见范围由组织/成员分享独立配置）。
- `public`：公开数据，由真实有效的外部分享状态派生。

新表 `SharedWorkspaceAssetClassification` 只在有权限的成员主动保存时写入。分级与「设置可见范围」解耦：保存分级**不再**写入非管理角色读拒绝 ACL，也不再自动改写组织可见范围。看板统计优先级：**管理员/路径所有者显式保存的分级（最长路径前缀继承）> 有效外部分享推导的公开数据 > ACL / 组织可见范围推导**。因此即便路径仍存在外部分享，显式「核心机密」也会计入核心机密而非公开数据。未显式声明的路径仍按既有 ACL、组织可见范围和外部分享只读推导，不回写数据库。文件移动/删除成功后旁路同步分级路径，同步失败不回滚文件操作，并由进程内补偿队列有限重试。

### 6.4 审计与合规趋势

展示最近 3 个上海时区自然月（当月截至查询时间）：

- 正常处理：企业普通/Skill 对话数 + 对话中真实文件条目数。
- 风险事件：短信失败、密码失败、AI 越权和分级策略拒绝（与顶部「风险拦截次数」同源）；未来可另纳入真实 WAF/SLS 事件。

### 6.5 安全评分

最近 7 日扣分规则：

- AI 越权：每次扣 8 分，最多扣 40 分。
- 密码登录失败：每次扣 1 分，最多扣 15 分。
- 短信验证码失败：每次扣 0.5 分，最多扣 10 分。
- 真实 WAF 拦截：每次扣 0.1 分，最多扣 10 分。

```text
score = max(0, round(100 - 总扣分))
```

评分等级：`90–100` 为良好，`75–89` 为需关注，`0–74` 为风险。页面同时显示相对前一个 7 日周期的分数变化。顶部「风险拦截次数」本身不重复计入评分；云防护 `realCloudInterceptions` 在未接入前保持为 0。

## 7. 接口排障

1. **接口返回 400**：确认查询参数包含非空 `enterpriseId`。
2. **接口返回 401**：确认 JWT 有效且请求携带登录凭据。
3. **接口返回 403**：确认当前用户是目标企业管理员或所有者；该 403 本身不会被计入 AI 越权。
4. **登录失败始终为 0**：确认失败账号可解析为真实用户、用户是该企业当前有效成员，并且事件发生在功能上线后。
5. **高危调用始终为 0**：确认拒绝发生在 AI 对话、附件/知识库检索或图谱对话边界，且原因属于白名单；通用 403 会被有意排除。
6. **风险拦截为 0 但预期有值**：确认对应 `AuditLog` 动作已写入，且登录失败主体为企业当前有效成员、AI 越权/分级拒绝的 `resourceType/resourceId` 指向该企业；该 KPI 现为 `source: "audit"`，与合规趋势「拦截」同源。
7. **页面显示加载错误但仍有旧数据**：前端保留了最后一次成功结果；检查 API 日志与网络响应后再刷新。

## 8. 验收示例

- 企业成员当天完成 3 次普通对话和 2 次 Skill 对话，“今日安检任务”为 5。
- 一条用户消息携带 2 个 `rawPayload.files` 条目，“敏感数据检测”增加 2。
- 已知企业成员输错一次短信验证码和两次密码，“外部攻击拦截”增加 3，风险构成分别增加 1 和 2；同日「风险拦截次数」至少增加 3。
- 一次 AI 请求同时触发两个白名单越权原因，仅新增一条风险事件，“高危调用发现”增加 1，事件中包含两个去重后的原因码；同日「风险拦截次数」同步 +1。
- 账号配额不足或普通后台权限不足返回 403 时，“高危调用发现”不增加。
- 无匹配安全审计时「风险拦截次数」为 0，且与当月合规趋势「拦截」及风险事件列表一致为空。
