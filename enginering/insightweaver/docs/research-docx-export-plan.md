## 研究论文 DOCX 导出方案

### 目标
- 在论文详情页提供“导出 DOCX”入口。
- 导出内容为数据库中“最新版本的正文”，覆盖正文的所有部分。

### 入口位置
- Web：论文详情页（历史会话详情面板）。
- 交互：页面按钮/菜单触发导出。

### 数据来源
- 后端接口返回：论文正文最新版本（从数据库读取）。
- 最新版本判定规则：按 `version` 倒序取最新。

### 已落地实现
- 后端新增导出接口：`GET /research/sessions/:sessionId/export/docx`。
- 服务端读取最新正文 `research_contents.contentMd`，生成 docx 后返回下载流。
- 前端在论文详情页新增“导出 DOCX”按钮，直接触发下载。

### 实现路径（建议）
#### 后端生成 + 直接下载
- API 新增导出端点：`GET /research/:id/export/docx` 或 `POST /research/:id/export/docx`。
- 服务端读取最新版本正文 → 转换为 docx → 返回文件流。
- 优点：数据一致性好、易控模板、避免前端渲染差异。

#### 前端生成 + 本地下载（备选）
- 前端调用接口获取最新正文 → 使用 docx 生成库构建文档 → 触发下载。
- 优点：部署简单；缺点：样式一致性难控、体积偏大。

### DOCX 生成方案
- 推荐库：`docx`（Node/Browser 都可用）。
- 基本结构：标题 → 正文段落（按章节拆分）。
- 若正文是 Markdown：先解析为结构化段落再生成 docx。
- 若正文是富文本/HTML：需做 HTML → docx 的映射策略。

### 当前实现备注
- Markdown 解析：支持标题、段落、无序列表、代码块。
- 文件名：`{标题或主题}-v{version}.docx`，带 UTF-8 文件名头兼容浏览器。

### 安全与权限
- 导出接口需要鉴权（仅论文所有者/有权限角色可下载）。
- 记录导出行为（审计或统计可选）。

### 需要确认的问题
- 论文详情页的具体路由与页面组件位置。
- 正文在数据库中的字段与格式（纯文本/Markdown/HTML/结构化 JSON）。
- “最新版本”判定规则。
- 是否需要固定模板（封面、页眉页脚、字体字号、页码等）。
