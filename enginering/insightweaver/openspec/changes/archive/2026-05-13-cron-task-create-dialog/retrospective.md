# 定时任务创建功能 — 失败经验总结与改进建议

> **变更：** cron-task-create-dialog
> **日期：** 2026-05-13

---

## 失败事件 1：遗漏创建按钮的触发入口

### 问题描述

实现 `CreateCronTaskDialog` 组件后，完成了表单 UI、辅助函数、指令生成等全部逻辑，但**遗漏了将创建按钮连接到对话框的触发入口**。用户发现后反馈："你是不是遗漏创建定时任务dialog的触发入口？"

### 根因分析

1. **实现计划不完整**：Task 5（重写 CreateCronTaskDialog UI）只关注了 Dialog 内部 UI，没有包含"触发入口"这一步骤。计划假设触发入口是已有功能，但实际旧版 Dialog 并没有独立触发按钮。
2. **缺少端到端验证步骤**：计划中每个 Task 只做了 typecheck 验证，没有"打开页面手动验证完整交互流程"的步骤。
3. **代码审查未覆盖用户路径**：code review 侧重于代码质量和边界逻辑，没有从用户视角走一遍"入口 → 填表 → 提交"的完整路径。

### 改进建议

| 编号 | 改进措施 | 适用阶段 |
|------|----------|----------|
| R-1 | **实现计划必须包含用户路径**：每个涉及 UI 的 feature，计划中必须列出"用户从哪个入口进入 → 操作流程 → 结果反馈"的端到端步骤 | 写计划时 |
| R-2 | **增加交互链路自查清单**：实现完成后，检查：① 有入口 ② 入口可点击 ③ 点击后触发正确组件 ④ 组件关闭后状态正确 | 实现完成时 |
| R-3 | **验收测试必须包含入口测试**：人工验收的第一条用例必须是"用户能否找到并进入该功能" | 验收时 |

## 失败事件 2：创建按钮位置设计不当

### 问题描述

第一次添加的"创建"按钮放在了定时任务列表的工具栏区域（与"运行结果"、"刷新"按钮并排），用户看后指出"是不是在红色框框位置加创建定时，按钮比较好"，希望放在标题栏右侧，与"创建智能体"按钮风格一致。

### 根因分析

1. **未参考同页面已有模式**：页面中"已安装智能体"模块已有成熟的"创建智能体"按钮放在标题栏，但实现时没有参考这个已有模式。
2. **设计文档缺少 UI 位置说明**：设计文档描述了 Dialog 内部表单字段，但没有明确"创建按钮放在哪里"。
3. **按钮样式不一致**：第一次实现的按钮用了边框样式（与"运行结果"按钮相同），而"创建智能体"按钮是实心填充的主色按钮。

### 改进建议

| 编号 | 改进措施 | 适用阶段 |
|------|----------|----------|
| R-4 | **新 UI 元素必须先找同页面参照**：添加任何 UI 元素前，先搜索同页面/同模块是否有类似功能的已有实现，保持一致 | 设计+实现时 |
| R-5 | **设计文档必须包含入口位置**：如果 feature 需要新的触发入口，设计文档中必须用文字或截图明确标注入口位置 | 写设计时 |
| R-6 | **UI 一致性检查**：实现完成后，对比同页面相似模块的样式，确保一致 | 实现完成时 |

## 失败事件 3：后端约束发现不及时

### 问题描述

设计初期假设后端支持 `endAt`/`maxRuns` 等结束条件字段，后来才发现后端不支持。同时最初以为后端只支持 `once`/`daily`/`interval`，后来才发现还支持 `cron` 类型。这导致设计经历了多轮修改。

### 根因分析

1. **需求分析阶段未先检查 API 类型定义**：`ZclawCronSchedule` 类型在代码中已明确定义，但设计初期没有先去查看。
2. **假设驱动而非验证驱动**：基于"猜测"设计，而非"先读代码确认"再设计。

### 改进建议

| 编号 | 改进措施 | 适用阶段 |
|------|----------|----------|
| R-7 | **先读后端类型/API 再设计前端**：任何涉及 API 交互的 feature，第一步必须是检查后端类型定义和 API 接口，记录约束 | 设计前 |
| R-8 | **后端约束文档化**：在设计文档中设立"后端约束"章节，明确列出支持/不支持的字段 | 写设计时 |

## 综合改进清单

以下改进建议应沉淀到项目的 openspec specs 中，作为后续所有 feature 的参考：

### 实现计划模板补充

```markdown
## 端到端用户路径
- 入口：用户从哪里进入该功能？（具体到页面 + 位置）
- 操作：用户进行什么操作？
- 结果：操作后的反馈是什么？

## 同页面参照
- 是否有类似功能的已有实现？（列出具体组件和文件位置）
- 新 UI 元素是否与参照保持一致？

## 后端约束
- 涉及哪些 API？类型定义在哪里？
- 支持哪些字段？不支持哪些字段？
```

### 验收测试补充

```markdown
## 第一条：入口可达性
- 用户能否找到并点击进入该功能的入口？
- 入口位置是否与设计一致？
- 入口样式是否与同页面类似功能一致？
```
