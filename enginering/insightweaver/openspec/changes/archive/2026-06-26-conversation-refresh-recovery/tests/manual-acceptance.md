# 对话消息刷新恢复 — 人工验收

> 验收第一条：用户刷新对话页后，消息是否正确恢复？

---

## 前置条件

- 本地或测试环境 Super Lobster 可访问
- 有可用的 Zclaw 会话与 API 连接
- 浏览器 DevTools Network 面板可用

---

## 场景 1：刷新生成中会话

**步骤：**
1. 打开 Super Lobster，发起一个会触发较长回复的对话（如「生成一篇论文附录」）
2. 等待 assistant 开始流式输出（出现 loading / 部分内容）
3. 在生成过程中按 F5 刷新页面

**预期：**
- [ ] 页面加载后显示之前的 user 消息
- [ ] in-flight assistant 内容恢复（可能不完整，但不应空白）
- [ ] 无重复 user 气泡
- [ ] 消息顺序正确（user 在上，assistant 在下）
- [ ] 输入框保持禁用直至生成完成
- [ ] 生成完成后输入框恢复可用
- [ ] draft 被清除（sessionStorage 中无该 session 的 draft）

---

## 场景 2：刷新已完成会话

**步骤：**
1. 打开一个已完成的对话会话
2. 按 F5 刷新

**预期：**
- [ ] 完整历史消息正确显示
- [ ] 无重复 user / assistant 气泡
- [ ] 无 raw JSON 内容作为 assistant 气泡（如 `{"query":...}`）
- [ ] 无 `(no output)` 或 `NO_REPLY` 占位气泡
- [ ] tool 消息以工具卡片形式展示，非 JSON 文本
- [ ] 输入框可用

---

## 场景 3：URL 直达会话

**步骤：**
1. 复制一个会话 URL（含 `sessionId` 参数）
2. 在新标签页打开

**预期：**
- [ ] 正确加载该会话消息
- [ ] 侧边栏高亮对应会话
- [ ] 消息顺序与刷新前一致

---

## 场景 4：生成中轮询正常结束

**步骤：**
1. 发起对话，刷新页面触发生成中恢复
2. 打开 Network 面板，观察 `/sessions/{id}/messages` 请求
3. 等待生成完成

**预期：**
- [ ] 生成过程中有周期性 poll 请求（约 500ms 间隔）
- [ ] 生成完成后 poll 停止（无_burst 请求）
- [ ] 最终 assistant 消息 status 为 sent
- [ ] 侧边栏该会话从「生成中」列表移除

---

## 场景 5：无死循环请求

**步骤：**
1. 刷新一个生成中会话
2. 观察 Network 面板 30 秒

**预期：**
- [ ] 仅 1 次 hydrate 相关请求（detail + messages）
- [ ] 之后为周期性 poll，无连续_burst 请求
- [ ] 无重复的 `/sessions/{id}` detail 请求

---

## 场景 6：加载更早消息

**步骤：**
1. 打开一个超过 50 条消息的长会话
2. 滚动到消息列表顶部
3. 点击「加载更早消息」

**预期：**
- [ ] 更早消息 prepend 到列表顶部
- [ ] 消息顺序正确（时间递增向下）
- [ ] 无重复消息（相同 ID 不出现两次）
- [ ] 滚动位置保持在用户阅读位置附近

---

## 场景 7：SSE 断线恢复

**步骤：**
1. 发起对话，等待流式输出
2. 在 DevTools Network 中模拟 Offline 2–3 秒，再恢复 Online

**预期：**
- [ ] SSE 自动重试（最多 3 次，指数退避）
- [ ] 恢复后继续接收流式内容
- [ ] 消息不丢、不重复
- [ ] 不会过早结束生成状态

---

## 场景 8：Tool 消息正确渲染

**步骤：**
1. 发起会触发 web_search 等 tool 调用的对话
2. 等待 tool 执行完成
3. 刷新页面

**预期：**
- [ ] tool 消息以工具卡片展示
- [ ] 不出现 raw `toolCall`/`toolResult` JSON 作为 assistant 气泡
- [ ] tool 消息在 user 和 assistant 之间（轮次顺序正确）

---

## 场景 9：多会话切换

**步骤：**
1. 在会话 A 生成中刷新
2. 切换到会话 B
3. 再切回会话 A

**预期：**
- [ ] 会话 A 消息正确恢复
- [ ] 切换过程中无消息串台
- [ ] 会话 B 不受会话 A 轮询影响
