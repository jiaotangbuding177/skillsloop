# Feature Implementation Checklist

> 从 cron-task-create-dialog 变更中沉淀的规范。后续所有 UI feature 实现必须遵循此清单。

## 一、设计阶段

### 1. 后端约束优先

- [ ] 已检查 API 类型定义，确认支持/不支持的字段
- [ ] 在设计文档中设立"后端约束"章节，列出限制
- [ ] 不假设后端支持任何未在类型定义中声明的字段

### 2. 用户路径完整

- [ ] 设计文档包含"端到端用户路径"：入口 → 操作 → 结果
- [ ] 明确标注触发入口的位置（具体到页面模块 + 区域）
- [ ] 入口位置有截图或文字描述参照

### 3. UI 一致性

- [ ] 已搜索同页面/同模块是否有类似功能的已有实现
- [ ] 新 UI 元素的样式、位置与参照保持一致
- [ ] 如无参照，设计文档中说明理由

## 二、实现阶段

### 4. 交互链路自查

- [ ] 功能入口存在且可点击
- [ ] 入口点击后触发正确的组件/页面
- [ ] 组件/页面关闭后状态正确（重置/刷新）
- [ ] 操作结果有反馈（toast/跳转/列表更新）

### 5. 代码组织

- [ ] 纯逻辑辅助函数提取到独立文件，便于单元测试
- [ ] 组件只负责 UI 渲染和事件处理
- [ ] 类型定义与实现分离（类型文件 vs 组件文件）

## 三、验证阶段

### 6. 自动化测试

- [ ] 所有辅助函数有单元测试覆盖
- [ ] 边界条件已测试（空值、零值、极端值）
- [ ] `pnpm test` 通过

### 7. 人工验收

- [ ] 验收第一条：用户能否找到并进入该功能？
- [ ] 入口位置与设计一致
- [ ] 入口样式与同页面类似功能一致
- [ ] 完整操作流程可走通
- [ ] 人工验收文档已签署

## 四、提交阶段

- [ ] `pnpm lint` 通过
- [ ] `pnpm build` 通过
- [ ] 人工验收全部 ✅
- [ ] 代码已推送到 feature 分支
- [ ] PR 已创建
