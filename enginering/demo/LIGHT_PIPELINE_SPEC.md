# 轻量轨迹到技能库管道

本轮用户授权：独立读取 `X=(E,C,V)`，输出技能库；不再把多用户、个人采纳、组织审核或数据库作为运行前提。原十二阶段Demo保留，本入口只承担恢复和生成侧。

## 固定接口与流程

- `E`：按导出位置排列的原始事件，包含user/assistant/tool正文、双方可见工具调用与回执。可含多个原会话；稳定消息ID、会话ID与位置可显式提供，缺失时只生成导入编号，不伪造时间或任务归属。
- `C`：公开政策、工具说明与背景来源数组；可为空。
- `V`：带来源、对象、标准及范围的可见评价数组；可为空。不读取完整reward_info、隐藏答案或金标动作。
- 兼容现有 `events/context/evaluations` 对象。调用者无需提供成员或组织身份。

来源索引 → 一次模型语义提议＋程序轨迹恢复 → 成功／失败／未知经验分析 → 流程兼容聚类与归纳 → 程序封装与官方工具校验 → `skills/`、技能索引和完整中间记录。

复用现有纯算法模块，不创建Loop、Store、账号、Web服务或治理审批。内部统一工作空间标识仅用于兼容纯函数，不代表多用户权限或真实技能使用事实。新库发现使用独立路线，不伪造KNOWN_NONE来决定NEW/UPDATE。

## 成功与失败处理

参考Trace2Skill成功側提取有依据的有效路径、去掉已纠正错误；失败側提取有范围的教训、已有验证修订。当前无通用环境重跑器，不声称实现其主动根因修复／金标对比验证。

方法和最终条款区分推荐流程、失败警示、待验证假设；证据强弱另记。已知失败动作不能因为有来源或非空条件就进入推荐步骤。整任务失败不自动判每一步错；明确政策／要求违反即使无局部评分也可以产生警示。未知但真实执行的方法继续处理为候选。原因未知不能反推确定根因或成功替代方案。

双方工具动作保留行动方与原位置。空正文有实际动作的记录不伪造用户需求；语义归属须有明确绑定，原消息位置与模型绑定分别保存。

## 资源与可复查性

恢复和工作流分析直接使用现有结构化模型接口；封装由程序执行，不额外启动creator模型或工具代理。恢复1次，每批最多8任务，提取1次＋有方法才归纳1次；正常小输入3请求，多批上界1＋2×批数。批内相容聚类，跨批不凭空推断关系；完全相同编译技能合并条目并保留多份来源。超预算明确停止／延期，不截断原文，不自动补发失败请求。

请求按输入、提示、模型配置和相关源码指纹保存；成功输出再次校验才复用。保存原始输入、标准事件、问答视图、恢复轨迹、方法／聚类／处置、工作流、技能与调用账本。文件存在／官方打包通过不等于专业质量或新任务收益已证。

## 本轮验收

免费回归涵盖双方动作、空正文动作、任务交错、失败警示不进入推荐步骤、同一失败经历仍有可学正确方法、无方法正常结束、批次／预算／缓存、技能封装。一次小规模真实模型验收在免费检查后固定版本执行，有限请求与失败记录保留，不开展正式benchmark或训练。
