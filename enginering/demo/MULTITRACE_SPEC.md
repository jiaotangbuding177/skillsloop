# 多轨迹归纳契约

本项授权为独立demo升级与论文文档替换，不接入企业生产。沿用原三张SQLite表和技能发布流程。当前目录不是Git仓库，不创建开发分支或自动提交；变更由本地文件、测试与研究记忆记录。

## Plan / Spec

1. 任务关联之后，按owner、NEW/UPDATE、实际skill版本隔离材料。NEW以规范化目标的词/中文二元组余弦相似度进行complete-link聚类，阈值0.72；UPDATE按相同实际skill及hash聚池。每池最多8个独立任务；同任务修订不是新增独立样本。规则聚类不调用模型，词法不同但语义相同可能漏合并。
2. 默认服务等待120秒吸收后续同类轨迹，单例到期仍处理；可用--pool-wait-seconds设置。候选开始派发后冻结，不能继续加材料。
3. evidence携带消息、可见工具结果、产物hash和版本；技术成功与业务成功分离。用户明确验收或导入评估可产生SUCCESS，错误评估/用户纠正进入FAILURE，其余UNKNOWN。导入评估标注IMPORTED_EVALUATION，不声称由宿主独立验证。
4. 一次OpenClaw学习派发内，按success/failure/unknown职责逐轨迹提出patch，再给出合并组；共享同一冻结基准。该预算适配不等于论文的独立并行子agent及多层merge复现。
5. 每个方法有适用范围与原文引用；失败观察缺少cause/通过的check引用只能延期，用户纠正规则可作为USER_RULE。宿主验证引用有效性，不自动证明语义因果正确性。
6. 所有提议必须被合并或明确延期，禁止静默遗漏。宿主实际执行add/append/唯一片段replace；校验beforeHash、路径、冲突，禁止UPDATE整文件覆盖及删除。最终包来自宿主应用结果，仍用官方creator验证封装。
7. 所有来源在生成与采纳前复核；任一来源修订导致整个候选过期，同时释放未修改来源重新聚池。条目级已发布技能自动撤销尚未实现。
8. 缓存使用冻结候选和运行幂等键，相同派发不自动重试。所有分析和合并都在purpose=learn下计入现有额度；该额度是Agent派发限制，不是内部tokens硬上限。
