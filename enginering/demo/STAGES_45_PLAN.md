## 2. 调用布局

1. 从已有效的trace中构造有界学习批次；过滤holdout、不同owner、不同使用基准等硬边界。
2. 请求A：每来源workflow轮廓、方法提议、成功/失败/UNKNOWN局部分析及流程兼容关系。保持来源可区分，不预先混合全文摘要。
3. 程序按workflow兼容关系分组，保存未比较/证据不足关系。方法之间的互补关系不能被相似性聚类切断。
4. 请求B：在同次输入/输出预算内批量归纳各簇；主要读取冻结frames/proposals、必要引文与证据类型，避免再次传全部历史正文。输出workflow、分支和完整方法台账。
5. 如果总输出过大，则明确分批、记录额外调用或延期；不能仍宣传整个批次固定两次调用。语义归纳无法成立可拆簇或延期，不能强行一簇一包。
6. 对每个合格NEW workflow运行一个独立creator会话；一个会话可能多次模型请求，完整计量。

提取缓存以trace hash＋分析配置版本为键；关系缓存以frame内容hash＋兼容判断版本为键；生成缓存以workflow hash＋生成配置为键。新增证据不无条件重算所有旧来源。可选失败诊断默认关闭。

## 3. 免费控制验收清单

以下为未来软件验收规格，全部尚未在本轮执行。

| ID | 输入/反例 | 必须看到的输出 |
| --- | --- | --- |
| C01 | 一个业务UNKNOWN、有明确操作过程的trace | 可输出有限方法；不要求成功或第二条trace |
| C02 | 新增事实/改变交付要求 | 要求版本或条件变化；不自动标旧方法失败 |
| C03 | 一个局部失败，其他步骤正常 | 只影响相关方法，不污染整任务 |
| C04 | 失败A后无关检查B通过 | 不声称A已修正验证 |
| C05 | 明确无技能与缺receipt两种输入 | 前者允许NEW，后者不能伪造NEW或版本 |
| C06 | 同skill不同实际版本、可分段与不可分段两种输入 | 分版本归因；不能分清的相关方法延期 |
| C07 | 相同流程不同措辞、同主题不同流程 | 前者可有依据聚合；后者不强并 |

| C09 | 相反角色/条件冲突 | 有具体条件则分支；目标根本不同则分开 |
| C10 | A-B、B-C兼容而A-C不明；组级条件矛盾 | 不传递强并；不将未知等同已证伪 |
| C11 | holdout与不同owner混入 | 在模型视图构造前排除，不参与摘要和命名 |
| C12 | 每个方法纳入/重复/排除/延期 | 台账全覆盖，不按多数票丢有效少数方法 |
| C13 | 执行过程中来源或基准更新 | 结果STALE，不可覆盖当前候选；保留消耗 |
| C14 | 只复制creator或只声称读过 | creatorRead不通过；需要真实成功工具回执 |
| C15 | 缺资源、私有sidecar、被排除结论被写入包 | 不进入READY；失败位置可定位 |
| C16 | 静态校验通过但官方打包失败 | 不宣称D1完成；不自动采纳 |
| C17 | 文本流程可用、文件工具缺失 | 文本分支保留；文件能力限制显式呈现 |

## 4. 038真实案例的最小试运行

### 准备

- 使用047已经形成的A/B task-trace-v2及受控源引用，不读取旧人工轨迹当模型输入，不再次运行前三阶段。
- C完全不进入阶段4/5材料、摘要和命名；不把其已参与前三阶段开发的事实隐藏成最终未接触测试集。
- 新受控data root、autoLearn关闭、仅为此次调用预留额度；记录程序/prompt/schema/模型/creator版本。
- 输出目录区分公开候选、私有证据和无正文验收摘要。明确历史附件/业务验证缺失。

### 阶段4验收

先A单例验证UNKNOWN仍能提炼有来源方法；A/B小池验证流程聚类与角色/交付条件。优先复用A提取缓存，不能为重复展示再次全量调用。

逐项审阅：提取出哪些具体方法，是否有原文依据，哪些是设计策略而非历史事实；A追问是否被误判失败，选项实现未核验是否保留；B新事实是否误作原错误；共同流程是否足够具体；没有合并时是否有理由。候选数量不设必须为1；方法覆盖和范围正确优先。

若模型只输出空泛“按要求处理”，或靠固定法律结论组成技能，则本阶段不通过。保留错误样例，先定位提取、归因还是聚合问题，不直接进入生成消耗。

### 阶段5验收

选择阶段4真实输出的一个合格NEW workflow，冻结公开生成视图，在一次独立OpenClaw会话中实际读取官方skill-creator并生成草稿。不得手工写workflow替代算法输出后称端到端通过。

宿主检查来源当前性、方法/条件落点、资源引用、内容边界及依赖；官方打包后读取解包内容核对hash，登记授权下载。READY仅代表可供采纳；个人和组织库数量不能因本次生成自动增加。

应交付：LearningDecisionSet、WorkflowCandidate、生成视图hash、真实SKILL.md及必要文件、.skill包、creator读取/打包记录、分层验证及资源账目。没有实际消费时D2/D3为NOT_RUN，不能写全闭环效果通过。

### 停止与定位

来源失效、权限/留出越界、输出不完整、错误专业结论、workflow语义缺失、creator未读、打包失败、预算耗尽均停止自动重试。保留失败和已消耗usage；合法文本分支仍可保留，通过阶段4新revision收窄范围后再考虑一次受控修复。不能无界反复调prompt直到案例看起来成功。
