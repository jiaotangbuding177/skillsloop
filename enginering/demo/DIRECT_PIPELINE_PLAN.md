# 直接实验管道实施计划

2026-10-05。依据用户本轮明确授权，以及已确认的轨迹恢复、工作流聚合两份研究设计。范围只有 `X=(E,C,V) → 恢复 → 聚合 → skills目录`。

## 交付与契约

- 复用既有有界关系搜索，补充局部动作、对象、条件与逐项检查的来源核对。
- 模型批量提出语义关系和局部方法；程序保留真实历史，计算步骤映射、条件分支、反例约束和正压缩收益合并。封装不再调用模型。
- 无用户、数据库、网页、组织审核或自进化前置条件。原十二阶段入口和历史实验保留。
- 默认输出标准 `SKILL.md` 目录、官方格式包、可核对来源与文件SHA清单；消费者只挂载生成的 `skills` 目录。
- 未知继续作为候选；整体得分不广播到局部；只声称完成但没有实际动作的内容不成为已执行流程。模型语义映射不冒充独立认证。
- τ²适配默认只取显式选择的学习会话正文及双方工具事件；不导入隐藏任务对象或完整评分对象。

## 执行顺序

1. 保存已有测试基线；各模块先写关键边界测试。
2. 并行完成局部证据编译、纯程序工作流归纳、实验输入适配。
3. 接通独立运行、按完整会话分批、跨批方法聚合、冻结清单、缓存和预算。
4. 验证多实例真实合并、局部失败与未知不扩散、来源不悬空、用户侧动作不丢失。
5. 完成小规模模型接通与离线复入、独立审查、使用说明和研究记忆。

状态：准备 → 运行恢复 → 局部核对 → 程序归纳 → 封装与冻结 → 完成。任一阶段失败保留原材料及请求记录；不自动重试，不发布半完成的冻结清单。相同输出目录以独占锁保护。

## 验收矩阵

| 检查 | 预期 |
|---|---|
| 两个同方法、不同实例 | 实际产生合并，并保留各自见证 |
| 相同话题、不同对象或效果 | 不因词面相似合并 |
| 编号通过但格式没有评价 | 只编号获得相应支持 |
| 工具明确失败后助手说成功 | 失败保留，自述不成为成功执行 |
| 整体失败但局部查询完成 | 保留查询事实，不全盘作废 |
| 超时、缺少回执、只有计划 | 结果未知，不编造执行或根因 |
| 相同条件下成功与失败 | 保留冲突，不以多数票抹反例 |
| 用户工具调用 | 原调用方、调用ID和返回全部保留 |
| 同目录并发／不同输入复入 | 拒绝覆盖 |
| 相同冻结库再次接入 | 校验SHA且零模型请求 |
| 输入超预算或不合法 | 明确失败，不截断尾部 |
| 真实模型验收 | 与人工回答夹具分开记录，不作效果证明 |

本轮使用开发路由的实施、测试和独立审查纪律；用户已明确批准执行既定方案，不重复索取阶段确认。项目没有根级Trellis，本轮不安装额外工作流框架、不伪造确认记录、不提交或推送已有大量未提交成果。科研记忆规则继续有效。
